# Android 실기기 자동 플레이 검사

같은 Wi-Fi에 연결한 Android 실기기 1~4대를 명시적으로 선택해 APK 설치·실제 터치·자동 전투·결과·재대전을 검사한다. 에뮬레이터 검사나 Mac의 화면 없는 검사는 물리 기기 통과로 기록하지 않는다.

## 연결과 실행

먼저 [Android 무선 연결](android-wireless-debugging.md)의 최초 페어링과 디버깅 허용을 기기에서 완료한다. 실행 도구는 페어링하지 않는다. 페어링 코드·Android 디버그 키·인증 토큰·재접속 토큰은 작업 기록에 넣지 않는다.

```sh
./scripts/android-wireless-debug.sh devices
./scripts/export-debug-android.sh
./scripts/verify-android-fleet.sh \
  --apk build/android/ForestArena-debug.apk \
  --serial '<첫 번째 기기의 serial>' \
  --serial '<두 번째 기기의 serial>' \
  --suite smoke
```

`--serial`을 1~4번 지정한다. 대상 중복·4대 초과·에뮬레이터·오프라인 또는 허가되지 않은 연결은 시작 전에 오류로 처리한다. 대상은 자동 선택하지 않는다. APK 패키지·해시, 기기 Android 버전·화면 크기·모델을 확인한 뒤 선택한 기기만 설치·조작한다. Android 10 이상 가로 화면이 게임 기준이며 Android 자체 무선 디버깅은 Android 11 이상에서 제공한다.

| 실행 종류 | 기능 검사 뒤 반복 대전 | 사용 목적 |
| --- | --- | --- |
| `smoke` | 없음 | 연결·화면·기능의 빠른 확인 |
| `soak` | 기기별 600초 | 기본 10분 반복 확인 |
| `extended` | 기기별 1800초 | 30분 반복과 28개 조합 확인 |

`--duration <초>`로 반복 대전 시간만 변경한다. 기능 검사 시간은 별도다. `--output <폴더>`로 결과 위치를 정한다. 기본 위치는 `artifacts/android-fleet/<run_id>/`다. 같은 폴더의 이전 실행을 덮어쓰지 않고 실행 ID로 분리한다.

오프라인 검사는 기기별로 병렬 실행한다. LAN은 serial 지정 순서대로 두 대를 한 쌍으로 묶는다. 4대면 별도 포트의 Mac 경기 서버 두 개로 두 경기를 실행한다. 홀수 번째 마지막 기기는 오프라인만 실행하고 LAN을 `미실행`으로 남긴다. Mac과 기기 간 통신이 막힌 Wi-Fi에서는 LAN을 통과로 기록할 수 없다. 자동 주소 확인이 맞지 않으면 `--lan-bind <Mac 사설 IPv4>`와 `--lan-cidr <허용 기기 주소 범위>`을 지정한다.

## 검사 방식과 저장

`export-debug-android.sh`가 Godot Android 템플릿에 제한된 검사 인자 전달 코드를 준비한다. Godot 4.7의 기본 시작 Activity는 외부 인자를 정리하므로 이 코드가 포함된 새 APK가 필요하다. 도구는 debug APK와 `org.forest_arena.qa_launch_adapter` 표시를 설치 전에 확인한다. 오래된 APK는 실제 기기를 조작하기 전에 거절한다.

Android 실행 인자 `command_line_params`에는 `--`, `--qa-run`, `--qa-device` 세 값만 허용한다. Android `BuildConfig.DEBUG`와 Godot debug 빌드 확인을 모두 거친 뒤 검사 모드를 켠다. 일반 실행과 release 빌드에서는 활성화되지 않는다. 실행 ID별 `user://qa/<run>` 아래에 기기 저장·설정·게스트 세션을 분리한다. 일반 플레이 저장을 삭제하지 않는다. 재실행 복원 검사는 같은 실행 ID를 사용하고 새 프로세스의 `boot_id`를 확인한 뒤 판정한다. 이전 프로세스의 상태 파일만 읽어 통과하지 않는다.

화면과 버튼·선택 목록·터치 영역은 안정적인 진단 ID와 현재 위치를 제공한다. 화면이 바뀔 때 위치를 다시 읽고 ADB의 누름·해제로 조작한다. 선택 목록은 실제 ADB 터치로 열고 키 이동·확정으로 선택하며 입력 방식에 따로 기록한다. 실제 입력 기록과 게임의 상태 변화가 모두 있어야 터치 검사를 통과한다. 자동 전투는 `LocalAICommandSource`의 판단을 `CombatIntent` 입력으로 전달한다. 오프라인은 기존 전투 처리, LAN은 기존 입력 메시지·순번 처리를 사용하며 실제 시간·60Hz 전투 설정을 유지한다.

ADB 터치와 debug 자동 입력은 결과에서 구분한다. 실제 터치 검사 때 자동 입력을 중지하며, 일시정지·포커스 손실·연결 단절·재대전 때 남은 입력을 해제한다. 자동 전투만으로 실제 동시 터치나 사람이 느끼는 조작 품질을 확인했다고 기록하지 않는다.

LAN 검사는 매 실행마다 별도 테스트 게스트 API를 사용한다. APK는 게스트 생성·갱신·닉네임 API와 LAN v2 서버의 인증 절차를 거친다. 테스트 API는 메모리 안에만 계정과 임시 인증값을 보관한다. 이는 격리된 테스트 데이터(fixture)를 이용한 LAN 흐름 검증이며, 실제 데모 API·PostgreSQL 인증·운영 환경 검증은 [데모 설치 안내](../../gameplay/demo-install.md)의 별도 검사다.

| UI-01 | 첫 캐릭터·0원 구매·선택·설정 조작, 재실행 뒤 보유·선택·설정 복원 | ADB 터치 |
| OFF-01 | 네 캐릭터와 장신구 없음·6종 선택을 실제 경기에 각각 반영 | ADB 터치/키/진단 |
| INPUT-01 | 이동·점프·약/강/특수 공격·회피의 누름·해제와 실제 상태 변화, 궁극기 조건 충족 전후 구분 | ADB 터치 |

| SOAK-01 | 지정한 시간 동안 결과·재대전 반복, 충돌·응답 멈춤·입력 고착 없음 | debug 자동 입력/ADB 터치 |
| MANUAL-01 | 실제 Wi-Fi 끄기/켜기 뒤 상대 상태·입력 해제·재접속 또는 이탈 패배 | 사람이 기기 조작 |

`extended`는 네 캐릭터 × 장신구 없음·6종의 28개 조합을 기기들에 나누어 배정한다. 시간이 끝나기 전에 완료하지 못한 조합은 `미실행`이다. 자동 장애 검사는 게임 연결만 차단하며 ADB 무선 디버깅 연결과 기기 Wi-Fi 설정을 끄지 않는다.

수동 재검사 이름은 `MANUAL-01 실제 Wi-Fi 단절·복귀`, `MANUAL-02 실제 동시 터치`, `MANUAL-03 소리 청취·진동 체감`이다. APK 해시·기기 별칭·수행 날짜·조작 순서·관측 결과를 남긴다. 미수행 항목은 자동 검사 결과와 함께 미실행으로 남긴다. Story 대화·보상·성장·경제, 개발용 DB 저장과 정식 인터넷 온라인·4인 온라인은 검사 범위 밖이다.

## 판정과 증거

APK 설치 제한은 600초이며 화면 대기 30초·자동 전투 한 판 최대 5분과 별도로 계산한다. 자동 전투에서 30초간 피해·남은 기회 변화가 없으면 증거를 모아 실패로 기록한다. 연습·일시정지·의도적인 연결 장애 시간은 전투 정체 검사에서 제외한다.

- `pass`: 기대한 상태 변화와 증거를 실제로 확인했다.
- `fail`: 연결 가능한 환경에서 기대 동작을 확인하지 못했거나 게임이 충돌했다.
- `blocked`: 기기·도구·서버가 없거나 예상하지 않은 ADB 단절로 확인할 수 없다.
- `미실행`: 기기 쌍 부족·시간 부족·수동 확인 대기로 해당 검사를 수행하지 않았다.

ADB 단절은 해당 시도를 `blocked`로 남긴다. 연결 복구 뒤 새 실행 ID로 다시 검사하고 이전 결과는 보존한다. 연결 기기 없음과 한 대만 연결된 LAN은 통과가 아니다.

결과에는 형식 버전·실행 ID·케이스 ID·기기 별칭·단계·기대값·관측값, APK 해시·코드 버전·기기 정보, JSON 결과·한국어 요약·게임 및 서버 로그·주요 화면 캡처를 남긴다. FPS·프레임 시간 p95·메모리·발열은 측정값으로 보고한다. 승인된 성능 합격 수치가 없으므로 측정만으로 성능 통과를 선언하지 않는다. 조회할 수 없는 값은 `미확인`이다.

다음 명령으로 기기 조작 전에 실행 도구·저장 분리·LAN 두 경기 분리를 확인할 수 있다. 두 경기 검사는 서로 다른 로컬 서버·테스트 API에 네 인증 클라이언트를 붙인다. 한 경기의 이동 입력이 다른 경기로 전달되지 않는지, 첫 서버를 종료해도 두 번째 경기가 계속되는지 검사한다.

```sh
python3 -m unittest discover -s tools/forest_arena -p test_android_fleet.py
python3 tools/forest_arena/test_prepare_android_qa.py
godot --headless --path . --script res://tests/android_qa_session.gd
./scripts/verify-android-qa-lan.sh
```

도구 자동 테스트와 화면 없는 Godot 검사의 통과는 실행 도구 검증 결과다. 최신 APK로 실제 기기에서 수행한 케이스만 물리 기기 확인 결과에 포함한다.
