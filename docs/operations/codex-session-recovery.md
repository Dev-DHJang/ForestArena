# Codex 세션 로딩 복구

“이 작업의 메시지를 불러오는 중 시간이 초과되었습니다”가 반복되면 새 채팅에서 세션 ID를 받아 아래 명령을 실행한다. 이전 채팅 내용을 읽어오거나 새 Goal을 만드는 작업은 필요하지 않다.

## 즉시 복구

Forest Arena 프로젝트 루트에서 실행한다.

```sh
python3 tools/forest_arena/recover_codex_session.py repair 01a0a530-8f01-7f61-a947-9719bb0397f4
```

다른 세션은 마지막 ID만 바꾼다. 진단만 하려면 `repair` 대신 `inspect`를 사용한다. Python 3.11 이상이 필요하고 이미지 미리보기를 줄일 때는 Pillow가 필요하다. 현재 프로젝트 이미지 도구와 같은 Python 환경을 사용한다. 다른 로컬 계정 또는 별도 저장 위치는 `--codex-home /실제/Codex/저장폴더`로 지정한다. 기본값은 `CODEX_HOME`, 없으면 사용자 홈의 `.codex`다.

성공 결과에는 변경한 항목 수, 전후 표시 데이터 크기, 백업 위치, 데이터베이스 검사 결과가 나온다. 원본 대화나 이미지 문자열은 출력하지 않는다. 다른 채팅으로 이동했다가 대상 세션을 다시 열어 화면을 확인한다. 도구가 연결돼 있으면 `navigate_to_codex_page`로 전환할 수 있다. 같은 화면만 다시 선택하면 기존 표시 상태가 남을 수 있다.

**사용자가 실제 대화 화면을 확인하기 전에는 복구 완료로 단정하지 않는다.** 서버 조회 성공과 화면 표시 성공은 다르다. 여전히 실패하면 앱의 새로고침 또는 재실행이 필요할 수 있다. 다른 작업이 실행 중이면 앱 전체를 임의로 종료하지 않는다.

## 새 채팅에 전달할 문장

> Forest Arena 프로젝트의 AGENTS.md와 docs/operations/codex-session-recovery.md를 따라 세션 `<세션-ID>`의 메시지 로딩 시간 초과를 복구해줘. 기존 Goal과 작업 기록은 보존하고, 화면에서 열리는지 확인해줘.

## 도구가 변경하는 것

이 도구는 확인된 로컬 파일 형식 `thread_history_1.sqlite`에서 지정한 세션의 화면용 기록만 수정한다. 완료되거나 실패한 도구 호출의 긴 문자열과 첨부 스크린샷을 표시용 요약으로 바꾸고, 별도 원본 파일이 존재하는 완료된 이미지 생성의 미리보기를 최대 192px PNG로 줄인다. 투명도는 유지한다. 아직 실행 중인 항목은 바꾸지 않는다.

원본 세션 파일, 사용자·에이전트 메시지, 실제 이미지, 프로젝트 자산, Goal 상태·예산·완료 조건은 수정하지 않는다. 압축된 모델 컨텍스트를 새로 만드는 명령도 아니다. 앱 버전에서 저장 형식이 달라지면 중단하고 오류를 보고한다. 이 절차는 내부 표시 저장소를 직접 수정하는 복구 방법이며 OpenAI가 보장하는 앱 기능은 아니다.

백업은 Codex 저장 폴더의 `recovery/session-<ID>-<시간>/`에 둔다. 원본 세션 파일, 세션별 DB 행, Goal 사본, 변경 전후 해시, 결과를 포함한다. 대화가 포함되므로 백업을 Git·PR·외부 서비스에 업로드하지 않는다. 백업 파일과 디렉터리를 디스크에 저장한 다음 표시 기록을 변경한다. 준비 중 원본이나 대상 행이 바뀌면 중단하므로 진행 중인 턴을 정상 종료한 후 다시 실행한다.

## 복원

필요할 때 `repair`가 출력한 정확한 백업 폴더를 사용한다.

```sh
python3 tools/forest_arena/recover_codex_session.py restore <세션-ID> --backup <백업-폴더>
```

해당 복구가 변경한 행만 되돌린다. 복구 후 앱이 그 행을 갱신했다면 새 기록을 덮어쓰지 않고 중단한다. 복원하면 대용량 미리보기와 시간 초과가 다시 생길 수 있다. Goal이나 실제 이미지까지 되돌리는 명령이 아니다.

## 재발과 작업 재개

도구 출력을 새로 쌓거나 앱이 원본에서 화면 기록을 다시 만들면 용량이 커질 수 있다. 재발 시 같은 `repair` 명령을 다시 실행한다. 이미 축소된 기록만 있으면 변경 없이 종료한다. 자동 감시나 앱 데이터 삭제는 하지 않는다.

이미지 업로드에 base64를 명령·도구 인수로 길게 붙이거나 파일 diff 전체를 출력하지 않는다. 파일 업로드를 우선하고 검사 결과는 수치·경로·짧은 요약으로 남긴다. 앱 자체의 이미지 기록은 프로젝트 지침만으로 막을 수 없으므로 재발하지 않는다고 보장하지 않는다.

대화가 열린 뒤 승인 요청이 남아 있으면 기존 요청을 확인한다. 사용량 제한 또는 Goal 일시 중단은 로딩 오류와 별개다. 복구 도구는 이를 자동 승인하거나 재개하지 않는다. 기존 Goal과 프로젝트의 작업 마무리 기록을 기준으로 이어간다.

## 검증

```sh
python3 tools/forest_arena/test_recover_codex_session.py
./scripts/verify-docs.sh
./scripts/verify-harness.sh
```

자동 검사는 다른 세션·대화·Goal·원본 파일 보존, 진행 중 항목 보존, 투명 미리보기, 반복 실행, 복원, 새 기록 덮어쓰기 거부와 백업 불가 시 중단을 확인한다. 기본 검사 `./scripts/verify.sh`에도 포함된다.
