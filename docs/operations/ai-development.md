# 07. AI 개발 가이드

이 문서는 AI가 저장소 작업을 빠뜨리지 않게 하는 절차다. 문서 위치는 [문서·파일 색인](../INDEX.md)에서 찾고, 역할 이름과 결과 상태가 낯설면 [용어 가이드](../GLOSSARY.md#프로젝트-진행-용어)를 먼저 읽는다.

## 문장과 용어

- 쉬운 한국어로 행동과 결과를 먼저 쓴다.
- 코드나 도구의 정확한 이름은 유지하고 첫 등장에 쉬운 뜻을 붙인다.
- 두 문서 이상에서 반복되는 전문 용어는 `docs/GLOSSARY.md`에 추가한다.
- 새 문서나 파일을 추가하면 목적에 맞는 폴더에 두고 `docs/INDEX.md`에 연결한다.
- 새 최상위 문서 폴더를 임의로 만들지 않는다. 기존 분류로 설명하기 어렵다면 먼저 색인의 분류표를 갱신한다.

## 작업 순서

1. README.md의 문서 우선순위와 현재 Phase를 확인한다.
2. 목표, 개발 단계, 할 일, 하지 않을 일, 반드시 지킬 조건, 완료 판단 조건과 검사 방법을 `_workspace/<topic>/00_request.md`에 적는다.
3. 여러 코드가 함께 쓰는 Godot 데이터, 저장 형식, ID 또는 통신 규칙이 바뀌면 계약 역할이 `01_contract.md`를 먼저 작성한다.
4. 한 영역의 작업은 해당 전문가 역할이 처리한다. 여러 영역이나 개발 단계에 걸친 작업은 조율 역할(orchestrator)이 꼭 필요한 역할만 고른다.
5. 구현 역할은 자동 테스트 또는 이름을 붙인 수동 재검사를 수행한다.
6. 품질 역할(QA)은 원 요청과 데이터를 만드는 쪽·읽어 사용하는 쪽이 같은 규칙을 따르는지 함께 검토한다.
7. 아직 정하지 않은 장기 규칙은 `proposed` 결정 기록으로 남기고 사용자 승인 전에 `accepted`로 바꾸지 않는다.
8. 실제 Android 기기에서 수행하지 않은 검증은 에디터 결과와 구분한다.
9. 비전투 UI 작업은 `docs/ui/non-combat-ui-v01.json`과 `assets/ui/asset-requirements.csv`를 먼저 읽고 product/contracts → ui/image-design → mobile/qa 순서로 인수인계한다.

## 작업 증적

- `00_request.md`: 목표, 할 일과 제외할 일, 반드시 지킬 조건, 완료 판단 조건과 담당.
- `01_contract.md`: 여러 코드가 함께 쓰는 데이터 형식이 바뀔 때 구현 전에 작성.
- `02_<role>.md`: 역할별 변경, 데이터를 만드는 쪽과 읽는 쪽, 검사와 위험.
- `03_qa_rNN.md`: 품질 검사 회차별 통과(`pass`), 수정 필요(`fix`), 설계 재검토(`redo`) 또는 진행 불가(`blocked`).
- `04_closeout.md`: 최종 상태, 실행한 검사와 못 한 검사, 브랜치·커밋·PR·병합·되돌리는 방법과 다음 작업.

## 초기 구현 금지

현재 Phase 2 완료 상태에서는 정식 선택 UI, 24개 비전투 화면의 실제 Godot 구현, 성장·재화 UI, 계정, 상점, 결제, 광고, 온라인 매칭, 실제 서비스용 서버와 전체 자산 다운로드를 만들지 않는다. 기본 전투와 `캐릭터 + 직업 + 장신구` 조합은 동작하지만, 승인된 콘셉트와 애니메이션 묶음이 공격 적중이나 승패를 정하지는 않는다. 온라인 요청은 Phase 7과 관련 결정·데이터 형식이 승인되기 전까지 `blocked`(진행 불가)로 기록하고, 다시 시작할 조건을 남긴다.

## 인수인계 확인

- 바뀐 문서·코드·데이터·에셋 경로.
- 데이터를 만드는 쪽과 읽어 사용하는 쪽이 공유하는 ID, 상태, 사건 이름과 실패 의미.
- 실행한 테스트와 실행하지 못한 기기·서비스 검증.
- 임시 결정, ADR 상태와 재개 조건.
- 사용자 변경 보존 여부, 롤백 지점과 다음 담당.
