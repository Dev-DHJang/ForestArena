# 프로젝트 작업·검사·파일 정리

## 작업 폴더와 최신 상태

- 기본 폴더는 최신 통합본 확인용이다. 코드를 수정하는 채팅마다 최신 `origin/develop`에서 전용 Git 작업 폴더(worktree)와 `codex/` 브랜치를 만든다. 기존 적절한 작업 폴더가 있으면 재사용한다.
- 시작할 때 `git fetch origin` 뒤 `python3 tools/forest_arena/workflow.py status`로 실제 폴더·브랜치·기준 커밋·차이를 확인한다. 대화에 표시된 프로젝트 이름만으로 폴더를 판단하지 않는다.
- 서로 다른 폴더의 파일을 통째로 복사하지 않는다. 공통 조상에서 바뀐 내용과 승인 상태를 비교하고 한 담당자가 순서대로 통합한다. 다른 채팅의 미커밋 변경은 그대로 보존한다.
- 기본 폴더를 갱신하기 전 수정·미추적 파일의 복구 가능한 백업과 파일 지문(해시)을 남긴다. 통합됐거나 더 새 버전으로 대체됐는지 확인한 뒤 최신 통합 커밋으로 맞춘다. 확인되지 않은 변경은 별도로 보존한다.
- 단순 변경은 한 에이전트가 관련 문서·스킬만 읽는다. 독립 검토와 승인 경계는 [팀 명세](harness/team-spec.md)를 따른다. 긴 로그는 파일에 저장하고 대화에는 결과·원인·다음 조치만 요약한다.

## 검사 명령과 선택

| 명령 | 동작 |
| --- | --- |
| `./scripts/verify.sh` 또는 `--changed` | 기준 브랜치와 달라진 커밋·수정·추가·삭제 파일의 관련 검사 |
| `./scripts/verify.sh --list` | 파일별 선택 이유와 실행 명령만 표시 |
| `./scripts/verify.sh --full` | 기존 전체 검사와 새 정비 검사. 최종 통합·병합 전에 실행 |
| `./scripts/verify.sh --suite docs` | 지정 분야만 검사. 전체 분야는 `--help` 참고 |
| `./scripts/verify.sh --base HEAD --list` | 현재 미커밋 변경만 기준으로 선택 확인 |

분야별 검사 목록은 `tools/forest_arena/verification.json`, 파일별 선택 규칙은 `tools/forest_arena/verify_runner.py` 한 곳에서 관리한다. 문서만 바뀌면 문서 검사만 실행한다. 알려지지 않은 실행 코드·공용 설정은 전체 검사로 처리하며 기준 브랜치를 찾지 못하면 조용히 건너뛰지 않고 오류로 알린다. 장시간 AI 조합 검사는 `soak` 분야와 전체 검사에 남긴다.

- 실행 로그와 명령·시간·결과는 `build/verification/<실행-ID>/`에 저장한다. 검사 보고서를 과거 `_workspace/` 기록에 다시 쓰지 않는다. 필요한 최종 결과만 해당 작업의 종료 기록에 연결한다.
- 같은 폴더의 기본 검사·LAN/온라인 검사·Android 내보내기는 `workflow.py`의 작업 잠금을 공유한다. 다른 작업이 사용 중이면 소유자와 명령을 알리고 중단한다. 자식 명령은 같은 잠금을 이어 쓰며, 프로세스 종료 후 운영체제가 잠금을 해제한다. 편집기나 임의의 직접 `godot` 명령까지 잠그는 기능은 아니다.
- LAN 검사는 실행별 loopback 포트·임시 로그를 사용한다. Android 기기는 여러 채팅이 동시에 설치·조작하지 않고 한 담당자가 순서대로 사용한다.
- 전체 검사에서 Godot 가져오기는 한 번 실행한다. Node 의존성은 package·잠금 파일·Node/npm·실행 환경과 설치 상태가 같으면 재사용한다.
- 종료 코드와 Godot 오류 메시지를 함께 본다. 기존 종료 시 리소스 정리 진단은 결과에 별도 기록한다. 스크립트·파싱·그 밖의 엔진 오류는 통과시키지 않는다.
- 통과 이후 새 변경·실패·미확인 근거가 없으면 같은 검사를 반복하지 않는다. 이 도구 정비는 게임 규칙·저장·통신 형식을 변경하지 않는다.

## 아이콘과 APK

프로젝트와 Android Debug·Demo는 `assets/branding/myo-ryung-v02/manifest.json`에 기록한 상반신 아이콘을 사용한다. 이미지 자체의 승인·출처 기록은 보존한다.

- `python3 tools/forest_arena/verify_branding.py`: 원본 해시·크기·투명도·몸 연결·모든 Android 아이콘 경로 확인.
- `python3 tools/forest_arena/verify_branding.py --apk <APK> --output <결과.json>`: 실제 네이티브 아이콘·시스템 시작 아이콘·패키지 프로젝트 설정 확인.
- Android 내보내기는 APK 옆에 소스 커밋·APK 해시·버전·아이콘 기록을 남긴다. 이 기록과 설치 파일을 대조해 오래된 APK를 구분한다.
- 원형·둥근 사각형의48·72·192px에서 목·어깨·옷이 이어지는지 확인한다. 실제 홈 화면·업데이트 설치·재실행은 Android 기기에서 별도로 확인하고 미실행을 통과로 바꾸지 않는다.

## 파일 정리와 보존

| 위치 | 보존 기준 |
| --- | --- |
| `docs/` | 현재 기준은 한 곳에 적고 `docs/INDEX.md`에서 연결. 과거 점검은 당시 날짜를 명시 |
| 실행 코드·`assets/`·`forest_arena/` | 코드·장면·Resource·등록표·내보내기·제작 도구 참조를 함께 조사 |
| `_workspace/<topic>/` | 요청·종료 기록, 승인 원본·필수 검토 증거·복구 원본 보존 |
| `build/android/`, `build/demo/`, `artifacts/` | 최신 검증·배포·문서에서 연결한 결과 보존. 대체된 생성물만 정리 |
| `android/`, `.godot/`, Node·Gradle 캐시 | 반복 검사에 유용한 캐시 유지. 현재 작업 중인 캐시를 지우지 않음 |
| 서버·DB·개인 설정 | 비밀·DB 데이터·볼륨·서명 키·SDK·사용 중인 다른 작업 폴더를 일괄 정리하지 않음 |

정리 전 목록·용량·참조 근거·복구 위치를 기록한다. 승인되지 않은 후보나 미추적 파일을 미사용으로 단정하지 않는다. 작업·빌드·배포 폴더에는 `.gdignore`를 두며, 이 안의 재생성 가능한 `.import`는 이미지 원본과 구분한다. 원본 삭제와 캐시 삭제는 별개다. 큰 폴더를 백업할 때는 여유 공간을 먼저 확인하고 새 전체 작업 폴더 복사와 동시에 수행하지 않는다.

이름 있는 수동 재검사: `기존 변경 보존 확인`(백업 해시 대조), `생성 파일 분리 확인`(작업·빌드 폴더가 새 게임 자산으로 검색되지 않음), `Android 아이콘 업데이트 확인`(설치 APK·홈 화면·재실행 대조).
