# 06. 로드맵과 수용 기준

앞 Phase의 필수 종료 기준을 건너뛰지 않는다. 콘텐츠 수량과 일정은 근거 없는 확정값으로 만들지 않는다.

## Phase 0 — 실행 기반

Godot 프로젝트, 폴더, Android export, 의미 InputMap, 2D 테스트 경기장과 도형 기반 임시 파이터를 만든다. 전체 공격 체계 v01은 문서·계약 검사만 완료했으며 런타임 전투는 아직 만들지 않았다.

Forest Arena 브랜드, 비전투 화면·에셋 ID와 Penpot 작업 계약은 Phase 0의 설계 기반으로 유지할 수 있다. 이는 24개 화면 구현, 이미지 생성, 계정·상점·랭크·온라인 기능 또는 Phase 승격을 뜻하지 않는다.

종료 기준: 데스크톱 부트와 Android debug export가 실제 명령으로 재현되고, 터치·중단·복귀의 검증 계획 및 측정할 성능 ADR이 있다.

## Phase 1 — 코어 전투

결정론적 X/Y 이동, 점프, 대시, 공격 단계, Hitbox/Hurtbox, 넉백, 링아웃과 최소 터치 전투를 만든다. 우선 지상 기본 연계·방향 강공격·대시 공격·공중 약/강·대표 특수기와 복귀를 구현한다.

종료 기준: 빗나감, 단일 적중, 동시 타격, 자가 타격 방지, 반복 적중 방지, 링아웃과 입력 해제 회귀가 통과한다.

## Phase 2 — 데이터와 로드아웃

Resource 계약과 CharacterData + JobData + AccessoryData 조합을 만든다. MoveSetData는 기술 목록·분기·입력 조건·시각 상태 참조를, AttackData는 타이밍·판정을 소유하도록 versioned 계약을 확정한다.

종료 기준: 조합 순서, 잘못된 ID, 충돌과 소스 Resource 비변경성이 자동 검사된다.

## Phase 3 — 전투 원형 비교

서로 다른 전투 성향의 소수 캐릭터·직업 원형을 플레이테스트한다. 방어·회피·차지·필살기와 네 방향 특수기 비교는 ADR 승인 뒤 이 Phase부터 검증한다.

종료 기준: v2 계약·구버전 거부·결정론·모바일 입력·HUD 비권위가 자동 검사되고, 각 원형의 가설·공통 조건·결과·유지·조정·폐기 근거가 기록된다. 단일 참여자는 Galaxy S23 Ultra에서 기본형 3개와 전문 직업 3개를 세 봇 프로필과 각각 대전하는 18개의 3-stock 매치를 완료한다. 같은 기기에서 1280×720, GL Compatibility, 60 FPS 및 p95 16.7ms 이하를 10분 연속 전투로 확인한다. 실기기 증적 또는 독립 QA가 없으면 Phase 3은 완료가 아니라 blocked다.

## Phase 4 — 장신구

데이터 기반 단일 장신구와 Character/Job 태그 시너지를 검증한다.

종료 기준: 태그 만족·불만족, 기술 교체, 충돌 우선순위와 시각 비권위가 검사된다.

## Phase 5 — 직업 성장 구조

분기형 직업이 이동, 기술, 패시브와 취소 규칙을 바꾸는지 검증한다. 영속 성장과 경제는 분리한다.

종료 기준: 부모·단계·누적 규칙과 런타임 조합이 일관되고 이름별 공용 코드 분기가 없다.

## Phase 6 — 오프라인 수직 슬라이스

Android Story·AI·Practice와 Solo/Team의 오프라인 검증 범위, 결과 흐름, 2D 표현, 오디오, 접근성과 모바일 안정성을 통합한다. 전체 최대 8명과 Team 팀당 1~4명 규칙을 만족하되 온라인 기능을 암시하지 않는다.

종료 기준: 승인된 콘텐츠와 전체 사용자 흐름이 Android에서 검증되고 알려진 차단 결함이 없다.

## Phase 7 — 온라인 검토와 구현

승인된 ADR과 versioned 계약 이후에만 온라인 권위 모델, 전송, 재접속과 Android 네트워크 전환을 구현한다.

종료 기준: 중복·역순·손실·버전 불일치, 앱 중단·복귀와 재접속 실패에서도 권위 결과가 일관된다.

## 공통 완료 정의

- _workspace 요청, 생산, QA와 closeout 증적이 있다.
- 전투 판정과 시각·UI·오디오의 권한 경계를 지킨다.
- 새 기능에는 자동 테스트 또는 이름 있는 수동 회귀가 있다.
- Android 실제 기기 미검증을 pass로 표시하지 않는다.
- 외부 에셋은 출처·라이선스와 교체 가능한 래퍼가 있다.
- 미정 규칙은 proposed ADR이며 사용자 승인 없이 accepted가 아니다.
- 향후 코드 작업은 QA pass와 원격 develop 병합 증적이 모두 있어야 완료다.
