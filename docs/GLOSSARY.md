# Forest Arena 용어 가이드

이 문서는 게임 개발이 처음인 소프트웨어 개발자를 위한 빠른 참고서다. 본문에서는 쉬운 한국어를 먼저 쓰고, 코드나 도구에서 실제로 검색해야 하는 이름만 괄호나 백틱으로 함께 쓴다.

## 문서 작성 원칙

1. 전문 용어보다 독자가 해야 할 일과 결과를 먼저 쓴다.
2. 전문 용어가 꼭 필요하면 첫 등장에 `쉬운 설명(전문 용어)` 순서로 쓴다.
3. `CharacterData`, `AttackData`, `Area2D`처럼 코드에 있는 이름은 번역하지 않는다. 대신 바로 뒤에서 역할을 설명한다.
4. `권위`, `소비`, `주입`, `영속`처럼 일반적인 뜻과 다르게 쓰이는 말은 단독으로 쓰지 않는다.
5. 완료 여부는 `좋아 보인다`가 아니라 실행하거나 관찰할 수 있는 조건으로 쓴다.

권장 표현은 다음과 같다.

| 피할 표현 | 먼저 쓸 쉬운 표현 |
| --- | --- |
| 권위 있는 데이터 | 실제 결과를 정하는 기준 데이터 |
| 생산자 / 소비자 | 데이터를 만드는 쪽 / 읽어 사용하는 쪽 |
| 런타임 주입 | 게임 시작 시 선택 데이터를 합쳐 적용 |
| 영속 데이터 | 앱을 종료해도 남는 저장 데이터 |
| 수용 기준 | 완료 판단 조건 |
| 불변 조건 | 반드시 지킬 조건 |
| 회귀 검사 | 기존 기능이 다시 깨지지 않았는지 확인하는 검사 |
| 게이트 | 다음 단계로 가기 전에 충족할 조건 |
| 단일 원본 | 최종 기준으로 삼는 한 파일 |
| 경계 | 무엇이 결과를 정하고 무엇이 표시만 하는지에 대한 책임 구분 |

## 프로젝트 진행 용어

| 용어 | 쉬운 설명 |
| --- | --- |
| Phase(개발 단계) | 큰 작업 순서다. 현재는 Phase 2까지 끝났으며, 번호가 뒤인 기능은 앞 단계가 끝나고 승인을 받아야 시작한다. |
| 프로토타입 | 아이디어가 실제로 재미있고 동작하는지 빠르게 확인하는 시험 버전이다. |
| 수직 슬라이스 | 메뉴부터 한 판 종료까지 핵심 경험을 작지만 실제로 플레이할 수 있게 만든 버전이다. |
| 범위 | 이번 작업에서 할 일과 하지 않을 일의 선이다. |
| 완료 판단 조건(수용 기준) | 무엇을 확인하면 작업이 끝났다고 볼지 미리 적은 조건이다. |
| 다음 단계 조건(게이트) | 다음 Phase나 기능으로 넘어가기 전에 반드시 충족해야 하는 조건이다. |
| ADR(Architecture Decision Record) | 중요한 결정을 이유, 대안, 영향과 함께 남긴 기록이다. 이름은 기술 결정 기록이지만 이 프로젝트에서는 제품 규칙도 기록한다. |
| `proposed` | 제안 상태다. 아직 구현 기준으로 확정하지 않는다. |
| `accepted` | 사용자가 승인하여 구현 기준으로 쓸 수 있는 상태다. |
| `superseded` | 더 새로운 결정으로 교체된 상태다. 과거 기록은 삭제하지 않는다. |
| 계약 | 여러 코드나 작업자가 같은 데이터 이름, 형식과 동작을 쓰도록 정한 약속이다. 법률 계약이 아니다. |
| 단일 원본 | 충돌할 때 최종 기준으로 삼는 한 파일이다. 같은 내용을 여러 파일에 복사하지 않는다. |
| 하네스 | AI 작업을 역할별로 나누고, 필요한 문서와 검사를 빠뜨리지 않게 하는 프로젝트 운영 장치다. 게임 실행 코드가 아니다. |
| 인수인계 | 다음 작업자가 이어서 일할 수 있도록 변경 내용, 검사 결과와 남은 문제를 기록하는 일이다. |
| closeout(마무리 기록) | 작업 결과, 실행한 검사, 미확인 항목과 되돌리는 방법을 적은 문서다. |

## 세계관과 이야기 용어

| 용어 | 쉬운 설명 |
| --- | --- |
| 베르디아 | Forest Arena의 주요 무대인 거대한 숲 세계다. 여러 종족, 지역과 독립 세력이 함께 산다. |
| 검은 밤 | 약 30년 전 중립 도시 로엔이 여러 무장 세력의 충돌로 무너진 밤이다. 지역마다 다른 기록과 피해 기억이 남아 있다. |
| 기록회 | 검은 밤 전 여러 종족이 함께 만든 중립 기록 조직이다. 사건을 판결하는 대신 당시 자료를 남기는 일을 맡았다. |
| 기록자 | 기록회에서 문서, 증언, 지도와 현장 물품을 조사하고 보존하던 사람이다. |
| 기록고 | 기록회가 남긴 문서, 지도, 증언, 물품과 특수 기록 매체를 보관하는 시설이다. |
| 기록인장 | 기록고의 특정 자료와 내부 구역에 들어갈 수 있음을 증명하는 물건이다. 자료 접근 권한일 뿐, 사건의 정답을 자동으로 알려 주지 않는다. |

## 전투와 게임 규칙 용어

| 용어 | 쉬운 설명 |
| --- | --- |
| 플랫폼 격투 | 발판이 있는 경기장에서 상대를 밖으로 밀어내는 방식의 격투 게임이다. |
| 파이터 | 플레이어 또는 AI가 조작하는 전투 캐릭터다. |
| 링아웃 | 캐릭터가 경기장 밖의 탈락 영역으로 나간 상태다. |
| stock(남은 기회) | 링아웃되어도 다시 돌아올 수 있는 횟수다. 현재 한 판을 3회로 시작한다. |
| 스폰 | 캐릭터가 경기장에 처음 나타나거나 링아웃 뒤 다시 나타나는 일과 위치다. |
| 넉백 | 공격에 맞은 캐릭터를 밀어내는 힘과 움직임이다. |
| 경직 | 공격에 맞아 잠시 행동할 수 없는 시간이다. |
| 히트스톱(hit-stop) | 타격감을 위해 맞는 순간 화면이나 캐릭터 움직임을 아주 잠깐 멈추는 효과다. |
| 연계 / 콤보 | 여러 공격을 정해진 입력 가능 시간 안에 이어 쓰는 것이다. |
| 피니시 | 연계를 끝내면서 상대를 강하게 밀어내는 마지막 공격이다. |
| 가드 | 공격을 막는 행동이다. |
| 패리 | 정확한 순간에 막아 유리한 결과를 얻는 방식이다. 현재 초기 규칙에는 없다. |
| 차지 | 버튼을 누르고 기다려 공격을 강화하는 방식이다. |
| 쿨다운 | 기술을 사용한 뒤 다시 쓰기까지 기다려야 하는 시간이다. |
| 대공 | 공중에 있는 상대를 견제하거나 공격하는 기술이다. |
| 판정 | 공격이 맞았는지, 얼마나 밀리는지, 누가 이겼는지를 계산한 실제 게임 결과다. |
| hitbox(공격 판정 영역) | 상대에게 닿으면 공격이 맞았다고 계산하는 보이지 않는 영역이다. |
| hurtbox(피격 판정 영역) | 공격을 맞을 수 있는 캐릭터의 보이지 않는 영역이다. |
| startup / active / recovery | 공격 버튼을 누른 뒤 `준비 시간 / 실제로 맞힐 수 있는 시간 / 다시 행동하기까지의 시간`이다. |
| 상태 머신 | 대기, 점프, 공격, 피격처럼 현재 가능한 상태와 상태가 바뀌는 규칙을 관리하는 코드다. |
| tick(고정 계산 단위) | 프레임 표시 속도와 별개로 전투를 일정한 간격으로 계산하는 한 번의 단위다. |
| 결정론적 전투 | 같은 시작 상태와 같은 입력을 주면 언제나 같은 결과가 나오는 전투 계산 방식이다. |
| 로드아웃 | 한 판을 시작할 때 고른 `캐릭터 + 직업 + 장신구` 조합이다. |
| 태그 시너지 | 같은 분류표를 가진 데이터가 조합될 때 추가 효과가 생기는 규칙이다. |

## 화면과 그래픽 용어

| 용어 | 쉬운 설명 |
| --- | --- |
| UI | 메뉴, 버튼, 선택 화면처럼 사용자가 조작하거나 정보를 읽는 화면 요소다. |
| UX | 사용자가 조작을 배우고 목표를 달성하는 전체 경험이다. |
| HUD | 전투 중 피해율과 남은 기회처럼 계속 보여 주는 정보 영역이다. |
| VFX | 타격 섬광, 먼지, 궤적 같은 시각 효과다. |
| BGM / SFX | 배경 음악 / 버튼·타격 같은 효과음이다. |
| 스프라이트 | 2D 게임 화면에 그리는 캐릭터나 물체 이미지다. |
| 프레임 애니메이션 | 여러 장의 이미지를 빠르게 바꾸어 움직임처럼 보이게 하는 방식이다. |
| 스프라이트 시트 / 아틀라스 | 여러 이미지를 한 장에 모아 둔 큰 이미지다. |
| `SpriteFrames` | Godot에서 프레임 이미지와 재생 속도를 묶는 데이터 형식이다. |
| 턴어라운드 | 캐릭터의 앞, 옆, 뒤 모습을 일관되게 보여 주는 디자인 자료다. |
| 키 포즈 | 동작을 가장 잘 설명하는 핵심 자세다. 중간 프레임의 기준이 된다. |
| 패럴랙스 | 카메라가 움직일 때 먼 배경을 더 천천히 움직여 깊이감을 만드는 효과다. |
| safe area(안전 영역) | 노치, 둥근 모서리와 운영체제 제스처에 가리지 않는 화면 영역이다. |
| 논리 해상도 | 기기 실제 픽셀 수와 상관없이 게임 배치를 계산할 때 기준으로 쓰는 화면 크기다. 이 프로젝트는 1280×720이다. |
| 플레이스홀더 | 최종 이미지나 소리가 준비되기 전 기능 확인에 쓰는 임시 자산이다. |
| Penpot | 화면 설계를 만드는 디자인 도구다. Godot에서 실행되는 게임 화면 자체는 아니다. |

## Godot와 데이터 용어

| 용어 | 쉬운 설명 |
| --- | --- |
| Godot | 이 게임을 만들고 실행하는 게임 엔진이다. |
| GDScript | Godot에서 사용하는 스크립트 언어다. `typed GDScript`는 변수와 반환값의 자료형을 적어 오류를 일찍 찾는 작성 방식이다. |
| Resource | Godot가 저장하고 편집할 수 있는 데이터 객체다. 이 문서에서 대문자 `Resource`는 Godot 형식을 뜻한다. |
| 런타임 | 에디터에서 만드는 시간이 아니라 게임이 실제로 실행 중인 때다. |
| 런타임 프로필 | 한 판을 시작할 때 캐릭터, 직업과 장신구 데이터를 합쳐 만든 전투용 복사본이다. 원본 파일은 바꾸지 않는다. |
| ID | 표시 이름이 바뀌어도 같은 데이터를 찾기 위한 고유한 문자열이다. |
| 논리 ID | 실제 파일 경로 대신 쓰는 안정적인 자산 이름이다. 파일이 교체되거나 품질별 위치가 달라도 같은 이름으로 요청한다. |
| 카탈로그 / registry | 논리 ID와 실제 파일 위치를 연결한 목록이다. |
| Autoload | 게임 시작 때 Godot가 자동으로 한 번 만들고 모든 화면에서 접근하게 하는 공용 객체다. |
| manifest | 자산의 출처, 버전, 권리, 해시와 사용 위치를 적은 목록 파일이다. |
| 어댑터 | 한 형식의 입력이나 상태를 다른 시스템이 이해하는 형식으로 바꾸는 얇은 연결 코드다. |
| 직렬화 | 메모리의 데이터를 파일이나 네트워크로 보낼 수 있는 형태로 바꾸는 일이다. |
| ABI | Android 앱에 포함할 CPU 명령어 형식이다. 이 프로젝트는 실제 기기용 `arm64-v8a`를 기준으로 한다. |
| export | Godot 프로젝트를 Android APK처럼 설치하고 실행할 수 있는 결과물로 만드는 과정이다. |
| draw call | 한 프레임을 그리기 위해 CPU가 GPU에 보내는 그리기 요청이다. 많아지면 모바일 성능이 떨어질 수 있다. |

## 테스트와 결과 상태 용어

| 용어 | 쉬운 설명 |
| --- | --- |
| 자동 테스트 | 명령 한 번으로 기대 결과를 반복 확인하는 검사다. |
| smoke test(기본 동작 검사) | 앱이 켜지고 핵심 경로가 바로 실패하지 않는지 빠르게 확인하는 검사다. |
| 회귀 검사 | 새 변경 때문에 이미 되던 기능이 다시 깨지지 않았는지 확인하는 검사다. |
| headless | 화면을 띄우지 않고 명령줄에서 Godot나 테스트를 실행하는 방식이다. |
| `pass` | 요구한 검사가 통과했다. |
| `fix` | 구현은 유지하되 발견된 문제를 고쳐야 한다. |
| `redo` | 요구사항이나 설계부터 다시 정리해야 한다. |
| `blocked` | 필요한 승인, 장비, 권한 또는 선행 결정이 없어 진행할 수 없다. |
| 미검증 | 아직 확인하지 않았다는 뜻이다. 실패나 통과로 기록하지 않는다. |

## 코드 이름 빠른 찾기

| 이름 | 한 줄 역할 |
| --- | --- |
| `CharacterData` | 캐릭터의 기본 능력치, 기술과 확장 슬롯 원본 |
| `JobData` | 직업이 캐릭터를 어떻게 바꾸는지 담은 데이터 |
| `AccessoryData` | 장신구 효과와 조합 조건 데이터 |
| `RuntimeCombatProfile` | 위 세 데이터를 한 판용으로 합친 복사본 |
| `AttackData` | 공격 준비·적중·회복 시간과 피해·밀어내기·공격 영역 데이터 |
| `MoveSetData` | 사용할 수 있는 기술과 입력·연계 조건 목록 |
| `StageData` | 발판, 시작 위치와 링아웃 영역을 정하는 경기장 데이터 |
| `CombatIntent` | 터치, 키보드나 AI 입력을 전투 코드에 전달하는 공통 명령 |
| `ForestArenaResources` | 논리 ID를 실제 이미지·소리 파일로 찾아 주는 Godot 공용 객체 |

새 용어를 추가할 때는 가나다순보다 독자가 어떤 문서를 읽다가 찾을지를 우선한다. 설명만으로 구분하기 어려운 용어에는 짧은 실제 예를 함께 추가한다.
