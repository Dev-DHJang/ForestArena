# 무료 APK 데모 설치와 실행

데모는 같은 네트워크의 Android 두 대가 Mac 한 대의 서버에 접속하는 1대1 게임이다.
AI・연습・Solo・Team・Story 프롤로그는 기기에서 실행할 수 있다. 유료 결제는 없다.
Story는 대화・성장・보상이 없는 프롤로그다. debug APK를 직접 설치하며 스토어를 사용하지 않는다.

## 준비

- Android 10 이상, Mac과 Android 두 대를 같은 사설 네트워크에 연결한다.
- Mac에는 Godot 4.7.1, Node.js 22 이상과 npm, Python 3, Docker Compose가 필요하다.
  서버 배포 묶음에는 실행 데이터 `server.pck`와 API・DB 설정・도구가 들어 있다.
- 공유기의 기기 간 통신 차단을 끄고 인터넷 포트 전달은 만들지 않는다.
- 기존 `com.forestarena.welllbeing` debug 앱과 같은 서명을 사용하는 APK다. 다른 서명의 기존 앱을
  덮어쓸 수 없는 경우 기존 저장을 삭제하지 말고 동일 서명 APK인지 먼저 확인한다.

## 서버

배포 ZIP을 풀고 `server` 폴더에서 다음을 실행한다.

```sh
./scripts/demo-server.sh start
./scripts/demo-server.sh status
./scripts/demo-server.sh logs
./scripts/demo-server.sh stop
./scripts/demo-server.sh backup
```

처음 실행은 별도 `forest_arena_demo_postgres` 볼륨을 만들고 DB 형식을 준비한다.
기존 개발 DB는 변경하지 않는다. DB는 `127.0.0.1:55433`에서만 열린다.
API는 Mac LAN 주소의 3001, 게임 서버는 7778을 사용한다. API를 Mac에서 직접 실행해
접속자의 실제 주소를 검사한다. `stop`은 서버・API・DB를 멈추며 기록은 남긴다.
관리자 웹과 인터넷 자동 매칭은 실행하지 않는다.

자동 주소 탐지가 안 되면 Mac의 실제 IPv4・네트워크 범위를 지정한다. 아래는 예시이며 실제 주소로 바꾼다.

```sh
FOREST_ARENA_DEMO_IP=192.168.1.10 FOREST_ARENA_ALLOWED_CIDR=192.168.1.0/24 ./scripts/demo-server.sh start
```

`database/.env.demo`에는 비밀번호・서버 인증 정보가 있다. 전달하거나 Git에 넣지 않는다.
전체 폴더를 다시 배포할 때 이 파일과 DB 백업을 포함하지 않는다. 새 환경이면 게스트 기록도 별도다.
서버 재시작 중 진행 중인 경기는 복원하지 않는다. 기존 게스트는 같은 DB로 다시 접속해 새 방을 연다.

## 서버 업데이트

기존 서버를 `stop`한 뒤 새 묶음의 `server` 내용을 기존 폴더에 덮어쓴다.
`database/.env.demo`와 DB 볼륨을 보존한다. 다른 폴더에 풀었다면 이전 `.env.demo`를
새 `server/database`에 로컬로 복사하고 파일 권한을 `chmod 600 database/.env.demo`로 맞춘다.
이 파일을 배포 ZIP에 포함하지 않는다. 기존 DB가 있는데 인증 파일이 없으면 시작 도구가
중지하며, 기존 게스트를 유지하려면 원래 파일을 복원해야 한다.

## 호스트 방화벽

앱의 CIDR 검사와 함께 Mac 호스트 방화벽을 적용한다. 다음 도구는 검토 가능한 PF 규칙만 출력한다.

```sh
python3 tools/forest_arena/demo_firewall.py en0 192.168.1.10 192.168.1.0/24 > /tmp/forest-arena-demo.pf
sudo pfctl -a com.apple/forest-arena-demo -f /tmp/forest-arena-demo.pf
sudo pfctl -E
```

인터페이스・주소・범위는 실제 연결로 바꾼다. Mac 기본 PF 설정의 `com.apple/*` anchor가
활성화돼 있어야 한다. 기존 방화벽 전체를 덮어쓰지 않는다. PF 활성화 시 출력된 참조 토큰을 보관한다.
종료 후 이 규칙만 지우려면 `sudo pfctl -a com.apple/forest-arena-demo -F rules`를 사용한다.
데모를 위해 활성화한 참조는 `sudo pfctl -X <참조-토큰>`으로 해제하며 전역 방화벽을 끄지 않는다.
실제 적용과 허용 밖 접속 차단 결과를 기기 확인 기록에 남긴다.

## APK와 게스트

1. `ForestArena-demo.apk`를 두 기기에 전달하고 파일 관리자로 연다. 해당 설치 앱에 필요한
   APK 설치 허용을 설정해 설치한다. 같은 파일・버전을 사용한다.
2. 첫 캐릭터 선택 후 다른 무료 캐릭터・장신구를 상점에서 받을 수 있다.
3. 첫 기기에서 LAN → 방 만들기에 서버가 출력한 `FAH2` 연결 코드를 붙여넣는다.
4. 게스트가 처음 생성되면 닉네임을 설정한다. 한글・영문・숫자・밑줄 2~12자만 사용하며
   영문 대소문자가 다른 같은 이름도 중복으로 거부한다.
5. 닉네임을 저장하고 `이 닉네임으로 계속`을 누른다. 표시된 `FA2` 초대 코드를 두 번째 기기에 전달한다.
6. 두 번째 기기는 LAN → 초대 코드로 참가 → 게스트 접속・닉네임 설정 → 계속으로 접속한다.
7. 같은 결과를 확인한 뒤 양쪽에서 20초 안에 재대전을 요청하면 새 경기를 시작한다.

기기에는 별도 데모 게스트 인증 파일이 저장되고 서버에는 ID와 닉네임이 저장된다.
무료 보유・선택・설정은 기기 저장을 유지하며 DB와 자동 동기화하지 않는다.
닉네임은 방 참가 전에 변경할 수 있고 경기에서는 이름을 고정한다.
앱과 서버를 다시 실행해도 기존 세션을 복원한다. 앱 삭제・재설치, 토큰 만료 또는 인증 파일
유실 때 이전 게스트 자동 복원은 보장하지 않는다. 새 게스트 시작은 사용자가 명시적으로 선택한다.
새 게스트가 되어도 다른 게스트의 기존 이름을 사용할 수 없다.

## 연결 실패와 기록

- 처음 연결・API 요청・방 참가 응답은 8초를 기다린 뒤 취소・다시 시도할 수 있다.
- 경기 중 연결이 끊기면 60초 동안 같은 게스트로 복귀할 수 있다. 기한이 지나면 이탈 패배다.
- v1 APK・코드는 v2 서버에 연결하지 않는다. 같은 데모 APK로 업데이트한다.
- API・게임 서버가 멈추면 서버를 다시 실행하고 앱에서 새 방으로 접속한다.
- 문의 때 APK 버전・기기 모델・실패 시각・화면 안내를 전달한다. 인증 파일・토큰은 보내지 않는다.
- 서버 로그는 로컬 `.godot/demo-server`에 있다. 기본 개발 로그는 현장 문제 확인용이며
  개인정보・토큰 전체를 출력하지 않는다. 운영 종료 시 로그를 지울 수 있고 게스트 DB는 보존한다.

## 배포 전 확인

APK 최초 설치・동일 서명 업데이트・기기 저장 보존, 두 실제 Android의 게스트부터 경기・결과・재대전,
Wi-Fi 단절・복귀・중단・재개, 한글 키보드・작은 화면・소리・진동과 반복 플레이를 확인한다.
자동 검사・에뮬레이터와 물리 기기 결과를 구분하며 미실행 항목은 완료로 표시하지 않는다.
