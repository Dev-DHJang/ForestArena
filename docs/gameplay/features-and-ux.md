# 03. 기능과 UX

UX는 사용자가 조작을 배우고 목표를 달성하는 전체 경험이다. 화면 관련 용어는 [용어 가이드](../GLOSSARY.md#화면과-그래픽-용어)를 참고한다.

## 화면과 입력

- Android 가로 화면의 왼쪽 이동 영역과 오른쪽 행동 버튼을 기본 방향으로 삼는다.
- Phase 1 입력 UX는 왼쪽에 상·하·좌·우 방향패드, 오른쪽에 약·강·특수와 별도 점프 버튼을 두며 구현·검증됐다. 이 배치는 후속 범위 승인 없이 바꾸지 않는다.
- 미래 행동 버튼은 현재 대시 버튼을 막기·회피에도 쓰도록 확장한다. 궁극기와 막기 중 잡기를 입력하는 `grab_support` 보조 버튼은 Phase 3 이후 결정이 승인된 뒤에만 추가한다. 지금 화면에 동작하지 않는 버튼을 미리 표시하지 않는다.
- 터치 영역은 손가락으로 안정적으로 누를 수 있어야 하며 운영체제 제스처, 노치와 안전 영역(safe area)을 침범하지 않는다.
- 멀티터치 이동·공격, 버튼 경계 이탈, 포커스 손실과 복귀 뒤 입력 고착이 없어야 한다.
- 구체 터치 크기, 배치 프리셋과 사용자 조정 범위는 실제 기기 검증 뒤 ADR로 확정한다.

## 프로토타입 흐름

    앱 실행 → 연습 또는 AI 대전 → 캐릭터·직업·장신구·경기장 선택
    → 전투 → 링아웃/복귀 또는 결과 → 재시도/선택 화면

승인된 미래 모드는 Story, Solo, Team, AI, Practice다. 전체 참가자는 최대 8명이며 Team은 팀당 1~4명, 전체 최대 8명이다. Phase 2 종료 시점에는 이 정식 선택 화면 흐름을 구현하지 않으며 성장·획득·인벤토리 저장을 선택 화면과 혼동하지 않는다.

## 비전투 화면 설계 계약

- Penpot 기준 프레임은 1920×1080 가로 화면이고 Godot 런타임 논리 해상도 1280×720은 유지한다.
- 고정된 24개 `SCR_*` 화면 이름과 `IMG/*` 이미지 자리는 [비전투 UI 데이터](../ui/non-combat-ui-v01.json)를 프로그램이 읽는 최종 기준으로 사용한다.
- 밝은 비픽셀 판타지 숲을 기본 시각 방향으로 삼고 `SCR_01_Splash`에는 캐릭터를 배치하지 않는다.
- 장신구 UI는 기능 범주와 궁합을 표현하되 희귀도·등급으로 오인될 별·색상 테두리·티어 라벨을 사용하지 않는다.
- 빠진 이미지는 정확한 `IMG/...` 이름의 임시 이미지(플레이스홀더)로 남기고 Penpot의 `MISSING ASSETS` 목록에서 보이게 기록한다.
- 24개 화면의 Godot 구현, 이미지 생성과 외부 Penpot 파일 편집은 이 설계 기반과 별도의 후속 작업이다.

## 카메라와 전투 정보(HUD)

- 카메라는 두 파이터와 위험 경계를 담고 최소·최대 줌 및 스무딩을 적용한다.
- 최대 줌아웃에서도 동물 종, 직업, 장신구와 공격 포즈가 읽혀야 한다.
- HUD는 전투 중 현재/최대 HP와 남은 stock을 보여 주지만 그 값이나 승패를 직접 계산하지 않는다.
- Phase 3 이후 궁극기 게이지와 막기 내구도도 전투 코드가 계산한 값을 표시만 한다. 터치 UI가 충전, 소모나 막기 실패를 계산하지 않는다.
- 개발 오버레이는 상태, 공격 단계와 성능 정보를 릴리스 UI와 분리한다.

## Android 생명주기

- 중단·백그라운드 진입 시 오프라인 전투를 일시정지하고 입력과 오디오를 정리한다.
- 복귀 시 중복 진행 없이 명시적 재개 흐름을 제공한다.
- 앱이 입력 초점을 잃으면 눌린 입력을 모두 해제하고 화면 안전 영역을 다시 계산한다.
- 초기 Phase에는 저장되지 않은 매치 복원을 약속하지 않는다.

## 접근성

- 위험, 피격과 상태를 색상 하나에만 의존하지 않는다.
- 화면 흔들림, 번쩍임, hit-stop과 진동의 조절 가능성을 설계한다.
- 텍스트, 아이콘과 핵심 조작이 작은 화면과 손가락에 가려지지 않게 한다.
