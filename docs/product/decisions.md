# Forest Arena 결정 기록

중요한 제품·기술 결정을 이유와 함께 남기는 기록이다. 아직 정하지 않은 규칙도 여기에서 ADR(결정 기록)로 관리하며, 사용자 승인 없는 제안은 구현 기준이 아니다. 상태와 항목의 뜻은 [용어 가이드](../GLOSSARY.md#프로젝트-진행-용어)를 참고한다.

## 상태

- proposed: 검토 중이며 교체 가능한 프로토타입 선택만 허용.
- accepted: 사용자가 승인해 번호순 제품 문서보다 우선하는 결정.
- superseded: 새 ADR로 대체된 결정.
- rejected: 구현 근거로 사용할 수 없는 결정.

## ADR-001: Phase 1 승리 방식과 링아웃 흐름 기준안

- 상태: superseded by ADR-022
- 날짜: 2026-09-06
- 적용 Phase: 1
- 배경: 링아웃·복귀·결과 회귀를 구현하려면 최소 경기 종료 규칙이 필요하다.
- 결정: 각 파이터는 3 stock으로 시작하고 링아웃 때 1 stock을 잃은 뒤 짧은 무적과 함께 스폰으로 복귀한다. 0 stock이면 패배하며 Phase 1에는 제한 시간을 두지 않는다.
- 대안: 단판 링아웃, 체력 0 패배, 제한 시간과 동점 판정.
- 영향: stock HUD와 결과 이벤트가 필요하지만 영속 성장·보상은 만들지 않는다.
- 검증: 연속 링아웃, 동시 최종 링아웃과 복귀 중 재링아웃을 자동 검사한다.
- 대체/롤백: MatchRules 데이터로 수치와 방식이 교체 가능해야 한다.
- 승인 근거: 2026-09-06 사용자 응답에서 제안 규칙 전체 승인.

## ADR-002: Phase 1 피해·넉백·경직 기준안

- 상태: superseded by ADR-022
- 날짜: 2026-09-06
- 적용 Phase: 1
- 배경: 공격 결과가 임시 수치라도 한 곳에서 결정되어야 전투 회귀를 만들 수 있다.
- 결정: 누적 피해율 방식으로 시작한다. 적중 시 피해율을 더하고 `base_knockback + damage_after_hit × growth`를 무게 보정해 넉백 속도를 구하며, 경직은 넉백 속도에 비례하되 상·하한을 둔다. 모든 계수는 CombatRules 데이터에 둔다.
- 대안: 고정 HP, 공격별 고정 넉백, 곡선 기반 공식.
- 영향: 높은 피해율일수록 링아웃 가능성이 커지고 정확한 계수는 플레이테스트 조정 대상이다.
- 검증: 동일 초기 상태·입력·tick의 동일 결과, 무게 순서, 피해 증가에 따른 단조 증가와 상·하한을 자동 검사한다.
- 대체/롤백: CombatMath 구현을 교체하고 AttackData·UI 이벤트 계약은 유지한다.
- 승인 근거: 2026-09-06 사용자 응답에서 누적 피해율 넉백 승인.

## ADR-003: Phase 1 공중 점프 기준안

- 상태: accepted
- 날짜: 2026-09-06
- 적용 Phase: 1
- 배경: 점프 상태와 입력 회귀에 공중 점프 횟수 및 회복 시점이 필요하다.
- 결정: 기본 파이터는 지상 점프 후 공중 점프 1회를 가지며 권위 플랫폼에 착지하면 회복한다. 피격·넉백은 남은 횟수를 회복하지 않는다.
- 대안: 공중 점프 없음, 종/직업별 기본 횟수, 피격 후 회복.
- 영향: 기본 이동 상태에 남은 공중 점프 카운터가 추가되며 이후 CharacterStats가 횟수를 변경할 수 있다.
- 검증: 지상→공중 점프, 초과 입력 무시, 착지 회복과 피격 비회복을 자동 검사한다.
- 대체/롤백: 기본 횟수를 데이터로 바꾸고 의미 입력 ID는 유지한다.
- 승인 근거: 2026-09-06 사용자 응답에서 공중 점프 1회 승인.

## ADR-006: Phase 0 터치 입력 기준안

- 상태: proposed
- 날짜: 2026-09-06
- 적용 Phase: 0/1
- 배경: 멀티터치와 포커스 손실 회귀를 검증하려면 교체 가능한 초기 배치가 필요하다.
- 결정: Phase 0에서는 화면 하단 42%만 입력에 쓰고 왼쪽에 이동, 오른쪽에 행동을 둔다. 좌우 6.5%는 임시 safe edge로 입력에서 제외하며 영역 이탈은 이전 의미 입력을 해제한다.
- 대안: 가상 스틱, 자유 배치, 고정 이미지 버튼.
- 영향: 현재 비율은 플레이테스트용이며 safe area·최소 물리 크기·사용자 조정 범위를 확정하지 않는다.
- 검증: 에뮬레이터에서 다중 포인터와 이탈을 검사하고 실제 Android 기기에서 가림·도달성과 OS 제스처 충돌을 후속 확인한다.
- 대체/롤백: 입력 영역 테이블만 바꾸고 의미 입력 ID는 유지한다.

## ADR-007: Phase 0 성능 측정 기준안

- 상태: proposed
- 날짜: 2026-09-06
- 적용 Phase: 0
- 배경: 예산 확정 전에 재현 가능한 기준 장면과 측정 항목이 필요하다.
- 결정: 1280×720 논리 해상도, GL Compatibility, 60 FPS 후보를 시작점으로 삼고 프레임 시간·메모리·draw call을 기록한다.
- 대안: Forward+ 또는 Mobile renderer, 30 FPS 기준, 다른 논리 해상도.
- 영향: 목표 수치와 기준 기기는 아직 승인되지 않았으며 실제 기기 측정 뒤 조정한다.
- 검증: 기준 기기에서 10분 실행 후 프레임 시간 분포, 메모리와 발열 저하를 기록한다.
- 대체/롤백: ProjectSettings 렌더러와 논리 해상도를 변경하고 장면 계약은 유지한다.

## ADR-008: 서버 권위 온라인 네트워크 모델

- 상태: accepted
- 날짜: 2026-10-03
- 적용 Phase: Phase 7 기반과 ADR-026 예외
- 배경: 클라이언트가 전투 결과를 정하지 않으면서 현재 60Hz 결정론적 전투를 온라인에서 재사용할 기준이 필요하다.
- 결정: Godot headless 서버가 60Hz로 모든 전투 결과를 정하고 클라이언트는 버전·순번이 있는 의미 입력만 보낸다. 서버는 20Hz 상태를 보내며 첫 로컬 버전은 보간만 사용하고 예측·되감기 보정은 이연한다. 연결 해제 시 fighter 입력을 해제하고 경기는 계속되며 60초 안에 같은 slot으로 복귀할 수 있다. 넘기면 이탈 패배다.
- 대안: 클라이언트 권위, 입력 lockstep, 첫 버전부터 prediction/reconciliation 구현.
- 영향: 버전 있는 HTTP·WebSocket 계약, match ticket, reconnect token, 서버 전용 결과 저장과 Android 네트워크 전환 검사가 필요하다.
- 검증: 중복·역순 입력, 잘못된 버전·ticket, 두 클라이언트 결과 일치, 연결 해제·복귀·만료와 결과 중복 저장을 자동 검사한다.
- 대체/롤백: protocol v1 소비자를 함께 제거하고 기존 오프라인 전투를 기본 흐름으로 유지한다.
- 승인 근거: 2026-10-03 사용자가 서버 권위 snapshot, 60초 재접속과 로컬 온라인 세로 흐름 계획을 명시 승인.

## ADR-011: Android 애플리케이션 식별자·지원 ABI 기준안

- 상태: accepted
- 날짜: 2026-09-06
- 적용 Phase: 0
- 배경: debug APK 생성에는 유효한 package ID와 ABI 선택이 필요하다.
- 결정: package ID는 `com.foresttales.welllbeing`, ABI는 실제 기기용 arm64-v8a와 로컬 에뮬레이터용 x86_64를 사용한다. 최소 Android 버전은 제품 기준인 Android 10이다. 향후 물리 기기 기준대상은 Galaxy S23 Ultra이며 당분간 에뮬레이터를 사용한다.
- 대안: 사용자가 소유한 역도메인 package ID, arm64-v8a 단일 ABI.
- 영향: 스토어 등록 또는 외부 배포 전에 소유권 있는 package ID로 확정해야 한다.
- 검증: debug export, 에뮬레이터 설치·실행, 최종 기준 기기의 arm64 설치를 확인한다.
- 대체/롤백: 공개 배포 전 export preset의 식별자와 ABI를 교체한다.
- 승인 근거: 2026-09-06 사용자 응답에서 package ID 철자와 Galaxy S23 Ultra 기준대상, 당분간 에뮬레이터 사용을 지정.
- 부분 상태: package ID `com.foresttales.welllbeing` 결정만 ADR-014로 superseded되었다. ABI, 최소 Android 버전, 기준 기기와 에뮬레이터 사용 결정은 accepted 상태를 유지한다.

## ADR-012: 기본 공격 입력·짧은 분기 연계 기준안

- 상태: accepted
- 날짜: 2026-09-11
- 적용 Phase: 1
- 배경: 방향 공격과 캐릭터별 기본 연계를 구현하려면 버튼을 누른 순서, 입력 예약, 공중 추격의 공통 경계가 필요하다.
- 결정: 왼손 4방향과 오른손 약·강·특수, 별도 점프를 기준으로 한다. 약 반복은 자현 3단·묘령 4단·나비 2단이며 다음 입력 하나만 예약한다. 피니시 전 적중은 다음 약·방향 강·특수로 분기할 수 있고, 강·특수 분기와 피니시는 원 연계를 끝낸다. 위 강 적중 후만 점프 추격을 허용하며 체공 중 공중 공격은 최대 두 번이다. 발동 방향·보는 쪽은 고정하고 자동 추적·자동 뒤돌기를 하지 않는다.
- 대안: 단일 공격 버튼, 자동 완주 연계, 모든 기술에 확정 취소, 방향 자동 보정.
- 영향: Phase 1에는 ComboController와 방향·edge가 있는 CombatIntent가 필요하다. 정확한 프레임·피해·hitbox는 AttackData로 분리한다.
- 검증: 한 입력 예약, 3/4/2단 연계, 피니시 취소 불가, 위 강 적중 전후의 점프 추격, 체공 공격 2회 한도와 방향 고정을 자동 검사한다.
- 대체/롤백: MoveSetData의 분기 테이블을 교체하되 `attack_light`, `attack_heavy`, `attack_special` ID는 유지한다.
- 승인 근거: 2026-09-11 사용자가 Phase 1 코어 전투 수직 슬라이스 계획에서 이 입력·연계 기준의 구현을 명시 승인.

## ADR-016: 동시 최종 링아웃 서든데스

- 상태: superseded by ADR-022
- 날짜: 2026-09-11
- 적용 Phase: 1
- 배경: 양쪽 마지막 stock이 같은 고정 tick에 소진될 때 판정 순서가 승패를 정하면 결정론과 공정성이 깨진다.
- 결정: 동시 최종 링아웃이면 양쪽을 피해율 0%·1 stock으로 되돌리고 원래 스폰에 45 tick 뒤 복귀시킨다. 이후에도 동시 탈락하면 승자가 생길 때까지 같은 서든데스를 반복한다. 비동시 최종 탈락만 승패를 확정한다.
- 대안: 무승부, 피해율 비교, 안정 ID 순서로 승자 결정.
- 영향: MatchController가 같은 tick의 링아웃을 묶어 처리하며 HUD는 서든데스 상태를 읽기 전용으로 표시한다.
- 검증: 동시 최종 탈락과 반복 동시 탈락, 비동시 최종 탈락을 고정 tick 자동 검사한다.
- 대체/롤백: 경기 결과 규칙을 바꿀 경우 새 ADR로 대체하고 MatchController와 HUD 계약을 함께 갱신한다.
- 승인 근거: 2026-09-11 사용자가 Phase 1 코어 전투 수직 슬라이스 계획에서 반복 서든데스를 명시 승인.

## ADR-013: 방어·회피·잡기·차지·궁극기 자원 기준안

- 상태: superseded by ADR-023
- 날짜: 2026-09-08
- 적용 Phase: 3 이후
- 배경: 가드·회피·잡기와 큰 보상 기술은 초반 기본 전투와 별도의 대응·자원 검증이 필요하다.
- 결정: 행동 버튼은 중립 유지 가드, 좌우 누름 회피 스텝, 좌우 유지 시 회피 뒤 대시, 공중 1회 회피로 확장한다. 가드 해제의 짧은 유예에 잡기 보조 입력을 제공하며 일반 공격은 가드 가능·잡기는 가드 대응·잡기 실패는 큰 빈틈으로 둔다. 초기 규칙에는 상하단 가드·정밀 패리가 없다. 지상 강 유지 차지는 방향을 고정하고 공중 차지는 금지한다. 특수기는 지상·공중 쿨다운을 공유하고 위 특수 복귀는 체공 중 한 번이다. 궁극기는 유효 피해로만 충전, stock당 한 번, stock 상실 때 초기화, 빗나가도 소모, 준비 중 대응 가능, 일반 콤보 확정 취소 불가로 둔다.
- 대안: 영구 가드, 무제한 회피·복귀, 헛공격 게이지 충전, 궁극기 콤보 확정 취소.
- 영향: Phase 3 이후 가드 내구·가드 붕괴, 회피·복귀 카운터, 특수 쿨다운과 궁극기 게이지가 권위 전투 데이터·HUD 이벤트에 추가된다.
- 검증: 가드 내구·붕괴, 회피 재입력, 공중 회피·위 특수 한도, 잡기 실패 회복, 헛공격 비충전, stock 초기화와 궁극기 빗나감 소모를 자동·기기 회귀로 검사한다.
- 대체/롤백: 자원·행동 상태를 MatchRules와 MoveSetData로 교체하며 기본 세 공격 ID와 Phase 1 판정은 보존한다.
- 대체 대상: ADR-004와 ADR-005의 미상세 제안을 이 기준안으로 대체한다.

## ADR-022: HP·stock·링아웃·사망·부활·무승부

- 상태: accepted
- 날짜: 2026-09-17
- 적용 Phase: 전투 개선 묶음 B 이후
- 배경: 누적 피해율은 체력의 의미를 흐리고 같은 공격의 결과를 누적값에 묶는다.
- 결정: 파이터는 최대 HP와 stock을 가진다. HP 0 또는 링아웃은 stock 1개를 잃게 하며, stock이 남으면 45 tick 뒤 최대 HP와 60 tick 복귀 무적으로 돌아온다. 마지막 stock은 `DEAD` 상태이며 같은 tick의 양쪽 마지막 stock 소진은 `DRAW`다. 부활은 `OnDeath` 효과만 제공할 수 있고 한 경기 한 번, 1 stock과 효과 데이터의 HP로 같은 45 tick 복귀 흐름을 탄다.
- 대안: 누적 피해율, 동시 탈락 서든데스, 기본 부활.
- 영향: 피해율 HUD·수식·문서가 제거되고 RuntimeCombatState와 HP HUD가 필요하다.
- 검증: HP 0, 링아웃, 복귀 HP·무적, 최종 사망, 동시 무승부, 1회 부활을 자동 검사한다.
- 대체/롤백: ADR-001, ADR-002, ADR-016을 대체한다. 수치 변경은 CombatRules와 효과 데이터에서 한다.
- 승인 근거: 2026-09-17 사용자가 전투 시스템 단계별 확장 계획 전체를 승인.

## ADR-023: 아래 입력 방어와 Phase 3 행동

- 상태: accepted
- 날짜: 2026-09-17
- 적용 Phase: 전투 개선 묶음 C 이후
- 배경: 지상 방어와 방향 공격·통과 발판은 동일한 아래 입력을 공유한다.
- 결정: 지상에서 아래만 유지하면 방어한다. 같은 tick의 우선순위는 `아래+점프 발판 통과 > 아래+공격 방향 기술 > 아래 단독 방어`다. 기존 대시는 호환 입력으로 유지하고 행동 버튼 좌우는 회피와 회피 뒤 대시를 맡는다. 중립 행동은 방어가 아니다. 가드 내구·붕괴, 지상 강 차지, 특수기 공유 쿨다운, 궁극기 게이지는 전투 데이터와 HUD가 소유한다. 잡기 기술은 제공하지 않는다. 정밀 방어는 결과 타입만 예약하며 입력 창·보상은 두지 않는다.
- 대안: 중립 유지 방어, 아래 방향 방어 없음, 정밀 방어 즉시 구현.
- 영향: CommandResolver가 이벤트 정렬 대신 tick 입력을 판정한다.
- 검증: 아래 단독, 아래+공격, 아래+점프, 일반 바닥, 멀티터치·이탈·포커스 손실을 자동·기기 검사한다.
- 대체/롤백: ADR-013 및 그 ADR가 대체한 ADR-004·005를 대체한다.
- 승인 근거: 2026-09-17 사용자 전체 계획 승인.

## ADR-024: 로컬 플레이어 중심 전투 카메라와 화면 밖 상대 표시

- 상태: accepted
- 날짜: 2026-10-03
- 적용 Phase: 로컬 AI 대전
- 배경: 두 파이터를 항상 한 화면에 담는 카메라는 캐릭터를 작게 보여 주며, 플레이어를 가까이 보여 주면 화면 밖 상대의 위치를 별도로 알려야 한다.
- 결정: 1280×720 논리 화면에서 전투 카메라는 로컬 플레이어를 목표로 따라가고 줌 1.25를 유지한다. 이는 현재 네 캐릭터의 평균 가로 실루엣 약 102 world px를 기준으로 가로에 약 10개가 들어오는 크기다. 상대의 실제 스프라이트 사각형이 화면과 전혀 겹치지 않을 때만 HUD 아래·터치 조작 위의 안전 영역 가장자리에 이름과 거리 없는 방향 화살표를 표시한다. 경기 종료 시 화살표를 숨긴다.
- 대안: 두 파이터 중간점을 따라가는 가변 줌, 카메라를 경기장 경계에 고정, 미니맵 또는 거리 숫자 표시.
- 영향: 경기장 전체는 한 화면에 나오지 않으며 배경과 투명 지형 그림은 카메라 이동 범위를 덮는다. 카메라·화살표·지형 그림은 표현만 맡고 고정 tick 전투 결과를 바꾸지 않는다.
- 검증: 상대 이동이 카메라 목표를 바꾸지 않는지, 줌 1.25, 상대의 부분 노출·완전 이탈, 네 방향 화살표 안전 영역, 경기 종료 숨김과 전투 snapshot 불변을 자동 검사한다. Android 에뮬레이터에서 실제 화면을 확인하고 실기기는 별도로 기록한다.
- 대체/롤백: `CombatCamera`, `OffscreenOpponentIndicator`와 관련 장면 노드를 함께 되돌리며 발판 충돌·링아웃 경계·전투 규칙은 유지한다.
- 승인 근거: 2026-10-03 사용자가 지형 이미지 생성, 약 10개 캐릭터 폭의 줌, 플레이어 중심 추적과 화면 밖 상대 방향 화살표 구현을 요청하고 자동 시안 선정·등록을 승인했다.

## ADR-018: 14개 역할 하네스 통합과 자동 버전 관리

- 상태: accepted
- 날짜: 2026-09-11
- 적용 Phase: 2 이후
- 배경: Godot UI·캐릭터 모션·버전 관리 역할이 각각 UI·2D 애니메이션·오케스트레이션과 분리되어 책임 경계와 증적 규칙이 중복됐다. 활성 문서에는 Phase 2 상태와 맞지 않는 Phase 0 표현도 남아 있었다.
- 결정: 활성 역할은 14개로 운영한다. `forest-arena-ui`가 Godot 비전투 UI와 `ForestArenaResources` 소비를, `forest-arena-2d-animation`이 승인 캐릭터의 idle·jump·run과 모션별 승인 게이트를, `forest-arena-orchestrator`가 브랜치·관련 commit·push·PR·QA 뒤 `develop` 병합·롤백 증적을 소유한다. 팀 명세의 역할 표가 단일 원본이며 검증기는 그 표에서 실제 스킬 목록을 동적으로 비교한다. 기본 증적은 `00_request.md`와 `04_closeout.md`이고 계약·인수인계·독립 QA 파일은 필요할 때만 추가한다.
- 버전 관리 범위: 사용자의 구현·수정·완료 요청은 일반 작업 브랜치, commit, push, PR과 `develop` 병합 권한을 포함한다. `main` 승격, release/hotfix, 강제 push, 이력 재작성, 원격 브랜치 삭제, 계정·권한·비밀정보 변경은 제외하며 플랫폼 보안 확인은 우회하지 않는다.
- 영향: ADR-017의 활성 17개 역할 운영 결정을 이 ADR로 대체한다. ADR-014와 ADR-017의 당시 수치·승인 근거는 감사 기록으로 보존한다. Godot Autoload·337개 논리 리소스·22개 품질 변형, 외형 승인 경계와 Phase 7 온라인 게이트는 유지한다.
- 검증: `./scripts/verify-harness.sh`, `./scripts/verify.sh`, Godot 리소스 검증, 활성 문서의 제거 역할·고정 역할 수·현재 Phase 0 표현 검사와 `git diff --check`를 실행한다.
- 대체/롤백: 역할을 다시 분리하려면 새 ADR에서 소유권, 스킬, 팀 명세와 동적 검증을 함께 변경한다.
- 승인 근거: 2026-09-11 사용자가 14개 역할 통합, 활성 문서 한국어화, 적응형 증적과 일반 원격 통합 자동 범위를 명시 승인.

## ADR-019: 기억 전장과 삼국 공동 과오 서사 기준안

- 상태: superseded by ADR-020
- 날짜: 2026-09-12
- 적용 Phase: 6 이후
- 배경: Story와 신규 캐릭터·지역 콘텐츠가 같은 세계 규칙을 사용하려면 아레나 전투의 세계 내 의미, 현재 국가 관계와 중심 대서사의 원인이 필요하다. 현재 Phase 2 범위를 Story 구현으로 확장해서는 안 된다.
- 결정: 세계수의 기억매듭은 실제 사건의 제한된 시점을 기억 전장으로 재현한다. 기억 전장 전투는 투영체와 stock 복귀를 사용하는 비살상 전투이며, 아레나 밖 전쟁은 치명적이다. 승자는 봉인된 기억을 열 수 있지만 세계수는 책임·영토·정당성을 판결하지 않는다. 현재 쥐·토끼 국가는 불완전한 동맹이고 고양이 국가는 적국이다. 과거 접경 소멸은 쥐 국가의 보급 뿌리 절단, 토끼 국가의 생명 흐름 전환, 고양이 국가의 기록 봉인이 연쇄된 공동 과오다.
- 대안: 아레나를 단순 대회로 두기, 승자의 기억을 객관적 판결로 취급하기, 숨은 단일 세력이나 세계수의 오작동을 전쟁의 유일한 원인으로 두기, 한 종족을 절대 악역으로 두기.
- 영향: `docs/product/world-and-story.md`가 세계관·중심 대서사의 단일 원본이 된다. 직업은 지역 전투 전통, 장신구는 기억 닻의 서사 의미를 가질 수 있지만 기존 Resource·전투 판정·획득 정책은 변경하지 않는다. Story 모드의 챕터·보상·성장·경제·저장은 별도 Phase 승인 전 구현하지 않는다.
- 검증: 세 국가가 정당한 우려와 책임을 함께 갖는지, 기억 공개와 판결이 구분되는지, 아레나와 현실 전쟁의 생사 경계가 명확한지, 신규 지역이 공동 과오의 원인을 소급 변경하지 않고 확장 가능한지 서사 회귀로 확인한다. 기존 자동 검증과 문서 diff 검사를 통과해야 한다.
- 대체/롤백: 정사 검토에서 기각되면 `docs/product/world-and-story.md`의 설정을 구현 근거로 사용하지 않고 제품 비전의 링크와 서사 문서 지도 항목을 제거한다. 런타임·Resource·전투 계약에는 롤백할 변경이 없다.

## ADR-020: 베르디아·검은 밤·기록물 중심 서사 기준

- 상태: accepted
- 날짜: 2026-09-13
- 적용 Phase: 6 이후
- 배경: 첨부된 `forest_arena_story_final_v2.md`는 세계수 기억 전장과 삼국 공동 과오 제안보다 구체적인 세계, 지역, 인물과 중심 시놉시스를 제공한다. Story 모드와 신규 캐릭터 구현 전에 하나의 서사 기준으로 반영해야 한다.
- 결정: 세계는 대수림 베르디아이며, 중심 과거 사건은 약 30년 전 중립 도시 로엔을 무너뜨린 검은 밤이다. 서굴·고목숲·백평원·안개늪·은빛호수는 종족과 완전히 같지 않은 지역 세력이다. 기록회·기록자·기록고·기록인장은 과거 자료를 보존하고 접근하는 장치이며, 자료는 자동으로 사건의 정답이나 책임을 판결하지 않는다. 자현과 나비는 적대·경쟁·제한적 신뢰 관계이고, 묘령은 백평원의 독립 조사자다. 유란·오현·백하·베른은 미래 서사 후보로만 둔다.
- 대안: ADR-019의 세계수 기억 전장 설정을 유지하기, 종족과 국가를 항상 같게 두기, 검은 밤의 단일 정답이나 비밀 배후를 지금 확정하기, 신규 인물을 즉시 플레이 가능 캐릭터로 등록하기.
- 영향: `docs/product/world-and-story.md`가 베르디아와 첫 기록인장 시놉시스의 최종 기준이 된다. 장신구는 등급 없는 전투 맞춤 요소이며 모든 캐릭터가 사용할 수 있다. 각 캐릭터의 두 개 첫 전직과 이후 세 번째 선택지는 미래 제품 목표다. 현재 Resource, 전투 판정, 저장 형식, 기존 세 캐릭터의 외형·공격 데이터와 신규 인물의 플레이 가능 상태는 바꾸지 않는다.
- 검증: 묘령이 초기 동맹이 아닌 백평원의 독립 조사자로 쓰였는지, 종족과 지역을 동일시하거나 선악을 고정하지 않는지, 기록인장이 접근 권한일 뿐 판결 장치가 아닌지, 검은 밤의 단일 정답을 확정하지 않는지, 미래 인물·전직·장신구를 현재 구현으로 쓰지 않는지 확인한다. 문서 검사와 전체 기본 검사를 통과해야 한다.
- 대체/롤백: 이후 세계관 결정이 이 기준을 바꾸면 새 ADR로 ADR-020을 대체하고 `docs/product/world-and-story.md`, 제품 비전, 전투 규칙과 용어 가이드를 함께 갱신한다. 이번 결정은 문서 규칙만 바꾸므로 런타임 데이터 롤백은 필요 없다.
- 승인 근거: 2026-09-13 사용자가 `forest_arena_story_final_v2.md`를 “확정 정리본”으로 제공하고 프로젝트 반영을 명시 요청했다.

## ADR-025: 개발계 PostgreSQL 기반

- 상태: accepted
- 날짜: 2026-09-17
- 적용 Phase: 2 이후 개발 도구
- 배경: 운영계·검증계·개발계를 나누어 운용할 준비가 필요하지만, 현재 Phase 2에서는 게임 저장·계정·클라우드 백엔드와 온라인 기능을 구현할 수 없다.
- 결정: 개발계에서만 무료 PostgreSQL 18.6 컨테이너를 로컬 호스트에 열고, 번호와 SHA-256을 기록하는 마이그레이션, 백업, 복원과 확인 인자가 있는 초기화 도구를 사용한다. 개발계·검증계·운영계는 나중에 서로 다른 PostgreSQL 인스턴스·계정·비밀번호를 사용한다. 게임 코드는 이 DB에 직접 연결하지 않는다.
- 대안: 로컬 파일 DB, 무료 클라우드 DB, 한 PostgreSQL 서버에서 환경별 DB 이름만 분리.
- 영향: `infra` 스키마는 마이그레이션과 개발계 표식을, `app` 스키마는 ADR-026의 로컬 guest player·refresh token hash·match result와 ADR-029의 개발용 프로필을 담는다. 성장·재화·정식 계정·검증계·운영계 배포는 포함하지 않는다.
- 검증: 개발계 컨테이너 healthcheck, 마이그레이션 재실행, 적용 파일 변경 거부, 앱 계정의 DDL 거부, 백업·복원, 확인 인자 없는 초기화 거부와 전체 기본 검사를 실행한다.
- 대체/롤백: DB 도구를 제거할 때 `database/`, 관련 스크립트·문서·작업 기록을 함께 제거한다. 개발계 볼륨 삭제 전에는 `backup`으로 백업 파일을 만든다.
- 승인 근거: 2026-09-17 사용자가 무료 DB로 개발계만 구성하는 계획을 승인하고 진행을 요청했다.

## ADR-027: 모바일 콤보 템포·Pushbox·확장 경기장

- 상태: accepted
- 날짜: 2026-10-07
- 적용 Phase: Phase 6 로컬 대전 개선
- 배경: 기존 기본 공격은 14 tick 안팎이고 입력을 회복 중에만 받아 터치에서 연계가 자주 끊겼다. 파이터 Pushbox는 정의만 있고 분리하지 않아 몸이 겹쳤으며, 짧은 경직과 지형 그림의 풀잎 상단 기준 때문에 타격과 발 접촉도 불명확했다.
- 결정: 기본 연계 중간타는 22 tick으로 하고 `ComboLinkData` v2가 회복 시작 기준 -2~10 tick의 입력 하나를 예약한다. 공격별 고정 경직을 늘리고 전역 범위는 10~36 tick으로 둔다. 고정 tick Pushbox가 이동 뒤·적중 전에 ID 순서로 몸을 수평 분리하며 참가 인원에 비례한 제한 횟수 안에서 반복한다. `StageData` v1은 폭 2,160의 바닥, 비대칭 통과형 발판 4개, 시작 위치와 링아웃 영역의 단일 원본이다. 새 지형 그림 승인 전에는 충돌면과 같은 임시 도형을 사용한다.
- 대안: 입력 구간만 늘리고 빠른 공격 유지, 물리 레이어로 파이터끼리 충돌, 기존 1,080 경기장 유지, 신규 지형 그림을 먼저 제작.
- 영향: 공격·연계·전투 규칙 Resource 버전과 AI 이동 경로가 갱신된다. 플레이어 중심 1.25배 카메라, HP·stock·피해·넉백과 승인 캐릭터 이미지는 바꾸지 않는다.
- 검증: 네 캐릭터 공격 tick과 경직, 활성 말기·회복 입력 예약, 2~8인 Pushbox 결정론, 발 기준과 바닥 접촉, 다층 AI 이동·링아웃, 카메라·화살표 불변을 자동·Android 회귀로 확인한다.
- 대체/롤백: 공격 Resource와 `ComboLinkData`·`CombatRules`, `StageData` 소비자, 장면·AI·문서·검사를 한 묶음으로 되돌린다.
- 승인 근거: 2026-10-06 사용자가 다섯 문제 해결을 요청했고, 콤보 중심 22 tick·비대칭 폭 2,160 다층 맵·임시 도형 우선을 선택한 뒤 계획대로 개발을 요청했다.
- 후속 적용: 2026-10-08 사용자가 패키징·스토어를 제외한 남은 완성 계획을 승인했다.
  `StageData` v2에 지형 논리 ID를 추가하고 다섯 충돌면에 맞춘 승인 숲 지형으로 임시 도형을
  교체한다. v1 경기장 Resource는 조용히 추정하지 않고 거부한다.

## ADR-029: 기본 게임의 개발용 DB 프로필 저장

- 상태: accepted
- 날짜: 2026-10-08
- 적용 Phase: Phase 6의 개발용 저장 연결
- 결정: 첫 지급·0원 구매·보유·선택·접근성 설정을 기존 게스트 API를 통해 로컬 PostgreSQL에 저장한다. DB 모드는 저장 성공 뒤 변경을 반영하며 기기 저장 모드는 별도로 유지한다.
- 이전: DB 기록이 없을 때만 유효한 기기 프로필을 이전하며 기기 원본은 보존한다. 기존 DB 기록은 덮어쓰지 않는다.
- 실패: 동일 요청 ID 재시도와 변경 번호 검사를 사용한다. 인증 실패 때 새 게스트를 자동 생성하지 않는다. 오프라인 자동 동기화는 추가하지 않는다.
- 영향: ADR-025·026의 개발용 저장 범위를 기본 게임 프로필까지 확장한다. 정식 계정·경제·성장·클라우드·Phase 승격은 포함하지 않는다. ADR-028의 LAN 전투 통신은 그대로 유지한다.
- 검증: Mac의 실제 Godot 앱과 API·PostgreSQL에서 저장·재실행 복원·SQL 일치·실패·중복·동시 변경을 확인한다. Android 실기기 확인은 별도 결과로만 기록한다.
- 대체/롤백: 코드 revert와 기기 저장 모드로 복귀한다. DB 볼륨·새 표의 데이터는 자동 삭제하지 않는다.
- 승인 근거: 사용자가 기본 게임 저장 연동, DB 확인 후 변경 확정, 비어 있는 DB로 기기 저장 이전을 선택하고 계획대로 개발을 요청했다.
- 후속 적용: 2026-10-08 사용자가 대전 미니맵 계획을 승인했다. 닉네임과 미니맵 표시 설정을 개발용 프로필 v3에 추가하고 기존 기기·DB 기록의 보유·선택·접근성 값을 보존해 이전한다.

## ADR-028: macOS 호스트 기반 LAN 1대1 사용자 대전

- 상태: accepted
- 날짜: 2026-10-07
- 적용 Phase: Phase 6 오프라인 흐름 진행 중의 제한된 LAN 대전
- 배경: 스토어 출시와 운영 서버 전에 실제 Android 사용자 두 명이 같은 Wi-Fi에서 전투를 검증할 수 있는 제품 경로가 필요하다. 기존 ADR-026은 데이터베이스와 고정 캐릭터를 쓰는 개발용 세로 흐름이라 사용자 화면으로 노출할 수 없다.
- 결정: macOS의 Godot headless 서버 한 대가 단일 1대1 경기를 60Hz로 판정하고 두 Android APK에 20Hz snapshot을 보낸다. 사용자는 사설 IPv4와 8자리 방 코드를 포함한 한 줄 코드로 연결한다. 로그인·결제·데이터베이스·인터넷 매칭은 사용하지 않으며 네 캐릭터와 무료 장신구 6종을 서버가 검증한다. 연결 해제 입력을 즉시 풀고 60초 재접속 뒤 이탈 패배로 처리한다.
- 대안: 개발용 PostgreSQL/API 흐름을 사용자에게 노출, Android 한 대를 권위 호스트로 사용, 공용 인터넷 서버 배포.
- 영향: 별도 버전 LAN 메시지 계약, macOS 호스트 명령, Android 방 생성·참가·재대전 UI와 두 실기기 검증이 필요하다. ADR-008의 서버 권위와 ADR-026 개발 경로는 유지한다.
- 검증: 잘못된 코드·로드아웃·버전·중복 입력·세 번째 참가 거부, 두 실제 클라이언트의 동일 결과, 재접속·만료·재대전과 Android 두 기기 실제 플레이를 확인한다.
- 대체/롤백: LAN 서버·클라이언트·화면과 ADR-028 소비자를 함께 제거하면 기존 오프라인과 ADR-026 개발 흐름으로 돌아간다.
- 승인 근거: 2026-10-07 사용자가 같은 Wi-Fi 1대1, macOS PC 호스트, 한 줄 연결 코드와 대전 중심 완료 계획을 승인하고 구현을 요청했다.

- 후속 적용: 2026-10-08 사용자가 대전 미니맵 계획을 승인했다. LAN 방 생성·참가 시 닉네임을 선택적으로 전달하고 참가자 표시 정보로 공유한다. 재접속·재대전에 유지하며 기존 protocol_version 1 메시지와 전투 상태·판정은 유지한다.
