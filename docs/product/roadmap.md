# 06. 개발 순서와 완료 조건

Phase는 큰 개발 단계를 뜻한다. 앞 단계의 필수 완료 조건을 건너뛰지 않는다. 콘텐츠 수량과 일정은 실제 작업 근거 없이 확정하지 않는다. 현재는 Phase 2까지 완료했다. 그 밖의 용어는 [용어 가이드](../GLOSSARY.md)를 참고한다.

## Phase 0 — 프로젝트 실행 준비 (완료)

Godot 프로젝트와 폴더를 만들고, Android 설치 파일을 생성할 수 있게 한다. 터치·키보드 입력 이름, 2D 테스트 경기장과 기본 도형으로 된 임시 캐릭터를 준비한다.

Forest Arena 브랜드, 비전투 화면·에셋 ID와 Penpot 작업 계약은 Phase 0의 설계 기반으로 유지할 수 있다. 이는 24개 화면 구현, 이미지 생성, 계정·상점·랭크·온라인 기능 또는 Phase 승격을 뜻하지 않는다.

완료 조건: PC에서 프로젝트를 실행하고 Android 테스트 APK를 만드는 명령이 반복해서 동작한다. 터치, 앱 중단·복귀와 성능을 어떻게 확인할지도 기록한다.

## Phase 1 — 기본 전투 (완료)

같은 입력이면 같은 결과가 나오는 좌우·상하 이동, 점프, 대시, 공격의 준비·적중·회복, 공격·피격 영역, 밀려남, 링아웃과 기본 터치 조작을 만든다. 지상 연속 공격, 방향 강공격, 대시 공격, 공중 약·강공격, 대표 특수기와 경기장 복귀를 먼저 구현한다.

완료 조건: 빗나감, 한 번만 맞음, 서로 동시에 맞음, 자기 자신을 때리지 않음, 의도하지 않은 반복 적중 방지, 링아웃과 입력 초기화 검사가 통과한다.

## Phase 2 — 캐릭터·직업·장신구 조합 (완료)

Godot 데이터 형식(`Resource`)과 `캐릭터 + 직업 + 장신구` 조합 처리를 만든다. `MoveSetData`에는 기술 목록, 연계와 입력 조건을 두고, `AttackData`에는 공격 시간과 실제 맞음 결과를 두도록 버전이 있는 데이터 형식을 확정한다.

완료 조건: 데이터를 합치는 순서, 잘못된 ID, 값 충돌 처리와 원본 파일이 바뀌지 않는지를 자동으로 검사한다.

## Phase 3 — 서로 다른 전투 스타일 비교 (다음 단계)

전투 방식이 다른 소수의 캐릭터와 직업 시험안을 직접 플레이해 비교한다. 막기, 회피, 힘 모으기, 궁극기와 전체 특수기는 관련 결정이 승인된 뒤 이 단계부터 확인한다. 잡기 기술은 제공하지 않는다.

완료 조건: 각 전투 스타일에서 무엇을 확인하려 했는지, 같은 비교 조건, 결과와 채택·폐기 이유가 기록된다.

현재 자동 비교 근거는 [_workspace/combat-phase3-comparison](../../_workspace/combat-phase3-comparison/)에 있다. 이 근거는 데이터 차이의 회귀를 막지만, 직접 플레이 비교와 채택·폐기 이유가 아직 없으므로 Phase 3 완료를 뜻하지 않는다.

## Phase 4 — 장신구

데이터 기반 장신구와 태그 시너지를 검증한다.

완료 조건: 조합 조건의 충족·불충족, 기술 교체, 값 충돌 우선순위를 검사한다. 아이콘이나 애니메이션이 전투 결과를 바꾸지 않는지도 확인한다.

## Phase 5 — 직업 변화 구조

여러 갈래로 선택하는 직업이 이동, 기술, 항상 적용되는 효과와 공격 연결 규칙을 제대로 바꾸는지 확인한다. 앱을 종료해도 남는 성장 데이터와 게임 재화는 별도 단계로 다룬다.

완료 조건: 이전 직업과 현재 단계의 효과를 쌓는 규칙, 한 판용 데이터 조합이 일관된다. 공용 코드에 특정 직업 이름을 직접 비교하는 예외 분기가 없어야 한다.

## Phase 6 — 처음부터 끝까지 가능한 오프라인 한 판

Android에서 스토리, AI 대전, 연습과 개인전·팀전의 오프라인 범위를 하나로 연결한다. 메뉴부터 결과 화면까지의 흐름, 2D 그래픽, 소리, 접근성과 모바일 안정성을 함께 확인한다. 전체 최대 8명, 팀당 1~4명 규칙을 지키되 온라인 기능처럼 보이게 만들지 않는다.

완료 조건: 승인된 콘텐츠와 전체 사용자 흐름을 Android에서 확인했고, 진행을 막는 알려진 문제가 없다.

## Phase 7 — 온라인 검토와 구현

관련 결정과 버전이 있는 데이터 형식이 승인된 뒤에만 어느 기기가 최종 결과를 정할지, 데이터 전송, 재접속과 Android 네트워크 전환을 구현한다.

완료 조건: 네트워크 데이터가 중복되거나 순서가 바뀌거나 사라져도, 버전이 맞지 않거나 앱 중단·복귀와 재접속이 실패해도 최종 전투 결과가 모든 기기에서 일치한다.

## 모든 단계에 공통인 완료 조건

- `_workspace`에 요청과 역할별 작업, 품질 확인, 마무리 기록이 있다.
- 전투 결과는 전투 코드가 계산하고 그래픽·UI·소리는 그 결과를 표시만 한다.
- 새 기능에는 자동 테스트 또는 이름을 붙인 수동 재검사가 있다.
- 실제 Android 기기에서 확인하지 않은 결과를 통과(`pass`)로 표시하지 않는다.
- 외부 이미지·소리에는 출처와 이용 권리 기록이 있고, 나중에 다른 자산으로 바꿔도 전투 코드가 영향을 받지 않게 연결한다.
- 미정 규칙은 결정 기록에서 `proposed`(제안)로 두며 사용자 승인 없이 `accepted`(승인)로 바꾸지 않는다.
- 앞으로 코드 작업은 품질 검사 통과와 원격 `develop` 브랜치에 합쳐진 기록이 모두 있어야 완료다.
