# 실제 서비스 개발 부족 항목 점검

> 이 문서는 2026-10-09 당시의 점검 기록이다. 아래의 “현재”와 미구현 판단은 그때의 상태를 뜻한다. 이후 구현 상태는 [데모 설치 안내](../gameplay/demo-install.md), [실제 메뉴 기능](../ui/menu-features-v01.md), [현재 작업 상태](../operations/harness/operating-index.md)를 따른다. 과거 판단을 새 검사 통과로 바꾸지 않는다.

점검일: 2026-10-09. 현재 Forest Arena는 **로컬 플레이가 가능한 개발 버전이며, 정식 배포·운영 준비는 아직 끝나지 않았다.** 전투 기반 Phase 1~5 완료와 서비스 출시 완료는 서로 다른 판단이다.

사용자가 추가로 지정한 무료·APK 직접 설치·게스트/닉네임·로컬 서버 한 대·동일 네트워크 대전의 초기 배포는 [데모 출시 점검](demo-readiness-audit.md)을 따른다. 이 문서의 스토어·결제·공용 인터넷 준비 전체를 데모 필수 조건으로 적용하지 않는다.

이번 점검은 현재 작업 폴더의 문서·코드·자동 검사와 기존 기기 기록을 대상으로 한다. Play Console, 운영 서버와 신규 실기기 시험은 직접 확인하지 않았다. 따라서 저장소에서 찾지 못한 운영 자료는 **근거 없음**으로 표시하며, 외부에서도 존재하지 않는다고 단정하지 않는다. 작업 중인 자산 변경이 있으므로 결과는 현재 폴더 기준이며 배포된 버전 전체의 판정이 아니다.

## 판단 기준

- **P0**: 해당 출시 형태로 공개하기 전에 해결해야 한다.
- **P1**: 해당 기능의 정식 제공 전에 개발·검증해야 한다.
- **P2**: 공개 후 개선할 수 있으며 초기 출시 필수로 정하지 않는다.
- **미구현**: 제품 문서에 미구현이 명시됐거나 현재 실행 코드가 제공하지 않는다.
- **부분 구현**: 기반이 있으나 실제 서비스 요구를 모두 충족하지 않는다.
- **미확인**: 구현 또는 기존 확인은 있지만 이번 출시 판단에 필요한 증거가 부족하다.
- **결정 필요**: 규칙·범위가 확정되지 않아 구현 조건부터 정해야 한다.
- **근거 없음**: 조사한 저장소에서 구현·운영 절차·확인 기록을 찾지 못했다.

출시 형태는 아직 확정하지 않았다. 아래에서는 **오프라인 Android 공개**, **정식 인터넷 서비스**, **성장·유료 상품 제공**을 나눠 필요한 조건을 표시한다. 계정·클라우드·결제·랭크를 오프라인 출시의 필수 기능으로 추가하지 않는다. 이 목록은 개발 제안이며 Phase 전환이나 미정 결정의 승인을 뜻하지 않는다.

## 이미 있는 기반

- 이동·공격·피격·링아웃·직업 상속·장신구 조합의 전투 코드와 자동 검사가 있다.
- 첫 캐릭터 지급, 4캐릭터·6장신구의 0원 상점, 기기 저장, AI·연습·Solo·Team의 최대 8인 오프라인 경기, 결과·재대전이 연결돼 있다.
- 기기 저장은 임시 파일 저장 후 교체, 이전 정상 파일 백업, 손상 시 복구와 v1→v2 이전을 제공한다. 저장 기능 전체를 미구현으로 분류하지 않는다.
- 접근성 설정과 이벤트 기반 임시 전투 효과음이 있다. 완성된 음악·효과음 패키지와 사람의 청취 검증은 별개다.
- LAN 1대1은 60Hz 서버 판정, 20Hz 상태 전송과 60초 재접속이 있다. 개발 API에는 게스트 인증, 토큰 갱신, 입력 크기 제한, 프로필 변경 번호 확인, 중복 요청 처리와 결과 저장이 있다.
- Galaxy S23 Ultra에서 AI 경기 종료·재대전과 일부 캐릭터 진입 기록이 있다. 당시 표본은 60 FPS, p95 약 16.7ms다. 이는 최신 모든 모션·8인전·다양한 기기의 성능 보장이 아니다.

## 권장 개발 순서

1. **출시 범위 확정(A01)**: 오프라인만 공개할지, Story·유료 상품·인터넷 대전을 포함할지 결정한다. 기존 미정 정책을 일괄 승인한 것으로 취급하지 않는다.
2. **오프라인 출시 기반(A02~A08, A14)**: release 빌드·개발 기능 분리·저장과 업데이트·기기 성능·스토어·권리·장애 대응을 먼저 준비한다.
3. **완성도 검증(A09~A13, B01~B02)**: 처음 사용하는 사람의 조작, 접근성·오디오·밸런스와 공개할 Story·직업 흐름을 연결한다. Story·성장을 제외하려면 범위 결정을 먼저 기록한다.
4. **수익화 조건 해결(B03~B06)**: 공정성·가격·보상 정책을 먼저 확정한 뒤 경제·결제를 구현한다.
5. **정식 인터넷 범위(C01~C07)**: Phase 7 승인 후 계정·운영 환경·다중 경기·네트워크 실패·데이터 복구를 검증한다.

날짜와 인력은 실제 구현 범위가 정해지기 전에는 산정하지 않는다. 항목별 담당 역할은 작업 배정 제안이며 현재 구현을 시작한 상태는 아니다.

## 점검 결과와 남은 확인

자동 검사 결과와 정확한 실행 환경은 [이번 점검 마무리](../../_workspace/service-readiness-audit/04_closeout.md)에 기록한다. 기존 기기 기록의 통과 범위를 확대하지 않았다. 문서·자동 검사 통과는 스토어 제출, 운영 부하 또는 최신 물리 기기 검사의 통과를 뜻하지 않는다.

이번 `./scripts/verify.sh`는 종료 코드 0으로 통과했다. 다만 여러 검사 종료 시 객체가 남는 `ObjectDB` 경고와 `tests/character_data_contract.gd`의 원본 이미지 읽기에 대한 export 경고, `build/` 안의 별도 프로젝트 감지 경고가 있었다. 이미지 경고의 호출 위치는 테스트이며 실행 앱의 이미지 실패로 단정하지 않는다. A05·A13에서 시험 정리 문제와 실제 반복 경기의 메모리 문제를 구분하고, A02·A03에서 배포 파일 자체의 자산 로딩과 포함 범위를 확인해야 한다.

별도 확인이 필요한 외부 정보는 Play Console 계정·테스트 트랙·제출 준비 상태, 실제 운영 서버 유무, 별도 보관한 권리·지원 자료다. 해당 자료가 확인되면 관련 항목 상태를 갱신한다.
