# APK 직접 설치 데모 출시 점검

> 이 문서는 2026-10-09~10 당시의 점검 기록이다. 아래의 “현재”와 미구현 판단은 그때의 상태를 뜻한다. 이후 구현 상태는 [데모 설치 안내](../gameplay/demo-install.md), [실제 메뉴 기능](../ui/menu-features-v01.md), [현재 작업 상태](../operations/harness/operating-index.md)를 따른다. 과거 판단을 새 검사 통과로 바꾸지 않는다.

점검 시작: 2026-10-09. 중단 후 재검토: 2026-10-10. **기존 LAN 대전 기반은 활용할 수 있지만, 현재 버전은 게스트 로그인·닉네임 요구를 충족하지 않아 아직 데모 배포 완료로 판단할 수 없다.**

이 문서는 사용자가 지정한 데모 범위의 점검 원본이다. [정식 서비스 부족 항목](service-readiness-audit.md)의 결제·스토어·인터넷 서비스 준비 전체를 데모의 필수 조건으로 적용하지 않는다. 기존 Phase 상태와 현재 구현 사실은 그대로 유지한다.

## 사용자가 정한 데모 조건

| 항목 | 데모 조건 |
| --- | --- |
| 배포 | Android APK 파일을 전달해 직접 설치·실행 |
| 유료 기능 | 유료 결제 없음 |
| 사용자 접속 | 게스트로 로그인하고 닉네임 설정 가능 |
| 서버 | 로컬 서버 한 대 |
| 온라인 범위 | 동일 네트워크에 연결된 사용자만 대전 가능 |

온라인 참가 인원과 동시 경기 수는 아직 미정이다. **서버 한 대는 경기 한 개와 같은 뜻이 아니다.** 현재 코드는 LAN 1대1 한 경기만 운영하므로 아래는 이 규모를 임시 기준으로 점검한다. 사용자가 여러 동시 경기 또는 8인전을 선택하면 서버·방 관리와 부하 검사를 추가한다.

DB 사용, 게스트의 재실행·서버 재시작 이후 유지, 닉네임 중복·변경 규칙도 아직 미정이다. 로컬 서버 한 대에서 여러 프로그램을 실행하는 것은 가능하므로 서버 대수만으로 DB 또는 API 사용을 금지하거나 필수로 정하지 않는다. 신규 기능 구현 시 이 규칙들을 먼저 정한다.

재개 시점의 장신구 규칙은 [ADR-031](decisions.md#adr-031-장신구-추가-피해부활-제외와-선택형-옵션)과 [현재 장신구 설정](../gameplay/accessories-v01.md)을 따른다. 과거 점검의 추가 피해·반사·부활 설명을 현재 데모 옵션으로 사용하지 않는다.

## 현재 구현과 차이

| 요구 | 현재 근거 | 판단 |
| --- | --- | --- |
| APK 직접 설치 | Android debug APK 생성·패키지 검사·기기 설치 기록 있음 | 기반 있음. 배포할 버전의 최초 설치·업데이트 검사는 추가 필요 |
| 무료 데모 | 4캐릭터·6장신구의 0원 상점, 결제 미구현 | 요구와 부합. 데모에서 제공할 목록·지급 흐름은 명시 필요 |
| 게스트 로그인 | 개발 API에는 `/v1/auth/guest`와 갱신 토큰 있음. LAN은 로그인 없이 `create_room`·`join_room`으로 접속 | 부분 구현. 개발 인증과 실제 LAN 참가를 연결해야 함 |

| 로컬 서버 한 대 | `scripts/lan-host.sh`가 Mac의 Godot 한 경기 서버 시작·상태·종료 제공 | 단일 1대1 기반 있음. 배포·재시작·지원 환경 확인 필요 |
| 동일 네트워크 제한 | 초대 코드가 사설 IPv4·loopback만 허용. 실행 스크립트는 `0.0.0.0`으로 모든 인터페이스에 서버를 엶 | 부분 구현. 사설 주소 검사만으로 같은 네트워크 접근 제한이 증명되지는 않음 |
| 두 Android 온라인 대전 | 자동 두 클라이언트와 Android 에뮬레이터+Godot 상대의 접속·결과·재대전 기록 있음 | 기반 있음. 물리 Android 두 대의 데모 전체 흐름은 미확인 |

근거 파일: `scripts/local_ai_app.gd`, `scripts/network/lan_match_client.gd`, `scripts/network/lan_invite.gd`, `server/game/lan_game_server.gd`, `server/api/src/server.ts`, `server/api/src/db.ts`, `database/migrations/0002_local_online_vertical_slice.sql`, `export_presets.cfg`.

기존 실제 연결 근거는 [LAN 사용법](../gameplay/lan-1v1-play.md)과 [Android 연결 기록](../../_workspace/lan-1v1-playable/03_qa_r02.md)에 있다. 기존 LAN의 “로그인 없음”은 현재 구현 설명이며, 데모의 “게스트 로그인 가능”은 새 요구다. 둘을 이미 같은 기능인 것으로 간주하지 않는다.

## 초기 데모에서 필수로 추가하지 않는 것

- 유료 재화·결제·영수증·환불·경제 보상 서버.
- Play Store 등록, AAB, 스토어 스크린샷·심사 제출·테스트 트랙.
- 공용 인터넷 서버, 인터넷 자동 매칭, 클라우드 계정과 기기 간 동기화, 랭크·소셜·채팅.
- Story 전체 대화·성장, 복수 장신구·추가 외형 상품. 데모 메뉴에서 제공한다고 약속하는 기능은 별도로 완성해야 한다.

복잡한 운영 시스템·고가용성 서버·대규모 부하 검사는 필요 범위를 줄일 수 있다. 다만 게스트·닉네임·LAN 접속 실패·배포 파일·현장 기기 확인은 데모 요구를 충족하는 데 필요하다. 데모 점검 완료만으로 기존 Phase 6 전체 완료를 선언하지 않는다.

## 권장 개발 순서와 데모 완료 조건

1. 온라인 규모와 데모 콘텐츠, 게스트 유지·닉네임 규칙을 정한다.
2. 게스트 접속·닉네임과 기존 LAN의 방 생성·참가·복귀를 연결한다.
3. 동일 네트워크 제한, 서버 실행 묶음과 접속 실패·종료 흐름을 준비한다.
4. 버전이 일치하는 APK·서버·설치 안내를 묶고 두 물리 Android 기기로 전체 흐름을 검사한다.
5. 출시 전 P0 항목이 통과하고, P1 항목의 확인 또는 미해결 내용·후속 계획을 기록한 뒤 데모 배포 가능 여부를 판단한다.

현재 가장 큰 미완성은 **게스트 세션과 LAN 통합, 닉네임, 같은 네트워크 제한 검증, 두 실기기의 전체 흐름**이다. 검사 명령의 실행 결과와 남은 제한은 [점검 마무리](../../_workspace/demo-readiness-audit/04_closeout.md)에 둔다. 문서 점검과 기능 구현·데모 출시 완료는 구분한다.
