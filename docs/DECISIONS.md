# Forest Arena 결정 기록

미정 제품 규칙을 ADR로 관리한다. 사용자 승인 없는 제안은 영구 구현 기준이 아니다.

## 상태

- proposed: 검토 중이며 교체 가능한 프로토타입 선택만 허용.
- accepted: 사용자가 승인해 번호순 제품 문서보다 우선하는 결정.
- superseded: 새 ADR로 대체된 결정.
- rejected: 구현 근거로 사용할 수 없는 결정.

## ADR-001: Phase 1 승리 방식과 링아웃 흐름 기준안

- 상태: accepted
- 날짜: 2026-09-06
- 적용 Phase: 1
- 배경: 링아웃·복귀·결과 회귀를 구현하려면 최소 경기 종료 규칙이 필요하다.
- 결정: 각 파이터는 3 stock으로 시작하고 링아웃 때 1 stock을 잃은 뒤 짧은 무적과 함께 스폰으로 복귀한다. 0 stock이면 패배하며 Phase 1에는 제한 시간을 두지 않는다.
- 대안: 단판 링아웃, 체력 0 패배, 제한 시간과 동점 판정.
- 영향: stock HUD와 결과 이벤트가 필요하지만 영속 성장·보상은 만들지 않는다.
- 검증: 연속 링아웃, 동시 최종 링아웃과 복귀 중 재링아웃을 자동 검사한다.
- 대체/롤백: MatchRules 데이터로 수치와 방식이 교체 가능해야 한다.
- 승인 근거: 2026-09-06 사용자 응답에서 제안 규칙 전체 승인.

## ADR-002: Phase 1 피해·넉백·경직 기준안

- 상태: accepted
- 날짜: 2026-09-06
- 적용 Phase: 1
- 배경: 공격 결과가 임시 수치라도 한 곳에서 결정되어야 전투 회귀를 만들 수 있다.
- 결정: 누적 피해율 방식으로 시작한다. 적중 시 피해율을 더하고 `base_knockback + damage_after_hit × growth`를 무게 보정해 넉백 속도를 구하며, 경직은 넉백 속도에 비례하되 상·하한을 둔다. 모든 계수는 CombatRules 데이터에 둔다.
- 대안: 고정 HP, 공격별 고정 넉백, 곡선 기반 공식.
- 영향: 높은 피해율일수록 링아웃 가능성이 커지고 정확한 계수는 플레이테스트 조정 대상이다.
- 검증: 동일 초기 상태·입력·tick의 동일 결과, 무게 순서, 피해 증가에 따른 단조 증가와 상·하한을 자동 검사한다.
- 대체/롤백: CombatMath 구현을 교체하고 AttackData·UI 이벤트 계약은 유지한다.
- 승인 근거: 2026-09-06 사용자 응답에서 누적 피해율 넉백 승인.

## ADR-003: Phase 1 공중 점프 기준안

- 상태: accepted
- 날짜: 2026-09-06
- 적용 Phase: 1
- 배경: 점프 상태와 입력 회귀에 공중 점프 횟수 및 회복 시점이 필요하다.
- 결정: 기본 파이터는 지상 점프 후 공중 점프 1회를 가지며 권위 플랫폼에 착지하면 회복한다. 피격·넉백은 남은 횟수를 회복하지 않는다.
- 대안: 공중 점프 없음, 종/직업별 기본 횟수, 피격 후 회복.
- 영향: 기본 이동 상태에 남은 공중 점프 카운터가 추가되며 이후 CharacterStats가 횟수를 변경할 수 있다.
- 검증: 지상→공중 점프, 초과 입력 무시, 착지 회복과 피격 비회복을 자동 검사한다.
- 대체/롤백: 기본 횟수를 데이터로 바꾸고 의미 입력 ID는 유지한다.
- 승인 근거: 2026-09-06 사용자 응답에서 공중 점프 1회 승인.

## ADR-006: Phase 0 터치 입력 기준안

- 상태: proposed
- 날짜: 2026-09-06
- 적용 Phase: 0/1
- 배경: 멀티터치와 포커스 손실 회귀를 검증하려면 교체 가능한 초기 배치가 필요하다.
- 결정: Phase 0에서는 화면 하단 42%만 입력에 쓰고 왼쪽에 이동, 오른쪽에 행동을 둔다. 좌우 6.5%는 임시 safe edge로 입력에서 제외하며 영역 이탈은 이전 의미 입력을 해제한다.
- 대안: 가상 스틱, 자유 배치, 고정 이미지 버튼.
- 영향: 현재 비율은 플레이테스트용이며 safe area·최소 물리 크기·사용자 조정 범위를 확정하지 않는다.
- 검증: 에뮬레이터에서 다중 포인터와 이탈을 검사하고 실제 Android 기기에서 가림·도달성과 OS 제스처 충돌을 후속 확인한다.
- 대체/롤백: 입력 영역 테이블만 바꾸고 의미 입력 ID는 유지한다.

## ADR-007: Phase 0 성능 측정 기준안

- 상태: proposed
- 날짜: 2026-09-06
- 적용 Phase: 0
- 배경: 예산 확정 전에 재현 가능한 기준 장면과 측정 항목이 필요하다.
- 결정: 1280×720 논리 해상도, GL Compatibility, 60 FPS 후보를 시작점으로 삼고 프레임 시간·메모리·draw call을 기록한다.
- 대안: Forward+ 또는 Mobile renderer, 30 FPS 기준, 다른 논리 해상도.
- 영향: 목표 수치와 기준 기기는 아직 승인되지 않았으며 실제 기기 측정 뒤 조정한다.
- 검증: 기준 기기에서 10분 실행 후 프레임 시간 분포, 메모리와 발열 저하를 기록한다.
- 대체/롤백: ProjectSettings 렌더러와 논리 해상도를 변경하고 장면 계약은 유지한다.

## ADR-011: Android 애플리케이션 식별자·지원 ABI 기준안

- 상태: accepted
- 날짜: 2026-09-06
- 적용 Phase: 0
- 배경: debug APK 생성에는 유효한 package ID와 ABI 선택이 필요하다.
- 결정: package ID는 `com.foresttales.welllbeing`, ABI는 실제 기기용 arm64-v8a와 로컬 에뮬레이터용 x86_64를 사용한다. 최소 Android 버전은 제품 기준인 Android 10이다. 향후 물리 기기 기준대상은 Galaxy S23 Ultra이며 당분간 에뮬레이터를 사용한다.
- 대안: 사용자가 소유한 역도메인 package ID, arm64-v8a 단일 ABI.
- 영향: 스토어 등록 또는 외부 배포 전에 소유권 있는 package ID로 확정해야 한다.
- 검증: debug export, 에뮬레이터 설치·실행, 최종 기준 기기의 arm64 설치를 확인한다.
- 대체/롤백: 공개 배포 전 export preset의 식별자와 ABI를 교체한다.
- 승인 근거: 2026-09-06 사용자 응답에서 package ID 철자와 Galaxy S23 Ultra 기준대상, 당분간 에뮬레이터 사용을 지정.
- 부분 상태: package ID `com.foresttales.welllbeing` 결정만 ADR-014로 superseded되었다. ABI, 최소 Android 버전, 기준 기기와 에뮬레이터 사용 결정은 accepted 상태를 유지한다.

## ADR-012: 기본 공격 입력·짧은 분기 연계 기준안

- 상태: accepted
- 날짜: 2026-09-11
- 적용 Phase: 1
- 배경: 방향 공격과 캐릭터별 기본 연계를 구현하려면 버튼을 누른 순서, 입력 예약, 공중 추격의 공통 경계가 필요하다.
- 결정: 왼손 4방향과 오른손 약·강·특수, 별도 점프를 기준으로 한다. 약 반복은 자현 3단·묘령 4단·나비 2단이며 다음 입력 하나만 예약한다. 피니시 전 적중은 다음 약·방향 강·특수로 분기할 수 있고, 강·특수 분기와 피니시는 원 연계를 끝낸다. 위 강 적중 후만 점프 추격을 허용하며 체공 중 공중 공격은 최대 두 번이다. 발동 방향·보는 쪽은 고정하고 자동 추적·자동 뒤돌기를 하지 않는다.
- 대안: 단일 공격 버튼, 자동 완주 연계, 모든 기술에 확정 취소, 방향 자동 보정.
- 영향: Phase 1에는 ComboController와 방향·edge가 있는 CombatIntent가 필요하다. 정확한 프레임·피해·hitbox는 AttackData로 분리한다.
- 검증: 한 입력 예약, 3/4/2단 연계, 피니시 취소 불가, 위 강 적중 전후의 점프 추격, 체공 공격 2회 한도와 방향 고정을 자동 검사한다.
- 대체/롤백: MoveSetData의 분기 테이블을 교체하되 `attack_light`, `attack_heavy`, `attack_special` ID는 유지한다.
- 승인 근거: 2026-09-11 사용자가 Phase 1 코어 전투 수직 슬라이스 계획에서 이 입력·연계 기준의 구현을 명시 승인.

## ADR-016: 동시 최종 링아웃 서든데스

- 상태: accepted
- 날짜: 2026-09-11
- 적용 Phase: 1
- 배경: 양쪽 마지막 stock이 같은 고정 tick에 소진될 때 판정 순서가 승패를 정하면 결정론과 공정성이 깨진다.
- 결정: 동시 최종 링아웃이면 양쪽을 피해율 0%·1 stock으로 되돌리고 원래 스폰에 45 tick 뒤 복귀시킨다. 이후에도 동시 탈락하면 승자가 생길 때까지 같은 서든데스를 반복한다. 비동시 최종 탈락만 승패를 확정한다.
- 대안: 무승부, 피해율 비교, 안정 ID 순서로 승자 결정.
- 영향: MatchController가 같은 tick의 링아웃을 묶어 처리하며 HUD는 서든데스 상태를 읽기 전용으로 표시한다.
- 검증: 동시 최종 탈락과 반복 동시 탈락, 비동시 최종 탈락을 고정 tick 자동 검사한다.
- 대체/롤백: 경기 결과 규칙을 바꿀 경우 새 ADR로 대체하고 MatchController와 HUD 계약을 함께 갱신한다.
- 승인 근거: 2026-09-11 사용자가 Phase 1 코어 전투 수직 슬라이스 계획에서 반복 서든데스를 명시 승인.

## ADR-013: 방어·회피·잡기·차지·궁극기 자원 기준

- 상태: accepted
- 날짜: 2026-09-12
- 적용 Phase: 3 이후
- 배경: 가드·회피·잡기와 큰 보상 기술은 초반 기본 전투와 별도의 대응·자원 검증이 필요하다.
- 결정: 행동 버튼은 중립 유지 가드, 좌우 누름 회피 스텝, 좌우 유지 시 회피 뒤 대시, 공중 1회 회피로 확장한다. 가드 해제의 짧은 유예에 잡기 보조 입력을 제공하며 일반 공격은 가드 가능·잡기는 가드 대응·잡기 실패는 큰 빈틈으로 둔다. 초기 규칙에는 상하단 가드·정밀 패리가 없다. 지상 강 유지 차지는 방향을 고정하고 공중 차지는 금지한다. 특수기는 지상·공중 쿨다운을 공유하고 위 특수 복귀는 체공 중 한 번이다. 궁극기는 유효 피해로만 충전, stock당 한 번, stock 상실 때 초기화, 빗나가도 소모, 준비 중 대응 가능, 일반 콤보 확정 취소 불가로 둔다.
- 대안: 영구 가드, 무제한 회피·복귀, 헛공격 게이지 충전, 궁극기 콤보 확정 취소.
- 영향: Phase 3 이후 가드 내구·가드 붕괴, 회피·복귀 카운터, 특수 쿨다운과 궁극기 게이지가 권위 전투 데이터·HUD 이벤트에 추가된다.
- 검증: 가드 내구·붕괴, 회피 재입력, 공중 회피·위 특수 한도, 잡기 실패 회복, 헛공격 비충전, stock 초기화와 궁극기 빗나감 소모를 자동·기기 회귀로 검사한다.
- 대체/롤백: 자원·행동 상태를 MatchRules와 MoveSetData로 교체하며 기본 세 공격 ID와 Phase 1 판정은 보존한다.
- 대체 대상: ADR-004와 ADR-005의 미상세 제안을 이 기준안으로 대체한다.
- 승인 근거: 2026-09-12 사용자가 ADR-013 확정과 Phase 3 방어·회피 원형 비교를 명시 승인. 첫 슬라이스는 가드·가드 붕괴·지상/공중 회피만 구현하며, 잡기·차지·궁극기는 accepted 후속 범위로 남긴다.

## ADR-014: Forest Arena 브랜드·Android 식별자 전환

- 상태: accepted
- 날짜: 2026-09-09
- 적용 Phase: 0
- 배경: 제품의 활성 브랜드, Godot 표시명, Android 식별자, APK와 하네스 경로가 하나의 공개 명명 계약을 사용해야 한다.
- 결정: 제품 표시명은 `Forest Arena`, 로고 표기는 `FOREST ARENA`, 기술 슬러그는 `forest-arena`, Android package ID는 `com.forestarena.welllbeing`, debug APK는 `build/android/ForestArena-debug.apk`로 통일한다. 저장소 폴더와 원격 저장소 이름은 이번 전환 범위에서 유지한다.
- 대안: 표시명만 변경하고 기존 package ID와 하네스 슬러그 유지, 또는 저장소·원격까지 동시에 이름 변경.
- 영향: Android는 기존 `com.foresttales.welllbeing` 설치본의 업데이트가 아니라 별도 앱으로 설치된다. 기존 앱과 데이터를 자동 삭제·마이그레이션하지 않는다. 캐릭터 ID, 자산 경로, 전투 입력 ID, Resource 스키마와 1280×720 런타임 논리 해상도는 유지한다.
- 검증: Godot 설정, Android export preset, APK badging, 스크립트 기본 경로, 15개 하네스 스킬 ID·경로와 활성 문서 링크를 자동 검사한다.
- 대체/롤백: ADR-011의 package ID 부분만 대체한다. 롤백 시 새 package 설치본을 별도로 다루고 ABI·최소 버전 결정은 유지한다.
- 승인 근거: 2026-09-09 사용자가 Forest Arena 브랜드 전환 및 Penpot UI 설계 기반 통합 계획의 구현을 명시 승인.

## ADR-015: 미래 모드·참가 인원·장신구 무등급 규칙

- 상태: accepted
- 날짜: 2026-09-09
- 적용 Phase: 6/7 이후
- 배경: 비전투 UI 설계 계약에는 모드 목록, 파티 슬롯 수와 장신구 표현의 제품 기준이 필요하지만 현재 Phase 0 범위를 확장해서는 안 된다.
- 결정: 미래 제품 모드는 Story, Solo, Team, AI, Practice 다섯 가지다. 한 경기는 최대 8명이며 Team은 팀당 1~4명, 전체 최대 8명이다. 장신구에는 등급·희귀도 체계가 없고 별·색상 테두리·전설/영웅 표기 등 희귀도 위계 표현을 사용하지 않는다.
- 대안: 4인 제한, 고정 4대4, 장신구 희귀도와 등급별 상점 표현.
- 영향: `SCR_*` 비전투 화면과 `IMG/*` 에셋 계약은 이 규칙을 표현한다. Story·AI·Practice의 오프라인 구현은 해당 Phase 수용 기준을 따르고, 온라인·계정·상점·랭크·경제·소셜 기능은 기존 Phase 게이트와 별도 승인 전 구현하지 않는다.
- 검증: UI 계약 테스트가 다섯 모드, 최대 8명, 팀당 1~4명, Splash 캐릭터 금지와 장신구 희귀도 금지를 검사한다.
- 대체/롤백: 참가 규칙 또는 장신구 정책을 바꾸려면 새 ADR로 대체하고 화면·에셋 계약과 소비자를 함께 마이그레이션한다.
- 승인 근거: 2026-09-09 사용자가 Forest Arena 브랜드 전환 및 Penpot UI 설계 기반 통합 계획의 구현을 명시 승인.

## ADR-017: Godot 리소스 역할과 17개 하네스 체계

- 상태: accepted
- 날짜: 2026-09-11
- 적용 Phase: 0 이후
- 배경: Godot 리소스 패키지가 logical ID·품질 변형·Autoload와 이를 소비하는 비전투 UI 역할을 추가하므로 기존 15개 역할 하네스에 명시적 소유권이 필요하다.
- 결정: 기존 15개 역할을 유지하고 `forest-arena-godot-resources`와 `forest-arena-godot-ui`를 정식 역할로 추가해 17개 역할로 운영한다. 기존 `ui`는 제품·터치·Penpot UX를, `godot-ui`는 등록 리소스를 소비하는 Godot 비전투 UI를, `godot-resources`는 registry·품질 변형·Autoload를 소유한다.
- 대안: 두 스킬을 하네스 외 지원 파일로 두거나 기존 UI·contracts 역할에 흡수한다.
- 영향: ADR-014의 15개 스킬 검증 수는 이 결정으로 대체된다. `res://forest_arena/` 카탈로그는 기존 캐릭터·`IMG/*` 승인 계약을 대체하지 않는다.
- 검증: 하네스가 17개 skill ID, 팀 라우팅, `ForestArenaResources` Autoload와 337개 logical asset/22개 품질 의존 asset을 검사한다.
- 대체/롤백: 두 역할과 Autoload를 제거할 때 팀 명세·하네스 검사·AGENTS 리소스 맵을 함께 롤백한다.
- 승인 근거: 2026-09-11 사용자가 Godot 패키지 통합 계획에서 두 스킬을 17개 정식 역할로 취급하도록 선택하고 구현을 승인.

## ADR-018: 14개 역할 하네스 통합과 자동 버전 관리

- 상태: accepted
- 날짜: 2026-09-11
- 적용 Phase: 2 이후
- 배경: Godot UI·캐릭터 모션·버전 관리 역할이 각각 UI·2D 애니메이션·오케스트레이션과 분리되어 책임 경계와 증적 규칙이 중복됐다. 활성 문서에는 Phase 2 상태와 맞지 않는 Phase 0 표현도 남아 있었다.
- 결정: 활성 역할은 14개로 운영한다. `forest-arena-ui`가 Godot 비전투 UI와 `ForestArenaResources` 소비를, `forest-arena-2d-animation`이 승인 캐릭터의 idle·jump·run과 모션별 승인 게이트를, `forest-arena-orchestrator`가 브랜치·관련 commit·push·PR·QA 뒤 `develop` 병합·롤백 증적을 소유한다. 팀 명세의 역할 표가 단일 원본이며 검증기는 그 표에서 실제 스킬 목록을 동적으로 비교한다. 기본 증적은 `00_request.md`와 `04_closeout.md`이고 계약·인수인계·독립 QA 파일은 필요할 때만 추가한다.
- 버전 관리 범위: 사용자의 구현·수정·완료 요청은 일반 작업 브랜치, commit, push, PR과 `develop` 병합 권한을 포함한다. `main` 승격, release/hotfix, 강제 push, 이력 재작성, 원격 브랜치 삭제, 계정·권한·비밀정보 변경은 제외하며 플랫폼 보안 확인은 우회하지 않는다.
- 영향: ADR-017의 활성 17개 역할 운영 결정을 이 ADR로 대체한다. ADR-014와 ADR-017의 당시 수치·승인 근거는 감사 기록으로 보존한다. Godot Autoload·337개 논리 리소스·22개 품질 변형, 외형 승인 경계와 Phase 7 온라인 게이트는 유지한다.
- 검증: `./scripts/verify-harness.sh`, `./scripts/verify.sh`, Godot 리소스 검증, 활성 문서의 제거 역할·고정 역할 수·현재 Phase 0 표현 검사와 `git diff --check`를 실행한다.
- 대체/롤백: 역할을 다시 분리하려면 새 ADR에서 소유권, 스킬, 팀 명세와 동적 검증을 함께 변경한다.
- 승인 근거: 2026-09-11 사용자가 14개 역할 통합, 활성 문서 한국어화, 적응형 증적과 일반 원격 통합 자동 범위를 명시 승인.
