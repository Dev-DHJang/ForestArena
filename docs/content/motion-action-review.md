# 모션의 행위 표현 검토

그림이 파일 규격에 맞는지와 실제로 의도한 행동으로 보이는지는 따로 확인한다. 제작은 `2d-animation`, 독립 검토는 `qa`가 맡는다. 새로 만들거나 수정하는 모든 이동·공격·상태 모션에 적용한다.

## 제작 전과 검토 입력

- 원 요청, 승인 외형과 콘셉트, 모션 ID와 기대 행위, 핵심 자세·방향, 준비·적중·회복 구간을 기록한다.
- 행위는 승인된 전투 문서·공격 계약과 실제 `AttackData`·상태 코드를 대조한다. 이름만 보고 특정 안무를 새 규칙으로 정하지 않는다. 서로 충돌하거나 필요한 동작이 정의되지 않았으면 `redo`로 담당자에게 돌린다.
- 검토 대상 PNG·SpriteFrames·표현 코드·공격 데이터의 해시를 고정한다. 검토 뒤 대상이 바뀌면 그 결과를 재사용하지 않는다.

## 눈으로 확인할 항목

| 모션 | 확인할 행위 |
| --- | --- |
| idle·run | 대기 호흡과 이동이 구별되는가, 달릴 때 다리 교대와 무게 이동이 이어지는가, 마지막에서 처음으로 반복할 때 튀지 않는가 |
| jump | 상승·정점·하강 자세가 구분되는가, 공중에서 지상 착지 자세를 보여 주지 않는가, 실제 착지에서만 착지 자세가 나오는가 |
| 약·강·방향·공중·대시 공격 | 의도한 손·발·꼬리·리본이 쓰이는가, 목표 방향·궤적과 준비→적중→회복이 읽히는가, 강도·연속 공격 단계가 구별되는가 |
| 특수기·궁극기 | 캐릭터별 기술의 특징과 순서가 보이는가, 상승·돌진·끌어오기·쓸기 등 실제 행위와 일치하는가 |
| guard·evade·charge | 막기·피하기·힘 모으기가 구별되는가, 정지시키는 프레임이 해당 자세인가. 차지 ID를 해제 공격에도 쓰면 그 공격 변형도 따로 검토하는가 |
| hitstun·launch·knock_down·wake_up | 맞음·공중으로 밀림·넘어짐·일어남이 구별되고 순서가 자연스러운가 |
| death·ring_out·spawn | 사망·장외 탈락·등장이 서로 구분되는가, 반복·끝 자세가 상태와 맞는가 |

전체 16프레임 비교판, 정상 속도·느린 재생과 실제 게임의 프레임 순서·타이밍을 함께 본다. 좌우 반전, 작은 표시 크기, 외형·실루엣, 잘림도 확인한다. 설명·파일명·메타데이터·이미지 유사도 일치만으로 행위가 맞다고 판정하지 않는다. 반복 프레임이나 가장자리 접촉은 확인할 징후이며 그 자체가 실패는 아니다.

## 도구와 기록

프로젝트 루트에서 실행한다. 이미지 준비에는 Pillow가 필요하다. `python3 -m pip install -r tools/forest_arena/requirements-motion-review.txt`로 검증한 버전을 설치한다. Android 게임에는 이 Python 라이브러리를 넣지 않는다. 도구는 게임용 자산을 수정하지 않는다.

```sh
godot --headless --path . --script res://tools/forest_arena/motion_review_timeline.gd -- --output /absolute/path/timeline.json
python3 tools/forest_arena/review_motion_actions.py prepare --project-root . --timeline /absolute/path/timeline.json --output /absolute/path/review
python3 tools/forest_arena/review_motion_actions.py validate --project-root . --review /absolute/path/review/motion-review.json
```

`prepare`는 manifest의 전체 모션을 열거하고 프레임 비교판·재생 미리보기·검토 양식을 만든다. 실제 표현 코드를 실행해 기록한 timeline(시간별 표시 프레임)을 사용하며 점프 단계·공격 단계·정지 자세를 임의의 균등 재생으로 대신하지 않는다. 전체 프레임 재생은 원화 검토용이고 게임 재생과 구분한다. 비반복 상태의2초 강제 유지, 반복 모션의완전한2주기와 단계별 점프 속도는 검토를 위한 시험 조건이다. 실제 경기 상태의 수명이나 이동 경로를 재현했다고 기록하지 않는다. 짧은 피격 상태는 실제 경직 시간 안에 반응이 읽히는지 별도로 대조한다.

`motion-review.json`에 모션별 기대 행위·근거 문서, 해시, 검토한 자료, 상태, 관찰 근거와 문제 프레임/시간을 기록한다. 기본 상태는 `blocked`이고 사람이 자료를 실제로 보기 전에는 통과하지 않는다. `validate`는 누락·중복·해시 변경·근거 없는 통과를 거부한다. 이 검사는 기록의 완전성을 확인하며 의미 판단을 자동으로 증명하지 않는다. `--require-pass`를 추가하면 수정·설계 확인·미확인 모션이 하나라도 있을 때 실패하므로 사용자 승인 요청 전 통과 조건 검사에 사용한다. `03_qa_rNN.md`에는 담당·검토 방법·집계·미해결과 수정 시안 경로를 요약한다.

## 결과와 수정

- `pass`: 기대 행위를 전체 프레임·재생·게임 타이밍에서 확인했다. 검토 자료와 구체적 관찰을 남긴다.
- `fix`: 기대 행위는 명확하지만 표현이 다르다. 문제 프레임·시간과 필요한 자세 수정을 제작 담당에게 전달한다.
- `redo`: 기대 행위 또는 데이터·문서가 충돌해 설계 확인이 필요하다.
- `blocked`: 파일·도구·필수 검토 자료가 없어 확인하지 못했다.

사용자 승인 요청 전 QA를 수행한다. 수정은 기존 팀 명세처럼 두 회차까지 검토하고 같은 원인이 반복되면 접근을 재분류한다. 수정 시안과 재검토 기록은 `_workspace/<topic>/`에 버전별로 보존한다. 내장 이미지 도구로 시안을 만들고 승인 외형·그림체를 유지한다. QA 통과가 모션별 사용자 승인을 대신하지 않는다. 승인 전 runtime·manifest에 쓰지 않는다. 그림에 맞추려고 전투 시간·피해·판정을 변경하지 않는다.
