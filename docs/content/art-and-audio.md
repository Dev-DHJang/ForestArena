# 05. 콘텐츠·아트·오디오

이미지·애니메이션 용어는 [용어 가이드](../GLOSSARY.md#화면과-그래픽-용어)를 참고한다. 그림과 소리는 전투 결과를 알아보기 쉽게 표현하지만 피해량이나 승패를 계산하지 않는다.

## 제작 원칙

- 전투 가독성이 장식성보다 우선한다.
- AI로 만든 자료와 외부 자산은 제작을 돕는 재료다. 공격 시간, 충돌이나 승패를 정하는 기준으로 쓰지 않는다.
- 최종 캐릭터, 명칭, UI, 효과, 음악과 애니메이션은 독창적으로 제작한다.
- 외부 에셋이 없어도 기본 도형과 임시 신호로 핵심 개발을 계속할 수 있어야 한다.
- 비전투 UI는 밝은 비픽셀 판타지 숲, 하늘색·민트·초록·코발트·따뜻한 금색, 유리·나무·석재 재질의 독창적 시각 방향을 사용한다.
- Splash 배경에는 캐릭터를 넣지 않고 장신구에는 희귀도·등급을 암시하는 장식을 사용하지 않는다.
- 베르디아의 의복·도구는 중세보다 발전한 기계식 기술을 쓸 수 있지만, 총기·자동차·전자기기·현대 통신망은 넣지 않는다. 드문 유물과 특이 현상의 판타지 표현 기준은 [세계관과 중심 이야기](../product/world-and-story.md)를 따른다.

## 3등신 캐릭터 제작 순서

    콘셉트 → 3등신 턴어라운드 → 동작별 키 포즈 → 프레임 제작
    → 스프라이트 시트/아틀라스 → SpriteFrames → 교체 가능한 Godot 시각 래퍼

- 머리 약 1, 몸 약 2의 비율을 출발점으로 삼되 종별 실루엣과 공격 포즈를 우선한다.
- 승인된 캐릭터 목록의 인간형 기준, 반드시 있어야 할 특징, 허용·금지 외형과 작은 화면에서 캐릭터를 구분하는 특징은 `docs/contracts/character-appearance-v01.json`을 최종 기준으로 사용한다.
- 종 모티브는 계약에 명시된 특징만 반영한다. 명시되지 않은 귀·꼬리·모피·동물형 팔다리를 자동으로 추가하지 않는다.
- 보이는 장식적 돌출부와 게임플레이 판정 크기를 동일시하지 않는다.
- 애니메이션은 `AttackData`가 정한 공격 준비·적중·회복 단계를 보여 준다. 그림 프레임 자체가 공격의 적중 여부를 정하지 않는다.
- 이미지 역할은 콘셉트와 정지 이미지를 만들고, 2D 애니메이션 역할은 프레임, 이미지 묶음(아틀라스)과 Godot에서 재생할 연결 정보를 만든다.
- 새 모션의 외형·크기는 [대전 모션용 대표 이미지](combat-character-references.md)의 승인 세트를 직접 첨부해 유지한다. 참조 세트의 승인·해시와 몸 기준 크기를 확인하고, 미승인 후보로 대체하지 않는다.

## 저장과 권리

- 외부 원본, 프로젝트 파생 원본과 런타임 아틀라스 경로를 분리한다.
- 자산 목록 파일(manifest)에는 자산 ID, 만든 곳이나 생성 방법, URL·출처, 확인 날짜·버전, 이용 권리 근거, 파일 확인값(hash), 수정 내용과 사용 위치를 기록한다.
- 무료 표시만으로 상업 이용 권리를 간주하지 않으며 상표·유명 캐릭터·참고 이미지 권리를 별도로 확인한다.

캐릭터 콘셉트의 출처와 권리 기록은 자산 목록인 `assets/character/manifest.json`에 둔다. 각 캐릭터의 이미지, 설정, 능력치와 기술 자리는 해당 `character.tres`에서 함께 관리한다. `user-provided final asset` 표시는 사용자가 파일을 제공했다는 뜻일 뿐, 외부 이용 권리까지 확인됐다는 뜻은 아니다.

자현·묘령·나비·유란의 추가 비전투 개성 콘셉트는 `concept-variant` / `personality`로 구분한다. 각 `concept/personality-v01.md`에서 사용하며 기존 대표 `concept` 네 장과 `CharacterData`·UI·모션 참조는 바꾸지 않는다. 외형 계약의 `non_combat_pose_policy`는 명시된 추가 정지 이미지 네 장의 전투 자세만 제외하며 신체·종 특징·의상·금지 외형과 기존 전투 이미지 규칙은 유지한다. 승인·파일 확인값과 제작 기록은 `_workspace/character-personality-concepts/`에 둔다.

사용자가 승인한 콘셉트와 아직 화면에 연결하지 않은 애니메이션 묶음은 전투 개발 전에 자산 목록과 `CharacterData` 형식을 확인하기 위해 먼저 등록할 수 있다. 등록됐다는 사실만으로 전투 화면에 연결됐거나 그 이미지가 공격 적중을 정한다는 뜻은 아니다.

## Android 성능 한도와 오디오

- 해상도, 애니메이션 이미지 수, 이미지 묶음 크기, 메모리, 프레임당 그리기 요청(draw call), 화면 속 캐릭터 수와 목표 FPS는 실제 기기에서 측정한 뒤 결정 기록으로 정한다.
- 최대 줌아웃에서 종, 직업, 장신구, 공격 준비와 피격을 형태로 구분한다.
- BGM과 SFX는 의미 이벤트를 소비하며 전투 결과를 만들지 않는다.
- 앱 중단·복귀에서 중복 재생을 막고 오디오가 없어도 핵심 상태를 이해할 수 있게 한다.

현재 음악·효과음 목록과 재생·음량 설정은 [음악과 효과음 v01](audio-v01.md)을 따른다.
