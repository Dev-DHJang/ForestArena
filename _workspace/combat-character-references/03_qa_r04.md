- 기준: r03의 해시별 시각 QA, 네 세트에 대한 사용자 발언 `채택한다.`, 외형 계약, 대전 대표 이미지 제작 기준.

## 원본과 등록본의 동일성

이전 승인 대기 커밋(`HEAD`)의 `02_candidates/<character-id>/<view>.png`를 Git에서 바이트로 읽고, 현재 후보 PNG와 새 `assets/character/<character-id>/reference/v01/<view>.png`를 비교했다. **자현·묘령·나비·유란 각 4장, 총16장이 모두 바이트 동일**하다. 각 파일의 SHA-256도 r03 qa.json 및 새 승인 기록의 대상 해시와 일치했다. PNG가 바뀌지 않았으므로 r03 시각 QA의 적용 대상도 동일하다.

각 세트의 후보·정식 reference.json은 approved이며, 이미지 경로를 제외한 images 항목의 기준점·배율·원본·추정 표시가 같다. 정식 경로에서 `validate(..., require_approved=True)`를 실행해 네 세트 모두 오류 없음으로 확인했다.

## 승인·QA·등록표 연결

- `06_approvals/<character-id>.json` 네 파일의 decision은 approved이고 사용자 채택 발언을 기록한다. 각 캐릭터 ID·v01·이미지4장 해시가 해당 qa.json과 정식 reference.json의 승인/QA 연결에 일치한다. 제작 시작 지시를 채택 승인으로 바꾸거나 외형 계약 변경·기존 모션 재생성까지 넓힌 기록은 보지 못했다.
- 기존 manifest130개 항목 전체를 이전 HEAD의 JSON과 대조해 **각 항목이 그대로 유지**됨을 확인했다. 추가16개만 motion-reference이며 전체146개다. 캐릭터·각도·경로·ID·참조 세트·승인/QA 기록의 연결은 새 통합 검사에서도 확인하도록 작성돼 있다.
- 정식 reference.json은 계속 생성 원본과 승인 콘셉트·외형 계약의 해시를 확인한다. 사용자 승인과 독립 QA의 기록 자체도 캐릭터·버전·대상 이미지 해시·근거에 맞춰 대조한다. 이 검사는 기록 정합성을 확인하며 사용자 발언의 진위나 시각 판단을 자동 증명한다는 주장은 하지 않는다.

## 기존 게임 자료 보존

현재 tracked 변경 목록을 확인했고 기존 캐릭터 PNG·모션·CharacterData, `scripts/`, `scenes/`, `forest_arena/`, `docs/contracts/`의 변경은 없었다. 기존 콘셉트/모션 manifest130개 항목도 보존돼 있다. 새 정식 참조 폴더는 제작용이며, 현재 게임에서 선택하는 캐릭터 리소스나 표시 배율을 교체하지 않는다.

## 문서·검사 검토

- 콘텐츠 문서의 네 정식 reference.json 링크와 승인 날짜, 후속 모션 생성 시 PNG 직접 첨부·해시 기록·승인 상태 검사 절차를 확인했다. 새 이미지 세트가 외형 계약이나 전투 판정의 기준을 대체하지 않는다는 설명도 유지된다.
- `RegisteredCatalogTests.test_registered_reference_catalog`는 실제 manifest16개→네 세트→PNG→사용자 승인/QA 연결, 전체 ID 중복, 캐릭터별4각도, 상태·경로·해시·기록 연결을 확인한다. 단위 실패 사례8개와 함께9개 검사라는 범위를 확인했다. 별도 독립 대조에서는 이전 커밋의 바이트와 기존130개 항목 보존까지 확인했다.
- 등록 뒤 전체 검사 결과 `build/verification/20261029-181135-5ad4b9cb/result.json`을 직접 읽었다. status=pass, completed_checks=91/total_checks=91, elapsed_seconds=526.655이며 새 등록 통합 검사를 포함한다. 같은 전체 검사를 이 QA에서 중복 실행하지 않았다. 최종 통합 커밋은 종료 기록에 연결한다.

## 제작 전용 폴더 제외의 최종 확인

- export preset의 `all_resources`를 고려해 새 `assets/character/<character-id>/reference/` 네 곳에만 `.gdignore`를 두었다. 기존 콘셉트·runtime 폴더와 export preset은 변경하지 않았다. 작업 중 생성된 미추적 참조 PNG.import16개만 제거했다는 범위를 확인했다.
- 게임 표현의 `approved_motion_paths`는 manifest의 `animation-runtime`만 선택하고 표시 자료도 `visual_state_id`가 있는 행만 읽는다. 새 motion-reference16개는 둘 다 해당하지 않으며 게임 코드·CharacterData에 새 reference 경로 소비가 없다. Python 파일 검사와 이미지 생성의 참조 파일 접근은 `.gdignore`와 양립한다.
- `build/verification/20261029-reference-production-exclusion/result.json`, `editor-import.log`, `resources.log`를 직접 확인했다. 새 headless editor 스캔과 리소스 검증이 완료됐고 리소스 검증은 `OK: 519 logical assets`다. 네 폴더의 `.gdignore` 존재와 PNG.import 미생성(0개)을 실제 파일 목록으로 다시 확인했다. 에디터 로그의 ADB daemon 연결 실패 안내는 기기 연결 결과이며 이번 로컬 리소스 검증을 기기 통과로 바꾸지 않는다.
- 제외 조치 후 정식 PNG16개 해시가 r03 시각 QA 해시와 계속 일치함을 다시 확인했다. 승인·manifest·기준점의 변경을 동반하는 조치가 아니다.
- 최종 판정은 pass다. 실제 APK 구성원·파일 크기·Android 기기 확인은 수행하지 않았으며, 가져오기 제외의 로컬 확인을 그 결과로 확대하지 않는다.
