## r01 수정 확인

- Wi-Fi/API 일시 실패: 재접속 갱신이 빈 값을 돌려주면 원래 60초 안에서 다시 시도하며 세대 번호로 취소 뒤 늦은 응답을 차단한다. 독립 `./scripts/verify-lan-runtime.sh`에서 LAN_RUNTIME・LAN_APP_FLOW・LAN_RECONNECT_AUTH 모두 PASS, exit 0. 8초 갱신 실패 뒤 다음 시도 성공과 경기 복귀 포함.
- 부분 시작 실패: LAN 프로세스 종료/8초 준비 실패에서 API를 종료하고 PID를 지우는 코드 확인. 정상 종료는 ROOT를 포함한 실행 명령을 확인해 PID 재사용으로 무관한 프로세스를 종료하지 않는다. OS 실행 예외까지의 직접 장애 주입 검사는 미실행이다.
- 결과 닉네임: 고정 participant_names로 두 이름을 표시하는 코드 확인. 실제 API/DB 두 앱의 결과 이름 확인은 생산자 `02_guest_client.md`에 실행 증거가 있고 reviewer는 테스트 구현을 읽었다. 해당 실제 DB 검사는 reviewer가 다시 실행하지 않았다.
- 인증 오류: 서버 authentication_*와 세션 갱신 오류의 한국어 안내 추가 확인.

## 신규 수정 요청

**PF 규칙의 내부 연결 허용:** demo_firewall.py는 en0에서 허용된 LAN 주소만 pass하고 다음 규칙에서 모든 인터페이스의 서버 주소 3001/7778 접속을 차단한다. 서버의 API 준비 확인과 내부 인증 URL은 자기 LAN 주소이며 로컬 경로는 lo0다. 현재 /etc/pf.conf에는 lo0 skip 규칙이 없으므로 PF 적용 뒤 호스트 내부 API도 차단될 수 있다. 최소 lo0 내부 요청 허용을 LAN pass보다 앞에 추가한다. sudo PF 적용은 수행하지 않았다.

## 배포·보안 확인

- package_demo.py는 명시한 APK/PCK・API 소스・lockfile・마이그레이션・init・실행 도구・설치 안내만 포함한다. .env.demo・DB dump・사용자 인증 기록은 포함 경로 밖이다. API 소스/tsconfig/실행 경로는 일치한다.
- DB는 compose에서 127.0.0.1:55433만 공개한다. 환경 파일과 백업 파일은 0600 생성한다. 기존 개발 DB와 별도 볼륨이다.
- 설치 안내는 무료 직접 설치・현재 앱 ID/debug 서명・오프라인 모드・한 경기 1대1・이름 정책・서버 재시작에서 경기 비복원・방화벽 적용/제거・실기기 확인을 구분한다.
- API 500 로그에서 request.url 전체 대신 pathname만 기록하는 보완을 root에 제안했다. URL query에 caller가 넣은 인증정보 노출을 피할 수 있다.
- 실제 최종 ZIP 확인값/비밀값 제외/추출 실행과 Android 설치・업데이트 및 OS 방화벽 차단 검사는 이 기록 시점에 **미실행**. 출시 통과로 추정하지 않는다.
