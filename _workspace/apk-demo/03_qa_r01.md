## 재현 가능한 수정 요청

1. **높음: 일시적인 Wi-Fi 단절이 60초 복귀 기회를 없앰.** `LanMatchClient._open_reconnect()`가 DemoGuestClient.login을 기다린 뒤 빈 토큰이면 바로 authentication_refresh_failed로 종료한다. 경기 중 Wi-Fi를 10초 이상 끄면 1초 뒤 refresh가 시작되고 8초 HTTP timeout에서 방 연결이 종료된다. 명확한 인증 만료와 일시적인 연결 실패를 구분해 후자는 전체 60초 안에서 재시도해야 한다. refresh 재시도 전 저장한 predecessor/successor는 그대로 사용해야 한다.
2. **중간: 부분 시작 실패에 서버가 남음.** demo_server.start에서 API가 준비된 뒤 LAN 서버 실행 실패/8초 준비 timeout이면 API PID/프로세스를 정리하지 않는다. LAN 포트를 다른 프로세스가 점유한 상태에서 start를 실행하고 재시도하면 API가 남아 already running으로 차단된다. 시작 중 새로 실행한 프로세스만 실패 경로에서 정리하고 DB 볼륨은 보존해야 한다.
3. **중간: 결과 화면 닉네임 누락.** `_on_lan_match_finished`는 승패와 사유만 표시한다. 방 참가 때 고정한 participant_names로 두 이름과 승자를 표시하고 변경 화면으로 돌아가기 전까지 동일 이름을 유지해야 한다.
4. **중간: 인증 오류 원문 노출.** 서버가 반환하는 authentication_required/failed/timeout/unavailable와 클라이언트 authentication_refresh_failed는 `_lan_reason_text`에 없어서 영어 코드만 나타난다. 원인과 다시 접속/서버 상태 확인 행동을 쉬운 한국어로 연결해야 한다.
