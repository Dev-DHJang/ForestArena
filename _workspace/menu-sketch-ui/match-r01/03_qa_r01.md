## 전체 시각 검토와 추가 동선 수정 요청

네이티브 PNG 23개 전부(대표3·목록 상태·코드2·만들기2·랭크친구·AI/개인/개인필터/팀/팀준비·오류2·안내·20:9 3)를 각각 직접 확인했다. 대표3개의 1280×720 축소와 `match-review.png` 연락표도 확인했다. 20:9는 중앙 안전 배치를 유지하고 축소에서도 주요 제목·목록·버튼과 예시/미정 문구가 잘리지 않는다. 추가 잘림·겹침·가려짐은 발견하지 못했다.

생산자가 실제 뷰어에서 공통 입력 폼의 취소/뒤로를 점검하며 발견한 반환 동선을 독립 판단했다. 빈 목록→만들기→취소, 팀 필터→코드 입력→취소 등이 진입한 상태 대신 기본 전체 목록으로 돌아간다. 실제 입력·서버를 생략하는 시안 범위와 별개로, 노출된 취소/뒤로의 반환 문맥은 보존해야 한다. 사용자의 뒤로 복귀 검증 요구와 앞서 수정한 필터 문맥 기준에 따라 **수정 필요**로 전달했다. 오버레이 닫기 또는 기원별 반환 상태 등 구현 방식은 생산자가 정하되, 노출된 폼의 취소/뒤로와 만들기→방→나가기까지 해당 목록 문맥으로 돌아오는지 새 뷰어에서 확인한 뒤 최종 판정한다.

## 공통 폼 반환 수정 명세

생산자가 폼·방 상태 20개를 전체 화면 오버레이(기존 목록 위에 여는 화면)로 바꿨다. 최신 명세를 독립 대조한 결과, 20개 모두 overlay이며 내부 코드 예시·개인/팀 선택·방·준비·나가기 확인의 전환은 현재 오버레이를 닫고 다음 것을 여는 `replace-overlay`, 폼 취소/뒤로와 최종 나가기는 `close-overlay`다. 밑의 진입 목록을 다른 목록으로 이동시키는 반환은 없다. 안내/오류는 중첩 오버레이를 한 층 닫아 현재 폼/방을 유지한다. 이러한 명세 조합에서 정적 누락은 없었다.

`overlay-probe.json`에는 같은 클릭의 close-overlay 다음 open-overlay 순서가 기록돼 있다. 생산자는 방 목록→코드→예시→취소 후 오버레이가 없고 원래 목록이 유지됨을 실제 뷰어 probe로 확인했다. 이 수정 방향을 해결책으로 인정하되, 최종 네이티브 감사·개인/팀/빈목록 기원·중첩 안내·준비/나가기·배경 차단의 실제 뷰어 재검증을 완료한 뒤 동선 수정 요청을 해소한다. 배치는 바뀌지 않아 앞선 23개 네이티브 PNG 시각 검토를 재사용할 수 있다.

- 개인선택·팀선택·빈목록에서 코드/만들기 BACK, 만들기→방→준비→시작 안내 닫기→나가기 취소→준비 취소→최종 나가기, 코드→실패 안내 닫기→방→나가기를 확인했다. 모든 전체 화면 전환에서 fullscreenStack=1, 최종 닫기에서0이다. 중간 상태가 누적되거나 기본 전체 목록으로 돌아가지 않는다.
- AI와 일반/개인필터/팀 직접 입장, 준비·나가기의 취소/실행, 중첩 안내 닫기, 배경 버튼 차단, 미정 경기 시작·랭크 파티·초대·자동 매칭 실행 차단, 오류/로딩·검토 안내 복귀 증거가 있다.
- 새 실제 뷰어13PNG를 직접 확인했다. 개인/팀 선택과 빈목록의 복귀 화면, 코드 예시 위 실패 안내, 팀 만들기, 팀/준비/나가기 확인에서 문자·원화·선택 문맥이 정상이다. 일부 녹색 강조는 Penpot 뷰어의 인터랙션 표시이며 제품 색 변경으로 판단하지 않았다.

따라서 공통 입력 폼의 취소/뒤로 반환 문맥 수정 요청을 **해소**한다. 초기 128단계·20개 뷰어PNG는 `history-before-context` 등 수정 전 이력이며 최종 통과에 합산하지 않는다.
