# 캐릭터·신기 묶음 독립 QA r01

2026-11-04. 독립 검토 역할 `collection_qa`. 최종 판정은 **pass — 이번 3종의 Penpot UI 검토 범위**다. 새 화면의 사용자 승인과 Godot 개발 승인을 뜻하지 않는다. 실제 Android 검사는 수행하지 않았다.

## 범위와 방법

- 사용자 승인 계획의 다음 묶음인 캐릭터 기술·캐릭터 스토리·신기 상세(참조19·21·12)를 검토했다. 대표3장 r01의 명시 승인과 새 묶음의 승인 대기를 구분했다.
- `forest-arena-qa/SKILL.md`, 요청·제작 명세·승인표·세계관·묘령 공격 Resource·요요 규칙과 ADR-037·LocalPlayCatalog를 읽었다. 참조3장의 회전 검토 이미지를 직접 보고 설계와 비교했다.
- 실제 새 뷰어의 화면 PNG12개와 네이티브 기술 선택4종, 대표3종의1280×720 축소와2400×1080 비교3개를 직접 시각 검토했다. 실제 이동은 제작자의 새 뷰어37단계 기록을 네이티브 링크 명세와 대조했다. QA가 브라우저에서37단계를 별도로 재실행한 것은 아니다.
- 전체46개 편집 보드는 네이티브 감사 결과와 명세를 검토했다. PNG는 중복 모달 배경을 제외한 선별25개이며 모든46개를 개별 PNG로 내보냈다고 기록하지 않는다.

## 발견과 수정 확인

| 1차 발견 | 수정 뒤 확인 |
| --- | --- |
| 이미 승인된 요요 이미지를 누락 슬롯으로 표시함 | `fa.accessory.pebble.yoyo` 원본을 Penpot미디어로 가져와 실제 표시했다. `yoyo-media.json`과 저장소 PNG의 SHA-256이 일치한다. |
| 요요 장착 후 분류를 바꾸면 철갑옷 장착으로 초기화됨 | 전체·방어·특수·빈 목록과 전체 복귀가 `*-yoyo` 문맥을 유지한다. 철갑옷 재교체 확인/취소도 현재 분류로 돌아간다. 실제 이동 기록과 명세를 확인했다. |
| 시안의 장착 예시와 현재 게임 기능 경계가 불분명할 수 있음 | 각 신기 화면에 설계용 보유 예시를 표시한다. 제작 명세와 실제 전달 보드는 철갑옷의 현재 비활성, 요요의 자현·나비 적용, 묘령 전투 규칙 미변경을 명시한다. 로비 재진입은 기본 예시로 시작하는 시연 범위다. |
| 누락 영상과 실제 로딩·연결 오류의 구별 필요 | 미수록 영상은 “영상 준비 중” 안내로 닫히며 원래 탭·분류·장착 상태로 돌아간다. 로딩·오류는 전달 보드에서 별도로 검토하고, 오류의 재시도는 로딩 예시로 돌아간다. |
| 일부 기술 영상 좌표가8px 격자에서 벗어남 | 최종 명세의 모든 사각형·버튼 x/y 좌표가8px 격자에 맞는다. 철갑옷 이미지 슬롯도1:1로 수정했다. |

## 최종 검증

- `check_spec.py`:46보드, 안전 여백·72px 이상 조작 영역·목적지·모달 배경 비활성·닫기 복귀·승인 경계 **pass**. 대표17보드의 별도 명세 검사도 통과했다.
- `native-audit-final.json`:46보드, 편집 가능한 텍스트1131개, 컴포넌트 인스턴스586개, 크기·좌표·순서·내용·이동·이미지 슬롯·서체·여백 문제0건이다.
- 실제 뷰어 PNG12개에서 기술·스토리1/2·철갑옷·요요·장착 확인/완료·장착 후 빈 목록·영상 안내·전달 보드·로딩·오류의 한글 표시를 확인했다. 텍스트 잘림·겹침을 발견하지 않았다. 선택 상태는 금색 선과 문구로 구분하며 주요 버튼 위계를 유지한다.
- 기술5분류, 스토리 다음/이전·탭 복귀, 요요 장착 확인/취소·분류 유지·철갑옷 재교체, 영상 안내 닫기·오류 재시도를 포함한 실제 뷰어37단계가 모두 통과했다는 기록을 확인했다.
- `export-index.json`의 PNG41개 전부에 대해 파일 크기·픽셀 크기·SHA-256을 독립 계산해 일치를 확인했다. 구성은 네이티브25개+축소3개+연락표1개+실제 뷰어12개다. 대표 축소3개는 최신 네이티브 PNG를 LANCZOS로1280×720 축소한 결과와 픽셀 단위로 같다.20:9 비교3개는2400×1080이며 중앙 내용과 추가 좌우 여백을 유지한다.
- `export-errors.log`에 남은 첫 내보내기500오류는 후속 성공한 PNG와 해시 기록으로 해결됨을 확인했다. 실패 로그를 현재 미완료 출력으로 오인하지 않는다.
- `before.json`과 `preservation-after.json`을 독립 비교했다. 승인 대표17보드의 ID·내용/기하 해시는 모두 정확히 같다. 기존24페이지의 루트1586개 수와 기존 컴포넌트586개 ID 집합도 유지한다. 대표 승인 메타데이터만 추가했으며 시각 원본은 보존했다.
- 묘령 스토리는 현재 세계관 문서의 백평원·독립 조사·기록회·기록인장·자현과의 경계/협력에 맞는다. 옛 Resource의 축제 길잡이 문구를 복사하지 않았다. 약공격4타·방향 특수·철갑옷 수치·요요10초는 기존 데이터와 일치한다.
- `MISSING ASSETS`는 철갑옷 이미지1종과 영상7종, 총8개다. 정확한 슬롯명이 문서와 실제 Penpot전달 보드에 일치한다. 해당 미디어의 완성이나 승인을 주장하지 않는다.
- 새3종의 등록표는 `ready-for-review`, `approval_status=pending`, `runtime_approved=false`다. 저장 버전은 `MENU09 대표 r01 승인 · 캐릭터·신기 r01 검토대기`로 기록됐다.

## 한계와 다음 단계

이번 판정은 추가3종의 UI 구조·편집 원본·시각 출력·프로토타입 검토 통과다. 누락 미디어8종 제작, 나머지15종 설계, 사용자 화면 승인, 실제 게임 기능 연결과 Android 실기기 확인은 별도 단계다. 기본 게임 전체 검사는 생산자가 별도 수행하므로 해당 결과는 마무리 기록을 따른다. 이 QA는 엔진·실기기 검사를 대신하지 않는다.
