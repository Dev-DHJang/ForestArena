## 발견 사항과 수정 확인

1. **장외 경계 통과 tick에도 공격·피격이 가능했다.** 최초 구현은 이동과 타격 계산 뒤에 FALLING_OUT으로 바꿨다. 아래 경계를 넘은 tick에 HP 소진으로 즉시 기회를 잃을 수 있어 타격·몸 충돌 제외 규칙에 맞지 않았다. 현재는 입력 전과 일반 이동 뒤에 낙하 전이를 먼저 처리한다. 실제 step_fixed_tick에서 겹친 활성 공격과 HP1인 두 파이터가 아래 경계를 통과해도 HP·기회를 유지하는 회귀가 추가됐다.
2. **공용 형식의 배수 타입이 달랐다.** 계약 문서는 hitstun_multiplier를 float로 설명하고 실제 Resource는 int였다. 현재 계약을 int로 맞췄다.
3. **0 tick 경직이 음수 상태 전송을 만들 수 있었다.** 경직 면역 또는 직접 0 경직 적용 뒤 첫 tick에서 0→-1로 감소해 새 상태 전송(snapshot)의 int>=0 약속을 어겼다. 현재 감소를 0 이상으로 제한했고, 상태 해제 뒤 snapshot도0을 유지하는 회귀를 추가했다.
4. **낙하 탈락 대기 중 특수기 시계가 멈췄다.** FALLING_OUT 분기가 공통 시간 감소보다 앞에 있어 낙하·비표시 대기만큼 부활 후 특수 대기가 늘어날 수 있었다. 현재 공통 시간 갱신 뒤 낙하를 처리한다. 비표시60 tick 동안 cooldown100→40인 실제 step 회귀를 추가했다.

추가로 기존 검사에서 발견된 거리 동률의 StringName 비교를 문자열 순서로 명시한 변경도 확인했다. 대상 선택·몸 충돌·화면 밖 상대 선택이 같은 ID 순서를 사용한다.
