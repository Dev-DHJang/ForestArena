# 자현 특수기 잔상 r06 독립 검토

2026-10-25. 담당 `afterimage_qa`. **판정 fix: 천의 선명한 연장은 없어졌으나 잔상 방향감이 약하다.** 원화·후보·제품 코드는 이 검토에서 수정하지 않았다. 이 기록은 다음 수정 전 r06 해시에만 해당한다.

## 직접 본 범위

QA·2D 애니메이션 스킬과 `docs/content/motion-action-review.md`, 원 요청의 추가 항목을 읽었다. 원화32장 비교판, 정상 줌1.50과 좌우 반전·작은 줌0.75 실제 영상 각120틱의 전체240틱을 세 장씩 나눈 비교판에서 빠짐없이 확인했다. `qa/afterimage-independent-r06/`에 전체 그림과30/44/64/82틱의1:1 상세 그림을 남겼다.

정상 영상은 QuickTime Player의 정식 로컬파일 열기에서 정상 속도 반복 재생과0.5배속으로 관찰했고 반전소형도 로컬에서 정상 재생했다. 도구 호출 사이 재생 화면은 표본이므로, 연속 동영상의 모든 순간을 육안으로 봤다고 주장하지 않는다. 전 구간의 누락 없는 확인은240틱 비교판과 상태 기록으로 보완했다. IAB 새 탭의 file URL 열기는 프로토콜 정책으로 거절되어 재시도하지 않았다. 브라우저·네트워크를 사용하지 않는 로컬 미디어 열기만 사용했다.

## 관찰과 수정 필요

목에 맨 짧은 천은 원화대로 보존되고, 길게 늘린 천의 흰 무늬·테두리·날카로운 끝은 사라졌다. 현재 및 직전 두 자세에서 흐린 파란 선이 겹치며 준비에는 나타나지 않는다. 회복83틱부터 약해지고88틱 뒤에는 길게 뻗은 흔적이 보이지 않는다. 이전 회복 천의 수직 낙하 문제도 재현되지 않았다.

다만 정상30·44·64·82틱에서 흔적이 숲·수면 배경에 묻혀 공격 방향이 약하다. 특히 반전소형0.75에서 머리 위와 양옆으로 교차하는 잔상은 거의 읽히지 않고 선명한 짧은 원화 목도리가 시선을 주도한다. 원화32장과 착용 연결은 보존하되 흐린 궤적의 폭·명도·대비를 조정하고 짧은 교차를 충분히 보이게 한다. 무늬나 딱딱한 끝을 다시 만들 필요는 없다. 수정 뒤 같은 정상/반전소형 전체 범위를 다시 확인해야 한다.

부모가 전달한 새 사용자 스케치도 직접 봤다. 머리 위와 몸 양옆을 감싸는 여러 푸른 곡선이 교차하는 요청으로 읽힌다. r06은 해당 스케치보다 궤적의 폭·양·감싸는 방향이 부족하다. 스케치에 따른 다음 수정은 이 r06 통과로 대신할 수 없다.

## 코드와 자료 확인

`fighter_attack_effects.gd` SHA-256 `88186b49af4dde154a3681d43e568cd69553ef25517f528504736a82956752a9`를 검토했다. 새 경로는 실제 잡은 손과 각 원화의 목도리 방향을 읽고 무작위·벽시계·피해·경직·승패를 변경하지 않는다. 현재 스프라이트의 좌우 반전을 부착점과 끝점에 함께 적용한다. 준비·피격·공격 종료에는 `_draw`의 단계/animation 조건이 지우고, 회복은 마지막 공격 그림을 기준으로5틱 안에 사라진다. 보이지 않는 손/끝점에서 방향을 만들어내지 않는다. 이 범위에서 필수 코드 수정 결함은 찾지 못했다. 독립 실행한 `tests/two_fighter_vfx.gd`는 PASS다.

두 캡처는 각728검사·120틱, 오류0이다. 상태는12틱 입력 시작,23틱 공격 시작,83틱 회복,107틱 idle로 바뀐다. 공격 구간60틱과 회복24틱을 확인했다. 두 무손실 MKV를 독립적으로 RGBA 전체로 풀어240개 프레임 MD5와 원본 전체 SHA-256을 영수증에 대조했고 모두 일치했다. 캡처 source 해시도 모두 당시 파일과 일치한다. 정확한 영상·상태·코드 해시는 `qa/afterimage-independent-r06/independent-capture-check.json`에 고정했다.

`qa/afterimage-review-r06/motion-review.json`에 fix와 수정 위치를 기록했다. 일반 validate는 PASS, `validate --require-pass`는 `motion decisions are not all pass`로 예상대로 실패한다. 검토 양식의 완전성 검사와 시각 통과를 구분한다.

새32장에 대한 사용자 명시 승인과 런타임 등록은 아직 없다. 실제 Android 기기 검사는 미실행이다. 촬영은 초점 중단을 제외한 검토용 실행이므로 기기 생명주기 통과가 아니다.
