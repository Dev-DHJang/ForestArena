# UI 연결 수정

실기기에서 새 UI가 보이지 않은 이유는 승인 숲빛 v06이 설계·자산 전달 상태로 남아 실제 런타임 자산 목록과 화면 코드에 연결되지 않았기 때문이다. 새 작업 사본에서만 승인 PNG 93개와 기존 투명 자현 로비 PNG 1개를 복사했다. 원본 파일, 기존 캐릭터·모션·UI 자산과 제품 저장 형식은 바꾸지 않았다.

`ForestlightUi`가 논리 ID로 배경·버튼·카드를 읽고 네이티브 글자를 조합한다. 로비의 큰 중앙 캐릭터와 하단 6개 메뉴, 준비의 왼쪽 2×2 캐릭터·오른쪽 조건, 첫 선택·상점·설정·LAN·정지·결과에 실제 연결했다. 원래 버튼 이름과 선택·구매·재대전 콜백을 유지했다. 프리셋·미션·친구는 현재 미구현 안내로 연결했다. 선택·상점·게임 저장과 실제 경기 데이터의 의미는 그대로다.

로비는 1280×720 내용을 화면 가운데 두며 20:9에서는 배경을 확장한다. 준비의 주요 선택·시작·로비 버튼은 16:9에서 스크롤 없이 보인다. 긴 상점·설정·LAN 내용은 스크롤한다. 승인된 어두운 초록 버튼 위의 네이티브 글자는 흰색으로 표시해 대비를 확보했다. 결과·정지 패널은 중앙에 둔다.

root 역할과 나눈 전투 연결: 오프라인·LAN `TouchCommandSource`에 `forestlight_controls=true`를 설정했다. root가 고정 조이스틱·행동 스킨과 main 재시작 스킨을 연결했다. UI 역할은 별도 ForestlightMatchHud로 실제 snapshot의 닉네임·캐릭터·P번호·팀·HP·기회·궁극·가드 카드를 연결하고 이전 readout을 진단용으로 숨겼다. 8명은 4×2 카드로 표시하며 pointer IGNORE로 터치를 가리지 않는다. UI 역할은 전투 상태·판정·오디오 계산을 바꾸지 않았다. 진동 요청은 MISS/IMMUNE을 제외하고 유효 HIT/BLOCK/PERFECT_GUARD/ARMOR에서만 발생하도록 했다. 실제 진동의 권한과 체감은 별도 Android 검사다.

검사 기록은 `build/android-current-fixes/ui-*.log`, 실제 렌더는 `build/android-current-fixes/ui-render/*.png`에 저장한다. 첫 렌더에서 어두운 버튼 문구 대비와 준비 화면의 하단 잘림을 발견해 수정했으며, 전투 스킨 ID 구분자 불일치는 root에 전달해 점 표기로 맞췄다. 원본 SVG 해시와 복사 PNG 해시는 서로 다른 자료이므로 [출처 기록](forestlight-runtime-provenance.json)에서 각각 분리해 보존했다.

- Godot 리소스: 491 논리 자산, 품질별 24개. 기존 high/medium/low 유지.
- LOCAL_AI_APP_FLOW: 네 캐릭터·장신구·전체 모드 참가·결과·재대전 실제 경로 통과.
- BATTLE_MINIMAP_APP_FLOW, AUDIO_APP_FLOW: 기존 연결 통과.
- FORESTLIGHT_RUNTIME headless와 실제 OpenGL/Metal 렌더: 화면·선택·미구현 안내·결과 데이터 보존 통과. 최종 전투 스킨과 1280×720·1600×720 실제 PNG에서 고정 조이스틱/버튼 위치와 fallback 없음 확인. Solo8·Team4대4 실제 모드의 8개 상태 카드가 두 비율에서 미니맵·터치와 겹치지 않고 팀·기회·HP를 읽을 수 있었다. 최소 줌 0.5는 검사에서만 지정했으며 현재 일반 게임 fixed_zoom=1.25는 바꾸지 않았다. 최소 줌에서 배경 바깥 회색 공간은 기존 지형 표시 한계로 남긴다. [렌더 검토 기록](forestlight-render-review.json)에 실제 PNG 해시를 남겼다.
- 문서 검사·git diff --check 통과. 종료 때 기존 ObjectDB/리소스 사용 경고가 남아 로그에 보존한다. 경고를 실기기 통과로 해석하지 않는다.

독립 QA가 같은 2명인 상태에서 기존 파이터 ID가 LAN ID로 바뀌면 카드가 갱신되지 않는 문제를 재현했다. ordered fighter ID 목록이 바뀔 때 카드를 다시 만들고 HP 42/71을 읽는 검사로 수정했다. 닫힌 HUD에 화면 크기 신호가 도착하는 경우와 이전 정지 버튼의 해제된 lambda도 실제 렌더에서 확인해, tree 상태 확인 및 WeakRef·button 종료 시 신호정리로 수정했다. 최종 실제 renderer runtime ERROR 0, FORESTLIGHT_RUNTIME/LOCAL_AI_APP_FLOW 재검사 PASS다. headless 종료의 기존 4개 리소스 사용 경고는 별도 남겨 두었다. UI 제품 코드는 root 통합 전 동결했다. 새 APK 실제 Android 확인은 root가 수행하므로 여기서 기기 통과로 기록하지 않는다.
