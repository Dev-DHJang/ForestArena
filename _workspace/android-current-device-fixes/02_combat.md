# 실제 기기에서 발견한 전투 문제 수정

## 확인한 문제와 범위

사용자는 실패 APK `6b855d25…`의 자현 연습에서 S23과 Tab S5e 모두 방향 유지 중 공격 이동, 피격 경직이 안 보임, 콤보 단절을 보고했다. 사용자 보고는 `manual/8325e1e2b5be4adcb4d46c3f93f415f9/manual-user-results.json`에 보존되어 있다. 이 기록은 해당 APK의 실제 조작 결과이며 새 수정본 기기 통과를 뜻하지 않는다.

`origin/develop`의 전투 컨트롤러와 승인된 공격 데이터를 사용하여 동일 입력을 먼저 재현했다. 검사 이름은 `ANDROID_DEVICE_COMBAT_REGRESSION`이며 원래 전투 코드의 별도 읽기용 사본에서는 37개 조건이 실패했다. 원본 작업 폴더와 실패 APK의 소스·자산·기기에는 쓰지 않았다.

| 현상 | 코드에서 확인한 원인 | 수정 |
| --- | --- | --- |
| 좌우 유지 중 약공격과 연계가 시작되지 않음 | 중립 기본 연계 시작 슬롯이 좌우 방향과 맞지 않는다고 처리됨. 위·아래 약도 기본 연계 시작 ID 목록에 없다는 이유로 거부됨 | 좌우 약은 데이터에 있는 기본 연계 첫 타, 위·아래 약은 해당 방향 기술을 고름. 중간·마지막 연계 타격을 첫 공격으로 고르지 않음 |
| 일반 공격 중 미끄러짐 | 공격이 시작된 뒤에도 직전 RUN 수평 속도를 유지함. 강 차지에서도 늦게 감속함 | 지상 일반 공격·강 차지 시작에서 수평 이동을 멈춤. 명시적인 대시 약과 공중 운동은 보존. 대시 강은 대시를 끝내고 일반 강 차지로 진입 |
| 첫 공격 방향이 직전 바라보는 방향을 사용함 | 같은 tick의 좌우 입력을 받더라도 공격 전에 바라보는 방향이 바뀌지 않음 | 첫 지상 공격에서 좌우를 고정하고 기본 연계 후속타에는 첫 바라보는 방향을 유지 |
| 근접 중립 약 연계의 후속타가 빗나감 | 일반 피격의 수평 넉백이 바닥에서도 줄지 않아 다음 공격 범위를 계속 벗어남. 방향 선택 문제와 별도 재현에서 자현 약 3단 피해가 4/15로 나타남 | 일반 HITSTUN의 바닥 이동에는 기존 고정 tick 지상 감속을 적용. LAUNCH·KNOCK_DOWN의 넉백은 유지. 피해·공격 영역·경직 데이터 값은 바꾸지 않음 |
| 일부 행동이 피격 중 사용 가능 | 궁극기와 발판 통과가 일반 피격 행동 제한보다 먼저 처리됨. 가득 찬 궁극기 게이지는 HITSTUN을 공격으로 바꿈 | 이동 해제는 받되 HITSTUN·LAUNCH·KNOCK_DOWN 중 모든 행동을 제한. 피격 시 공격·예약 입력·차지·가드·회피·대시 상태를 초기화 |
| Solo·Team 탈락자가 다음 tick에 살아 있는 것으로 취급됨 | DEAD와 MATCH_ENDED가 일반 이동 코드로 흘러가 FALL/RUN으로 바뀜. 이후 밖으로 떨어질 때 기회가 음수로 감소함 | 종료된 파이터는 이동·행동을 멈춘 채 종료 상태 유지. 반복 기회 상실과 종료된 파이터의 링아웃 이벤트 제외. 재대전에서 이전 대시·공격 단계·적중 상태도 초기화 |

피격 경직 자체가 항상 없었던 것은 아니다. 기존 일반 적중에는 공격 데이터와 무게에 따른 19 tick 안팎의 HITSTUN이 있다. 사용자에게 경직이 보이지 않았던 현상의 전체 원인은 표현 연결과 새 APK의 실제 화면도 확인해야 한다. 이 수정에서는 실제 상태·행동 불가 기간과 궁극기 우회 결함을 검증했다.

## 검사와 증거

새 검사에서는 일반 지상 공격·차지 중 X 이동 0, 공격 회복 뒤 유지 방향 이동 복귀, 대시 약의 의도된 이동, 대시 강 차지, 위·아래 약, 첫 좌우 방향 고정, 피격 중 행동 제한과 데이터에 따른 경직 종료를 확인한다. 기존 입력 예약 시간 안에 실제 PRESS 세 번을 전달하고 실제 공격 영역·HitResolver·HP 변화로 자현 3단이 적중하는지도 검사한다.

네 캐릭터의 승인 데이터에서 각각 자현 3단/15 피해, 묘령 4단/19 피해, 나비 2단/11 피해, 유란 3단/15 피해를 확인했다. 각 입력을 같은 초기 상태에서 두 번 실행했을 때 최종 snapshot 해시가 일치했다. 자동 접근이나 피해 합계에 맞춘 추가 적중은 넣지 않았다. 공격 데이터와 화면 표현은 적중을 계산하는 데 섞지 않았다.

8인 Solo와 4대4 Team에서는 탈락자 DEAD/0이 후속 10 tick에도 유지되고 반복 링아웃으로 음수가 되지 않는지, 최종 생존자 또는 팀의 결과가 나오는지 확인했다. 이는 경기 참가·승리 계산의 코드 검사이며 실제 APK의 모드 전체 흐름 재검사는 별도로 수행한다.

| 실행 | 결과 |

실행 로그는 `build/android-current-fixes/combat-baseline-final.log`, `combat-after.log`와 각 검사 이름의 `.log`에 있다. Godot 4.7.1을 사용했다. 새 전투 검사는 수백 tick을 같은 headless 프레임에서 계산하므로 음성 재생을 저장 없이 음소거하며, 오디오·진동 통과로 사용하지 않는다. 새 검사 로그에는 스크립트 오류와 종료 시 오디오 객체 경고가 없다. 일부 기존 검사의 종료 정리 경고는 원래 로그에 보존했다.

## 인계와 남은 검사

변경 파일은 `scripts/fighter_controller.gd`, `scripts/combo_controller.gd`, `scripts/match_controller.gd`, 새 검사와 UID 및 이 기록이다. `CombatIntent`, AttackData/MoveSetData, 60Hz 설정, 원본 Resource, 승인 PNG/SpriteFrames, 화면·소리·진동 코드는 바꾸지 않았다. `_start_attack`의 마지막 선택 인자는 기본값이 있어 기존 세 인자 호출과 호환된다.

새 APK에서 실제 방향+약/강/특수, 자현 기본 3단 적중과 피격 화면, Solo·Team 결과·재대전을 다시 확인한다. 실제 두 손가락 조작·느껴지는 피격 경직은 기기별 사용자 재검사 결과가 있어야 통과로 기록한다.
