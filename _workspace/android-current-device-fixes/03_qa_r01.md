# 현재 실기기 문제 수정 독립 품질 확인 · 1회차

2026-10-12, Godot 4.7.1, `codex/android-current-device-fixes` 작업 사본에서 확인했다. 요청·공용 약속·전투·모션·UI 생산자 기록과 실제 소비 코드를 읽었다. 원본 폴더·실패 APK·기기·ADB·실행 중인 서버는 조작하지 않았다.

현재 코드 판정은 **pass**다. 최초 확인에서 새 HUD의 LAN 참가자 ID 교체와 장면 제거 뒤 크기 신호 오류를 독립 재현해 **fix**로 전달했고, 생산자가 수정한 뒤 동일 재현과 영향 범위를 재검사해 통과했다. 통합 전체 검사와 새 APK의 실기기 재검사는 아직 **미실행**이다.

## 사용자 실패와 새 검사 구분

이전 APK `6b855d25aa5376f4b24958ce985e1c88cad21b6f0df5bdb1e82c8b613a3d092f`의 `manual/8325e1e2b5be4adcb4d46c3f93f415f9/manual-user-results.json`을 읽었다. S23과 Tab S5e 모두 일반 공격 중 이동, 모션 크기 혼재, 새 UI 미반영, 피격 경직·콤보 문제, BGM·효과음·진동 부재를 사람이 보고했다. 자동 입력은 꺼져 있었다. 사람의 방향+회피 결과는 별도로 미확인이다. 이 실패를 코드 검사 통과로 덮어쓰지 않는다.

## 표시와 승인 자산 확인

`build/motion-size-review/<캐릭터>-godot-f00.png`, `-f08.png`, `-f15.png`의 네 캐릭터 12판을 직접 읽었다. 원래 과확대된 자현의 charge·피격·회피와 작은 약 1단의 몸 크기 차이가 줄었다. 눕기·도약 자세와 무기·귀·꼬리의 자연스러운 범위를 서 있는 전체 높이로 강제 확대하지 않았다. 0·8·15 프레임만 확인했으므로 16프레임 전수의 미적 품질 통과를 주장하지 않는다. 실제 기기에서 모션 전환과 가독성을 확인해야 한다.

승인 manifest의 실제 `path`, `sprite_frames_path`를 순회해 원본 작업 폴더와 PNG 120개·SpriteFrames 120개의 바이트를 직접 비교했다. 차이 0이며 manifest 바이트도 같다. 각 PNG의 SHA-256이 manifest와 일치한다. 표시 배율 JSON과 표현 코드만 바뀌고 승인 그림은 보존되어 있다.

실제 UI PNG의 첫 선택·로비·준비·상점·설정·LAN 메뉴·결과와 1280×720/1600×720 전투를 직접 읽었다. 승인 숲빛 배경·버튼·선택 카드가 실제 네이티브 글자와 조합되고 준비의 선택·시작·로비 버튼이 화면 안에 있다. 긴 상점·설정은 스크롤 영역이다. 최신 HUD 생산자 작업은 별도 완료 후 다시 확인한다.

## 발견한 결함과 재검사

`ForestlightMatchHud.update_snapshot`이 참가자 개수만 비교해 카드를 재생성한다. LAN은 장면 초기화에서 만들어진 `ja-hyun`/`training-dummy`를 `lan_host`/`lan_guest`로 바꾸지만 참가자 수는 2명 그대로다. 따라서 새 ID의 HP·기회 갱신을 건너뛴다.

독립 재현 `build/android-current-fixes/qa/hud_id_replacement.gd`는 초기 2명 뒤 같은 수의 LAN 2명으로 교체하고 HP 42/71을 읽도록 했다. `hud_id_replacement-before.log`에서 `FAIL cards=["ja-hyun", "training-dummy"]`, 종료 코드 1을 확인했다. 생산자에게 ID 목록 변경도 재생성 조건으로 처리하고 같은 개수 ID 교체 검사 추가를 요청했다. 수정 후 같은 재현과 실제 LAN 흐름을 다시 검사한다.

수정 후 2회차: HUD가 순서 있는 참가자 ID 목록을 비교해 재생성하도록 바뀌었다. 동일 독립 재현 `hud_id_replacement-after.log`에서 `PASS cards=["lan_host", "lan_guest"]`, HP 42/71, 종료 코드 0을 확인했다. 실제 `forestlight_runtime`에도 같은 개수 ID 교체·HP 변화·전투 snapshot 불변 검사가 추가되어 통과했다.

추가로 `forestlight_runtime-after.log`는 PASS/종료 코드 0인데도 경기 종료 후 화면 크기를 바꿀 때 `!is_inside_tree()` 실행 오류가 있었다. 이전 HUD가 tree에서 제거되고 queue_free를 기다리는 사이 viewport 크기 신호가 `_layout`을 호출했다. 생산자에게 별도 수정 요청했고 `_layout`에 tree 존재 확인이 추가됐다. 같은 모드 닫기·화면 크기 변경 경로의 `forestlight_runtime-final.log`에서 PASS/종료 코드 0, 해당 실행 오류와 SCRIPT ERROR 0을 확인했다. 기존 종료 정리 경고는 따로 남는다.

새 8인 Solo·4대4 Team의 실제 PNG와 1.3배 텍스트 PNG를 읽었다. 8명 캐릭터·닉네임·팀·HP·기회·궁극/가드 카드가 구분되고 미니맵과 조작 버튼 영역을 침범하지 않는다. 최소 줌에서 캐릭터의 실제 기기 가독성은 수동 재검사로 남긴다.

LAN 재접속은 `lan_resume_pending.gd`를 독립 실행해 PASS/종료 코드 0, SCRIPT ERROR 및 ERROR 0을 확인했다. 실제 server/client 메서드를 사용하고 인증된 참가자·정상 토큰이 기존 연결을 기다릴 때만 재시도하며 슬롯을 탈취하지 않는지, 잘못된 토큰은 거절되는지, 끊김 처리 뒤 동일 슬롯·joined 응답·입력 순번 초기화, client 입력 해제·1초 재시도·기존 60초 기한 불연장·기한 만료 종료를 검사한다. 분리된 합성 fixture이며 실제 Wi-Fi 복구 통과로 확대하지 않는다.
