# 기존 LAN 재접속 경합 보완

ADR-028의 승인된 같은 Wi-Fi 1대1 복구 범위만 보완한다. 실제 이전 APK의 사용자 Wi-Fi 10초 뒤 LAN 메뉴 복귀와 resume_rejected는 보존했다. 당시 서버 상태·요청 시각·토큰 비교가 없어 직접 원인을 확정하지 않는다.

독립 검사는 같은 유효한 검사 토큰으로 복귀하려고 할 때 기존 서버 슬롯이 아직 connected=true면 거절하고, false가 된 뒤에는 같은 슬롯에 복귀하는 경합 경로를 재현했다. 새 protocol_version 2 서버는 이미 API 인증된 같은 참가자·맞는 재접속 토큰에 한해 resume_pending을 보낸다. 기존 소켓·슬롯·입력을 빼앗지 않는다.

재접속 중 클라이언트는 resume_pending을 받으면 입력을 풀고 1초 뒤 같은 참가자로 다시 요청한다. 처음 정한 60초 제한을 연장하지 않는다. 잘못된 토큰·기한 만료·다른 사용자·일반 참가 오류는 계속 실패로 처리하며 새 게스트를 만들지 않는다. 정식 인터넷 온라인과 4인 온라인은 추가하지 않았다.

LAN_RESUME_PENDING은 소켓을 실제로 열지 않는 격리된 Godot fixture로 슬롯 보존, 잘못된 토큰 거절, 이후 정상 같은 슬롯/순번 복구, 클라이언트 대기와 입력 해제, 고정된 제한 시간, 일반 실패를 검사한다. 처음 fixture에서 nickname을 빠뜨려 스크립트 오류와 pass 문구가 함께 나온 기록은 통과 근거로 쓰지 않았다. 필요한 샘플을 채우고 정상 joined 응답도 검사했으며 스크립트 오류가 없는 종료 0을 확인했다. 실제 서버·두 APK 재검사는 새 APK 생성 뒤 수행한다.
