# 제품 문서 변경 기록

## 독자 기준

- 대상 독자는 소프트웨어 개발 경험은 충분하지만 게임 개발 경험은 적다.
- 일반 개발 개념을 다시 가르치기보다, 게임 개발에서 다른 뜻으로 쓰는 말과 Godot 고유 개념을 설명한다.
- 문장을 읽기 위해 용어집을 계속 오가게 하지 않는다. 본문에서 쉬운 뜻을 먼저 쓰고, 더 정확한 이름을 찾을 때 용어 가이드를 사용한다.

## 적용한 기준

- `권위`는 `실제 결과를 정한다`로 풀어 썼다.
- `로드아웃`은 첫 설명에서 `캐릭터 + 직업 + 장신구 조합`으로 풀어 썼다.
- `런타임 주입`은 `게임 시작 시 데이터를 합쳐 적용`으로 풀어 썼다.
- `수용 기준`은 `완료 조건`, `회귀`는 `기존 기능 재검사`, `게이트`는 `다음 단계 조건`으로 바꿨다.
- `AttackData`, `Resource`, `Area2D`처럼 코드나 Godot에서 검색할 이름은 그대로 두고 한 줄 역할을 붙였다.

## 의미를 바꾸지 않은 항목

- 현재 Phase 2 완료 상태
- Phase 3 이후 기능 제한과 Phase 7 온라인 제한
- 3 stock, 링아웃, 공격·피격 판정 규칙
- 데이터 ID, JSON 필드, 클래스명과 파일 경로
- 기존 세계관 문서와 제안 상태의 ADR-019

## 문서 구조

- `README.md`: 프로젝트와 현재 상태를 쉬운 문장으로 요약하고 용어 가이드로 연결한다.
- `docs/GLOSSARY.md`: 프로젝트 진행, 전투, 화면·그래픽, Godot·데이터, 테스트 용어와 코드 이름을 주제별로 설명한다.
- `docs/01`~`docs/07`: 각 문서에서 자주 쓰는 용어를 쉬운 표현으로 바꾸고 필요한 곳에서 가이드로 연결한다.
- Godot 리소스와 Penpot 안내: 도구 고유 이름의 첫 등장에 역할을 설명한다.

## 수동 확인 항목

`초보 개발자 문서 읽기 검사`에서 다음 질문에 전문 용어를 미리 알지 않고 답할 수 있어야 한다.

1. 지금까지 구현된 범위는 어디까지인가?
2. 한 판용 전투 데이터는 무엇을 합쳐 만드는가?
3. 그림과 애니메이션이 공격 적중을 결정하는가?
4. Phase 3과 Phase 7 전에 만들면 안 되는 것은 무엇인가?
5. 낯선 코드 이름과 테스트 상태는 어디서 찾는가?
