# 요청: 문서 용어 쉽게 쓰기

## 목표

게임 개발 경험이 적은 10년 차 소프트웨어 개발자가 Forest Arena 문서를 한 번에 이해할 수 있도록 모호한 표현과 설명 없는 게임 개발 용어를 줄인다.

## 현재 단계

Phase 2 완료 상태를 유지한다. 이 작업은 문서 표현만 바꾸며 게임 규칙, 코드, 데이터 형식과 개발 단계는 바꾸지 않는다.

## 범위

- README와 `docs/01`~`docs/07`의 첫 진입 문구를 쉽게 쓴다.
- 자주 쓰는 게임·Godot·프로젝트 운영 용어를 한 문서에서 설명한다.
- 코드 이름이나 업계 표준 용어를 유지해야 할 때는 첫 등장에 한국어 설명을 붙인다.
- 앞으로 쓸 문서의 용어 작성 원칙을 정한다.

## 제외

- JSON 필드, 클래스명, 파일명, 리소스 ID 변경
- 확정된 전투 규칙, Phase 범위와 ADR 상태 변경
- 게임 코드와 에셋 변경

## 반드시 지킬 조건

- 쉬운 표현으로 바꾸더라도 기술적 의미가 달라지지 않아야 한다.
- 검색과 코드 대조에 필요한 고유 이름은 백틱으로 보존한다.
- 현재 작업 폴더의 기존 세계관 관련 변경을 덮어쓰지 않는다.

## 완료 판단 조건

- README에서 현재 상태와 다음 작업을 게임 개발 용어 없이도 이해할 수 있다.
- 용어 가이드가 자주 쓰는 게임, Godot, 테스트, 운영 용어를 설명한다.
- 핵심 문서가 용어 가이드를 안내하고 쉬운 표현을 우선 사용한다.
- 문서 링크와 저장소 기본 검증이 통과한다.
