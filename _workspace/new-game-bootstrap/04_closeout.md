# 새 게임 사전 구성 지침서 마무리

## 현재 상태

문서 작성과 수동 검토 완료. 원래 작업 폴더의 전체 검사는 마지막 문서 조건에서 실패해 별도 작업 폴더에서 다시 실행 중.

## 변경 파일

- `docs/operations/new-game-bootstrap.md`: 단독 전달용 입력 양식, 핵심 문서·스킬 템플릿, 역할 선택, 순차 구성, 선택 구성, 검사 규칙, 완료 보고와 참고 경험.
- `docs/INDEX.md`: 새 지침서 연결 행 추가. 기존 세션 복구 관련 변경은 유지.
- `_workspace/new-game-bootstrap/00_request.md`, 이 파일: 범위·완료 조건과 실제 결과 기록.
- 기존 게임 코드·스킬은 변경하지 않았다. 문서 검사에서 걸린 `docs/.DS_Store`는 macOS 메타데이터라 제거했다.

## 이름 있는 수동 검토

`bootstrap-standalone-review`: 1~7절만 읽어 시작 요청·입력·필수 파일·최소 스킬·역할·작업 순서·검사 생성·마무리 방법을 찾을 수 있음을 확인했다. 외부 근거 링크는 8절 참고 자료로 분리했다. 도구 설치·계정 연결·원격 변경을 기본 요청에서 분리했고 이름·ID·명령 치환과 금지 식별자를 명시했다.

`bootstrap-six-scenarios`: 다음은 지침서의 절차 검토이며, 새 저장소를 실제 구성하거나 생성할 검사 도구의 실패 탐지를 실행한 결과는 아니다.

| 상황 | 검토 결과 |
| --- | --- |
| 빈 프로젝트 | 입력 확인 후 공통 문서·최소 workflow 스킬·구조 검사를 생성하도록 명시 |
| 기존 프로젝트 | 유지·보완·생성·충돌 목록, 기존 경로·결정·사용자 변경 보존 명시 |
| 엔진 미정 | 제안 상태로 공통 구성을 완료하고 엔진 전용 파일·설치·실행을 강제하지 않음 |
| 선택 도구 없음 | 로컬 파일·Python 3 기반 검사, 임시 자산 계획으로 진행 가능 |
| 구성 재실행 | 중복 역할·스킬·결정 방지, 기존 승인 보존, 같은 작업 기록에 날짜별 추가 명시 |
| 필수 파일 누락 | 누락 경로 출력·실패·복원 후 재검사 규칙, 링크·스킬·ID의 실패 표본 명시 |

검토 중 검사 전에 `04_closeout.md`가 필요한 순서 문제를 발견했다. 검사 단계에서 `검사 진행 중` 상태로 먼저 작성한 뒤 결과를 확정하도록 고쳤다.

## 미실행과 다음 작업

- 실제 새 게임 초기 구성과 생성될 검사 도구의 표본 실행은 이번 문서 작성 범위가 아니다. 지침서 실행자가 임시 폴더에서 수행하도록 절차를 적었다.
- Android 에뮬레이터·물리 기기 검사는 문서 추가 작업에 해당하지 않는다. 게임·기기 통과를 새로 주장하지 않는다.
- 지침서 기본값의 미정 결정은 없다. 새 게임의 이름·엔진·플랫폼 등은 해당 프로젝트 사용자의 입력으로 정한다.
- 다음 작업: 이 문서와 입력 양식을 새 프로젝트 Codex에 전달해 사전 구성을 수행한다.

## 버전 관리

- GitHub CLI에는 로그인된 호스트가 없었지만 기존 Git 인증으로 push 사전 확인과 GitHub API 접근이 가능했다. 기존 인증을 프로세스 안에서만 재사용했으며 계정 연결·비밀정보 저장은 변경하지 않았다.
- 최신 `origin/develop`을 조회·fetch하고 별도 작업 폴더 `/Users/jdh/.codex/worktrees/new-game-bootstrap/ForestTales`에 `docs/new-game-bootstrap` 브랜치를 만들었다.
- 색인은 이번 추가 행만 복사했고 다른 사용자 변경은 커밋 대상에서 제외한다.
- 별도 작업 폴더의 전체 검사 완료 뒤 이번 문서·기록만 commit·push하고 PR을 생성할 예정이다.
