# 제품 문서 정리 결과

## 독자 기준

- 문서 이름보다 독자가 가진 질문을 먼저 기준으로 삼았다.
- 게임 개발 경험이 적어도 `무엇을 만드는가`, `지금 어디까지인가`, `다음에 무엇을 하는가`를 먼저 찾을 수 있게 했다.
- 문서 번호를 외우지 않아도 되도록 제품, 게임플레이, 공용 데이터, 엔지니어링, 콘텐츠, UI, 작업 운영으로 분류했다.

## 읽는 순서

`README → 제품 방향 → 개발 순서 → 전투 규칙 → 현재 작업 상태`를 처음 읽는 기본 경로로 정했다.

필요한 정보만 찾는 경우에는 `docs/INDEX.md`의 `목적별 문서` 표에서 질문에 맞는 문서로 바로 이동한다.

## 쉬운 문장 규칙

- 행동과 결과를 전문 용어보다 먼저 쓴다.
- 코드 이름은 번역하지 않고 첫 등장에 역할을 설명한다.
- 여러 문서에서 반복되는 전문 용어는 `docs/GLOSSARY.md`에 한 번만 설명한다.
- 문서 변경 뒤 `./scripts/verify-docs.sh`로 위치, 링크와 작성 규칙을 확인한다.

## 제품 의미 보존

- 현재 Phase 2 완료 상태와 Phase 3 이후 순서는 바꾸지 않았다.
- 전투, 로드아웃, UI, 세계관과 Android 기준은 바꾸지 않았다.
- 승인된 결정과 제안 상태의 결정 내용은 바꾸지 않았다.
