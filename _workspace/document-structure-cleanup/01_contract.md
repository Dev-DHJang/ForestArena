# 문서 경로 변경 약속

## 변경 성격

문서 내용과 JSON 데이터 형식은 유지하고 파일 위치만 목적별 폴더로 옮긴다. 저장소 안에서 이전 경로를 읽는 모든 문서, 스킬, 코드와 검사 스크립트는 같은 변경에서 새 경로로 갱신한다.

## 최상위 분류

| 폴더 | 내용 |
| --- | --- |
| `docs/product/` | 제품 방향, 개발 순서, 세계관, 승인 결정 |
| `docs/gameplay/` | 전투 규칙과 사용자 경험 |
| `docs/contracts/` | 프로그램이 읽거나 검사하는 공용 JSON 형식 |
| `docs/engineering/` | 코드 구조와 Godot 설정 |
| `docs/content/` | 캐릭터·이미지·애니메이션·오디오 제작 원칙 |
| `docs/ui/` | 비전투 화면 데이터와 Penpot 설계 기준 |
| `docs/operations/` | AI 작업 절차, 역할과 현재 운영 상태 |

## 호환성 처리

- 이전 경로에 복제본이나 연결 파일을 남기지 않는다. 두 파일 중 무엇이 최종 원본인지 다시 모호해지는 일을 막기 위해서다.
- 새 경로 전체 목록과 이전→새 경로 표는 `docs/INDEX.md`에 둔다.
- 과거 `_workspace` 기록 안의 경로는 당시 증거로 보존한다. 활성 파일 검사에서는 제외한다.

## 내용 불변

- `attack-system-v01.json`과 `character-appearance-v01.json`의 바이트 내용은 이동 전후 같아야 한다.
- 코드 식별자와 논리 ID는 바꾸지 않는다.
- 상대 링크는 새 파일 위치를 기준으로 다시 계산한다.

## 실패와 되돌리기

- 이전 경로가 활성 파일에 남거나 상대 링크가 끊기면 완료하지 않는다.
- 되돌릴 때는 이동표를 역순으로 적용하고 같은 변경에서 갱신한 경로 참조를 함께 복원한다.
