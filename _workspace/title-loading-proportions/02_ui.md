# 타이틀과 화면 이동 구현

## 시작 화면

- 실제 시작 장면은 `scenes/startup_title.tscn`이다. 기존 게임 장면을 바로 불러오지 않고, 네이티브 로고·하단 진행바·안내부터 표시한다.
- `UiResourcePreparer`가 등록된 타이틀 배경, 메뉴 글꼴, 공통 숲빛 UI, 대전 장면의 기본 의존 파일을 별도 스레드에서 읽는다. 읽은 자원은 `retained`에 계속 보관해 이후 동기 메뉴 조립에서 다시 읽지 않도록 한다.
- Godot에서 전역 게임 클래스가 서로 참조하는 앱 스크립트는 기본 장면 준비 뒤 메인 스레드에서 컴파일한다. 캐릭터 모션 전체는 이 단계에 읽지 않는다.
- 카탈로그를 만드는 앱 인스턴스까지 준비하면 진행률을 완료하고 `게임 시작`으로 바꾼다. 이때 앱은 아직 장면 트리에 없으므로 DB·LAN·메뉴 HTTP 클라이언트는 실행되지 않는다.
- 준비 중 누르고 있던 터치는 무시한다. 완료 후 새 터치, 마우스 왼쪽 클릭, 데스크톱 확인 입력으로 한 번만 기존 신규·로비·저장 오류·DB 복원 경로를 실행한다.
- 버전은 `ProjectSettings.get_setting_with_override("application/config/version")`에서 읽는다. 일반 빌드는 0.0.1이며 Demo 빌드는 기존 사용자 지정 기능 `demo`의 0.1.0-demo 설정을 따른다. 저작권은 네이티브 텍스트로 표시한다.
- Noto Sans KR 가변 글꼴의 굵기 650과 시작 문구·저작권 뒤 어두운 둥근 바탕으로 밝은 배경에서도 읽기 쉽게 했다. 기기 하단 안전 영역을 반영한다.

## 화면 이동

- 실제 타이틀에서 만든 앱만 `async_navigation`을 켠다. 기존 `local_ai_app.tscn`을 직접 사용하는 전투·흐름 검사는 동기 호출 방식을 유지한다. 실제 시작 장면은 별도 검사로 확인한다.
- 공통 `ScreenTransition`은 이동 요청 즉시 입력을 막고, 150ms가 지나면 중앙 진행바와 어두운 덮개를 표시한다. 진행률을 알 수 없는 단계는 움직이는 막대로 표현하며, 실제 파일 준비 값이 도착하면 그 값을 표시한다.
- 목적 화면 자원을 먼저 준비하고 화면을 조립한다. 한 프레임의 배치가 끝난 뒤 덮개를 제거한다. 빠른 이동에는 막대가 보이지 않는다. 같은 화면 옵션 변경과 일시정지·계속하기는 이동으로 처리하지 않는다.
- 프리미엄 메뉴 라우터의 진입·이전 메뉴 이동도 같은 관리자를 쓴다. 필터·설정 초안·목록 갱신은 기존 화면 갱신을 유지한다.
- 대전 진입·재대전에는 선택된 모든 참가자의 승인 모션을 먼저 읽어 보관한다. 준비 중 새 전투 장면은 만들지 않으며, 장면 조립 후에도 화면 표시 준비가 끝날 때까지 노드 처리를 멈춘다. LAN 대전은 기존대로 서버 스냅샷을 기다린다.
- 중복 사용자 요청은 거부한다. DB 연결 완료와 LAN 방 준비·방 생성·결과 같은 자동 알림은 가장 최근 이동 요청을 보관했다가 현재 이동 완료 뒤 실행한다. 이전 경기의 늦은 결과는 경기 객체도 확인한다.
- 준비 실패에는 재시도·이전 화면을 제공한다. 이전 화면이 없는 최초 진입 실패는 이전 화면 버튼을 끄고 재시도를 유지한다. 취소된 작업이나 종료된 화면의 늦은 완료는 새 화면을 만들지 못한다.

## Android 검사 도구

- 디버그 QA 실행에서 타이틀은 별도 `startup.json`에 준비 상태만 기록한다. 기존 사용자 프로필을 읽거나 바꾸지 않는다.
- Android fleet 도구는 준비 완료를 기다린 뒤 실제 화면 크기에 맞는 ADB 터치를 보내고, 이후 기존 앱 진단으로 연결한다. 로컬 AI 셸 검사도 `FOREST_ARENA_TITLE_READY`를 기다린 뒤 실제 터치를 보낸다.
- 에뮬레이터 검사 진입 스크립트는 새 시작 장면을 기존 로컬 AI 흐름으로 연결한다.

## 확인한 결과

- `tests/title_loading_flow.gd`: 73개 검사 통과. 실제 타이틀 진입·버전/Android 내보내기 일치·누른 채 대기 입력 차단·중복 시작·신규/기존 사용자·파일 실패/재시도·선택 모션 보관·150ms 전후 표시·중복 요청·취소 후 늦은 완료·실패 후 재시도/복귀·불러오는 중 종료를 확인했다.
- 같은 검사에서 화면 이동 중 DB 완료와 실제 LAN 방 준비 알림을 보내고, 로비 또는 멈춘 LAN 전투 장면까지 이어지는지 확인했다.
- 호스트 Android fleet 단위 검사: 126개 통과. 타이틀이 준비된 뒤 실제 터치를 보내야 앱 진단으로 넘어가는 항목을 추가했다.
- 기존 `local_ai_app_flow.gd`와 Godot 논리 자산 검사(519개) 통과. 독립 QA가 16:9·20:9 실제 네이티브 렌더와 밝은 배경 위 문구 가독성을 확인했다.
- 최신 집중 검사 로그: `ui-title-loading-flow.log`. 전체 검사와 최종 결과는 마무리 기록에 합친다. Android 실제 기기는 연결되지 않아 기기 통과로 기록하지 않는다.
