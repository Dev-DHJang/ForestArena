# 독립 QA 2차 — 타이틀·화면 전환 통과, 캐릭터 시안 검토 대기

2026-10-16. 기준: 승인 계획, `00_request.md`, `01_contract.md`, UI·리소스·애니메이션 역할 지침. 1차 발견 사항의 수정 뒤 영향 범위를 다시 확인했다.

## 판정과 한계

- **pass — 데스크톱 타이틀·화면 전환 구현**: 독립 실제 렌더 검사 34항목과 제품 전용 자동 검사 70항목 통과. 현재 검토 범위에서 남은 코드 수정 요구 없음.
- **검토용 산출물 pass / 게임 반영 대기 — 머리 비율**: 묘령 기존 대기 시안과 나비·유란 새 대기 시안은 사용자에게 제시할 수 있다. 90모션 재제작·게임 등록 완료를 뜻하지 않는다. 사용자 승인 전 런타임 등록을 하지 않았다.
- **미실행 — Android 실제 기기**: 데스크톱 확인만으로 터치·안전 영역·메모리·중단/복귀의 기기 통과를 주장하지 않는다.
- 전체 `verify.sh`·문서·리소스·APK 검사는 루트 담당의 별도 실행 기록을 따른다. 이 기록에서 대신 통과 처리하지 않는다.

## 동작과 시각 재확인

- 시작 하단 바와 진행률 역행 없음, 준비 전 터치 차단, 로딩 중 누른 손을 떼고 새로 누를 때 한 번만 진입, 게임 객체의 네트워크 클라이언트가 시작 전 비활성 상태인 점을 확인했다.
- 새 저장은 첫 선택, 기존 저장은 로비로 연결된다. 필수 파일 오류는 시작 문구를 표시하지 않고 재시도로 복구된다.
- 화면 이동 150ms 이전에는 바를 숨기고 이후에는 중앙 움직이는 바를 표시한다. 완료·취소 시 제거하며, 실패는 재시도·이전 화면을 제공한다. 중복 입력과 취소된 준비의 늦은 결과를 확인했다.
- 실제 선택된 전투 모션이 준비되고 강한 참조로 유지된 뒤 경기 객체를 생성한다. 준비 중에는 경기 객체 처리를 끄고 화면 배치 완료 뒤 다시 켠다.
- 1차 발견한 자율 서버 응답 누락을 수정했다. LAN `room_ready`와 DB 연결 완료는 현재 이동 중이면 최신 요청을 보관하고 이동 완료 후 연결한다. 실패 상태에서는 진행 중 이동을 취소한 뒤 보관된 요청을 실행한다. 실제 유효 LAN 로드아웃으로 전투 장면 연결과 서버 응답 대기 상태를 자동 검사했다.
- 키보드 포커스를 해제하고 전환 중 입력을 막는 구현을 검토했다. 실제 Android 멀티터치 검증은 남아 있다.
- 1280×720(16:9)·1600×720(20:9)의 실제 PNG에서 배경 자르기, 타이틀·시작 문구·버전·저작권 배치를 확인했다. 얇은 글꼴 문제는 굵기 650과 어두운 문구 바탕으로 고쳐 밝은 바닥 위에서도 읽힌다. 배경에는 캐릭터와 이미지 속 글자가 없다.
- 실제 이미지: `qa-captures/startup-loading-16x9.png`, `title-ready-1280x720.png`, `title-ready-1600x720.png`, `transition-loading-20x9.png`, `transition-error-20x9.png`.

## 캐릭터 시안 독립 검토

- 원본 자현과 승인 외형 기준을 보존했다. 나비는 어두운 고양이 귀·풍성한 꼬리·보라색 복장, 유란은 둥근 귀·갈색/흰색 줄 꼬리·청록색 장식을 유지한다. 검토한 16프레임에서 눈에 띄는 추가 귀·꼬리나 셀 잘림은 없다.
- 첫 대기 자세의 귀와 늘어진 머리를 제외한 머리 덩어리에 수동 선을 그은 방식이다. 보고된 자현 너비 27px에 대해 묘령 28px, 나비 약 28.27px, 유란 약 26.53px이며 높이는 각각 약 25.5·26.76·25.39px다. 동일 몸높이 72px의 비교판과 확대판을 함께 보았다.
- 새 나비·유란은 첫 시안보다 머리 가로폭이 줄고 자현과의 균형이 개선됐다. **전 프레임의 머리·모든 팔다리 길이가 10% 안이라는 증거는 아니다.** 수동 기준점의 해석과 최종 외형은 사용자 검토가 필요하다.
- 묘령31·나비29·유란30 전체 목록과 기존 파일은 보존됐다. 대기 자세 승인 뒤 캐릭터별 순서로 제작하고 모션별 승인 뒤 등록한다. 현재 사용자 미승인 시안을 승인 파일로 바꾸지 않았다.
