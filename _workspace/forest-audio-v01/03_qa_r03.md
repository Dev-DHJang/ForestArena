## 최종 추가 확인 — 독립 전투 장면과 검사 오류 탐지

- 기본 앱은 로컬 참가자 ID가 `player`지만 독립 `scenes/main.tscn`은 `ja-hyun`이다. `CombatAudio.local_fighter_id`를 `main._ready()`에서 실제 `MatchController.player.fighter_id`로 설정하고, 결과의 winner_id와 이 값을 비교한다. 앱 모드는 기존대로 어댑터 결과음을 억제해 앱의 팀/LAN 판정을 유지한다. 코드와 실제 장면 데이터를 독립 검토했다.
- 보강된 계약 검사는 autoload 준비 뒤 실제 main 장면을 생성한다. 실제 어댑터 ID 연결을 확인하고 `MatchController.presentation_event`를 통해 로컬 승리/상대 승리를 전달해 각각 victory/defeat를 확인한다. QA 직접 실행에서도 `PHASE6_AUDIO_CONTRACT: PASS`와 exit 0을 확인했다(`/private/tmp/audio-qa-standalone.log`; sandbox 인증서 조회 진단 1건은 기존과 동일). 수동으로 어댑터 ID만 설정하는 좁은 검사로 대체하지 않았다.
- 첫 추가 검사에는 직접 클래스 참조의 compile 오류 뒤 PASS가 출력되는 문제가 있었다. 이를 성공으로 간주하지 않았고 동적 장면 로드로 수정했다. `scripts/verify-audio.sh`는 Godot 종료 코드뿐 아니라 SCRIPT ERROR/ERROR/Parse Error/FAIL 진단도 차단한다. 전체 기본 검사도 이 실행기를 호출한다. 실패한 과거 로그와 최종 통과 로그를 구별한다.
- 최신 `/private/tmp/audio-final-guard.log`에서 47 음원 검사·두 Godot 검사·`verify-audio: PASS`와 오류/종료 경고 없음을 직접 확인했다. `/private/tmp/audio-final-guard-apk.log`도 최신 APK 생성·패키지 검사 통과다.
- 긴 전체 검사는 `4a7cef4`에서 통과했으며, 이후 위의 작은 변경은 영향 범위의 엄격한 오디오 검사·실제 독립 장면/앱 재검사·APK 재생성으로 확인했다. 변경 후 전체 검사를 다시 실행했다고 확대해서 기록하지 않는다. 사람의 청취와 실제 Android 출력은 앞서 기록한 미확인/blocked 상태 그대로다.
