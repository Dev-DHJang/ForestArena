## 수정 확인

1. 백업 파일 전체와 백업 디렉터리, 부모 `recovery`, Codex 저장 폴더를 `fsync`한 후 표시 DB 쓰기를 시작한다. 이전 검토의 백업 내구성 지적을 해결했다.
2. 원본 이미지 해시 검사를 `BEGIN IMMEDIATE`와 표시 행 변경 전에 수행한다. 준비 중 변경을 발견하면 표시 행을 바꾸지 않는다.
3. 연결은 컨텍스트 종료 시 commit 또는 rollback하고 반드시 닫는다.

## 보존 및 충돌 검토

- SQL 변경 범위는 지정한 세션의 변경 계획에 포함된 `thread_items.item_json`이다. 사용자·에이전트 메시지와 실행 중 도구 항목은 축소 대상에서 제외한다.
- 원본 rollout, 이미지 및 Goal DB는 수정하지 않는다. 도구 항목의 긴 command/arguments도 표시 기록의 일부로 축소하며, 실행 원본 rollout과 백업을 보존한다.
- 쓰기 트랜잭션에서 모든 대상 행의 기존 해시를 확인한 후 UPDATE한다. 대상 행에 동시 변경이 있으면 전체 작업을 중단한다.
- restore는 백업의 원본 해시와 현재 행의 변경 후 해시를 모두 확인한다. 새 표시 기록을 덮어쓰지 않으며 한 행의 충돌도 전체 복원을 중단한다.
- 이미 축소한 표시 기록의 repair 재실행은 변경 없이 종료한다. restore 재실행은 이미 복원된 상태에서도 거부할 수 있으나 데이터 변경은 없다.
