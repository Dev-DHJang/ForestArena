# 독립 QA 최종 — 소스·서버·네이티브·에뮬레이터 pass

2026-10-15. **소스/API/실제 Godot 연결/네이티브 화면/최종 APK 에뮬레이터는 pass**다. 아래 실행과 파일을 직접 확인했고 최종 Android APK 바이트 해시와 에뮬레이터 설치본 해시를 대조했다. **물리 Android·두 물리 기기 LAN 검사는 미실행**이며 통과로 바꾸지 않는다. ADR-033의 제한된 개발 서버 기능에 대한 판정이고 Phase 7 전체 완료를 뜻하지 않는다.

## 기준과 독립성

[요청](00_request.md)·[공용 연결 규칙](01_contract.md)·ADR-033과 서버 생산자, 실제 앱·저장·네이티브 화면 소비자를 비교했다. 검사는 다른 담당의 DB나 개발 DB를 쓰지 않는 별도 `forest_menu_qa_<실행값>` PostgreSQL 컨테이너와 임시 loopback API로 실행했다. 프로필·DB/LAN 세션·메뉴 파일은 QA 하위 폴더에 두며, 최종 실제 앱 검사에서 일반 사용자 파일 21경로의 해시가 바뀌지 않았음을 확인했다. 비밀은 자식 프로세스 환경으로만 전달했다. [1차 기록](03_qa_r01.md)의 미완료 항목을 이번 실제 증거로 갱신했다.

## 복구·실패와 의미의 확인

서버 통합 성공 후 프로필 `.tmp` 디렉터리로 기기 저장을 막으면 성공 응답·같은 요청이 남고 기존 메모리가 유지된다. 방해 경로를 치우고 앱을 다시 만들면 DB refresh token이 실제로 회전한다. 저장된 과거 응답을 재개해도 새 인증을 덮어쓰지 않고 같은 통합을 끝내며 후속 재시작과 LAN 세션 전달도 성공했다.

별도 LAN-only 검사에서는 DB 세션 파일이 전혀 없는 상태로 시작했다. 서버 성공 응답 뒤 DB 세션 저장을 막아 인증 실패를 만든 뒤 앱을 새로 만들고 LAN refresh를 실제로 회전했다. 과거 성공 응답의 재개가 같은 원래 ID·이미 확정된 revision을 유지하고 새 인증을 DB/LAN에 함께 저장하며, 후속 강제 refresh와 실제 identity 조회도 성공했다. 서버 통합을 새 계정으로 대체하지 않았다.

연결 전 완료 기록은 즉시 보이며 서버 연결 뒤에도 오프라인 출처다. 실제 51개 대기 기록은 최대50개 API 요청 규칙에 맞춰 나뉘어 전송되고 전부 확인되며 재조회 후 수가 늘지 않았다. 연습·Story·포기 제외, LAN 정상 결과만 순위, 합병 후 과거 자기 경기의 모든 집계 제외, 0경기 순위 없음과 친구 범위를 각각 확인했다. 사회 행동의 operation_id와 친구 요청 ID를 구분했고, 타인 요청·초대 조작을 거부하며 만료와 닫힌 방을 확인했다.

실제 연결 실패 그림은 빨간 안내·마지막 조회 자료를 보존하며 실제 검색 결과 없음과 다르다. 재조회 후 정상 친구 목록으로 복구된다. 보상·재화는 제공하지 않는다.

## 화면·81개 대응과 증거의 한계

총 **84개 원본 PNG(기본63+실제 API21)**를 시각 확인했다. 원본은 Godot `RenderingServer.frame_post_draw` 뒤 실제 viewport에서 저장했다. 연락용 축소 보기 JPG는 원본을 대체하지 않는다. [전체 색인](qa-index.html)과 [SHA-256 목록](qa-evidence-manifest.json)을 남겼다. 1280/1920, 긴 화면, 글자 확대에서 주요 조작·본문·폰트가 읽히며 화면 밖 내용은 ScrollContainer에서 이어진다. 프로필 기록을 실제로 스크롤한 그림도 있다. 합성1184 안전 영역에서 두 재시도와 실패 안내는 넘치지 않는다. 실제 Android notch 검사로 기록하지 않는다.

[81 CSV](state-runtime-coverage.csv)·[JSON](state-runtime-coverage.json)은 이번 native 실행의 확인 수를 붙였다. 81개 서로 다른 실서버 자료나 81개 물리 터치 실행을 뜻하지 않는다. 미션 세부는 실제 로컬 진행 버튼·모달로 실행했다. 친구2행·연결실패·빈검색4행은 명시한 서비스 응답 표본과 native Control로 실행했으며 `validation_scope`에 표시했다. 이 경로의 실제 HTTP/DB 및 실제 연결 그림은 별도 증거로 보완했다. 이전 작업의 대응표 원본은 유지했다.

재현은 `python3 tools/forest_arena/run_menu_features_qa.py --app`, 실제 연결 그림은 `--native-app`이다. backend 변경이 없을 때 후속 앱만 확인하려면 `--skip-api`를 명시한다. 81 결과 갱신은 `python3 tools/forest_arena/update_menu_features_coverage.py --report _workspace/premium-menu-features-v01/qa-captures/native-runtime-report.json`이다.

## 수정 이력과 남은 경고

실제 앱 종료 시 트리를 떠난 HTTPRequest가 요청되는 오류를 발견해 담당자 수정 후 실제 재시작 경로에서 재확인했다. 최종 r09 실제 앱 로그의 ERROR는 0건이다. 전체 verify에는 `resources still in use at exit`가 11건 남으며 모두 종료 정리 메시지다. 단위·기능 pass와 종료 자원 경고를 구분한다. 이전 r06의 ObjectDB4/resource2도 기록에 남기고, 최종 QA 도구는 큐에서 제거한 뒤 프레임을 기다려 정리하여 같은 경고가 사라진 것을 확인했다.

독립 도구의 초기 PostgreSQL 준비 오판, JSON 키 순서, 신규 필드/오류 코드/입력 키, owner 로드 전 비교 오류는 1차 기록에 남겼다. 제품 결함으로 숨기거나 수정 전 실행을 pass로 계산하지 않았다.

## Android와 최종 소스 연결

`build-hashes.json`의 21개 변경 생산 파일을 현재 파일 SHA-256과 직접 대조해 불일치0을 확인했다. 최종 source SHA-256은 `f044ab999f21d147af9f30cfd53ee5cc8c46df92f10a0cefa4999196cee7467f`, APK는 `2b911fbb6a7285362794e122ca97b782520fb1134459c01f011f73aa6da927d4`이며 실제 APK 바이트의 SHA-256과 같다. 실제 연결 그림 이후에는 인증·저장 경계만 보완했고 UI 배치는 바뀌지 않았다. 최종 실제 앱122개가 이 소스를 다시 실행했다.

첫 에뮬레이터 실행 `menu_emu_8c1725160849437f`는 cold-start만 pass 뒤 home 시간 초과로 fail이다. root가 원본 그림에서 Android System UI 응답 없음 대화가 게임 위를 덮은 것을 확인했다. 이 환경 실패 기록을 보존하며 성공으로 바꾸지 않는다. 최종 별도 실행 [menu_emu_8259ffd613b94ea1](emulator/menu_emu_8259ffd613b94ea1/summary.json)은 **7개 pass**, APK `2b911...`와 일치한다. cold-start·첫 지급·캐릭터에서 로비 복귀·0원 구매·조작 저장/재실행 복원·미션/친구/순위/프로필의 실제 ADB 탐색·일시정지 조작 뒤 복귀를 확인했다. 새 메뉴 탐색은 미연결/기기 상태이며 실제 서버 연결 검사는 위 Godot/API 증거와 구분한다. 원본13 PNG를 축소 보기와 함께 독립 시각 확인했고 화면을 가린 OS 대화는 없었다. logcat 1,578행에서 `FATAL EXCEPTION`·앱 ANR·`SCRIPT ERROR`·`Godot ERROR`는 확인되지 않았다. 일반 저장 파일 확인은 이 설치에서 실행 전후 대상이 모두 없던 `{}` 상태가 유지된 결과이며 기존 사용자 자료가 있었다고 해석하지 않는다. 물리 Android·두 물리 기기 LAN은 계속 미실행이다.
