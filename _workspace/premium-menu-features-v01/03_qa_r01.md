# 독립 QA 1차 — 서버·실제 앱 연결 통과, 화면·패키지 확인 대기

2026-10-15. 판정은 **진행 중**이다. 현재 서버/API와 실제 Godot 앱 연결 검사는 **pass**이며, 이번 코드의 네이티브 그림·Android 패키지·에뮬레이터 증거를 아직 최종 확인하지 않았으므로 전체 완료로 기록하지 않는다. 물리 Android 검사는 **미실행**이다.

## 기준과 검사 범위

[원 요청](00_request.md), [공용 연결 규칙](01_contract.md), ADR-033, 실제 생산자 `identities.ts`·`menu_services.ts`·migration 0007과 소비자 `MenuServiceClient`·`MenuFeatureStore`·`LocalAiApp`를 비교했다. 개발 DB와 서버 역할의 검사용 DB를 사용하지 않고 독립 임시 PostgreSQL 컨테이너·`forest_menu_qa_<무작위값>` DB와 임시 API 포트에서 실행했다. 인증 비밀은 자식 프로세스 환경으로만 전달하고 검사 보고서에는 저장하지 않는다. 초기 연결은 로컬 저장만 읽으며 검사용 프로필·DB/LAN 세션·메뉴 파일은 `user://qa/menu_features_actual_<실행값>/` 안에 둔다.

## 직접 실행한 증거

재현 명령: `python3 tools/forest_arena/run_menu_features_qa.py --skip-build --app`. `--skip-build`는 서버 담당의 최신 빌드 후 사용하며 재현 시 생략하면 서버를 먼저 컴파일한다. 도구는 자신이 만든 컨테이너와 API만 정리한다.

- [독립 실행 로그](qa-api-r06.log), [실행 환경·프로세스 재시작 결과](qa-isolated-runtime.json): **pass**.
- [API black-box 검사](qa-api-report.json): 10개 묶음, 553개 확인 **pass**. 공개 service UUID와 인증, 오프라인 전체취소·재전송·ID충돌·시간·최신50건, KST 일/월요일/월 경계와 미션, LAN 서비스 인증·등록순서·재전송·이탈제외, 본인 증명 통합·원본 보존·이전 refresh의 원래 사용자 ID, 통합 후 과거 자기 경기 제외, 사회 행동 소유·중복·타인조작·접속 만료·초대, 실제 51명 이상의 순위 페이지·공동순위·친구 범위를 포함한다.
- [실제 Godot 앱→HTTP→API→PostgreSQL 검사](qa-app-api-report.json), [Godot 실행 로그](qa-app-api.log): 50개 확인 **pass**. `request_adapter`를 쓰지 않았다. 기기/DB/LAN 세 계정의 보유 합집합, 기존 DB 우선, 현재 선택·설정·4개 프리셋·활성슬롯·조작 설정, 연결 전 기록의 실제 전송, 친구 검색·요청·수락·친구 순위, 출처 분리와 실제 앱 재시작을 확인했다.
- 복구 검사에서는 서버 통합 성공 뒤 프로필 `.tmp` 경로를 디렉터리로 막아 기기 저장 실패를 만들었다. 성공 응답과 같은 요청 기록이 남고 기존 메모리는 유지됨을 확인했다. 방해 경로를 치운 뒤 앱을 새로 만들면 실제 refresh token이 회전하며, 저장된 과거 서버 응답을 재사용해도 새 인증을 덮어쓰지 않고 끝난다. 다시 재시작·전송해도 경기 수가 늘지 않는다.
- 추가 API 묶음에서 사회 관계가 겹친 두 계정 통합 뒤 친구·본인 중복 제거, 첫 지급 전 빈 로컬 선택의 서버 보유 선택 복구, 초대의 DB `now()` 만료, 91초 지난 방, 닫힌 방에 늦게 도착한 과거 waiting의 재생 방지, 친구 삭제 후 다시 요청을 확인했다.

## 발견과 수정 재확인

1. 실제 앱을 종료/재시작할 때 `LocalAiApp._exit_tree`에서 이미 트리를 떠난 서비스가 HTTPRequest를 시작해 `!is_inside_tree` 오류가 났다. root/UI 담당이 생명주기 검사를 추가했고 r06 실제 앱 로그에서 해당 오류는 0건이다.
2. 저장된 성공 응답의 오래된 refresh token이 재시작 인증으로 새로 회전한 값을 덮어쓸 위험은 root의 코드 검토에서 발견했다. UI 담당 수정 후 위 실제 복구 검사에서 새 token 유지·후속 재시작·LAN 세션 전달을 확인했다.
3. 독립 도구 자체의 r01 PostgreSQL 임시 Unix 서버 준비 오판은 `pg_isready -h 127.0.0.1`로 수정했다. r02 JSON 키 순서 비교·신규 room.updated_at 누락, r03 새 source 인증 오류 코드 미반영, r04 검색 입력 키, r05 owner 로드 전 프리셋 메모리 비교는 검사용 코드의 오류였고 제품 결함으로 계산하지 않았다. 최종 r06은 수정된 검사를 다시 실행했다.
4. 실제 Godot 종료 로그에는 기존 ObjectDB 4개·resource 2개의 정리 경고가 남는다. 행동 확인 통과와 종료 자원 경고를 구분하며 경고 없는 실행으로 기록하지 않는다.
