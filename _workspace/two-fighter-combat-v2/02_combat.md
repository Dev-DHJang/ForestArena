# 자현·나비 전투 구현 기록

## 작업 기준

- 2026-10-19 사용자 승인과 `00_request.md`·`01_contract.md`, 전투 스킬에 따라 최신 `95e1fe4`에서 작업했다.
- 기존 사용자 원본 폴더, PNG와 manifest, 기존 캐릭터와 MoveSet, 기존 규칙 Resource는 수정하지 않았다. 새 제품 데이터와 기존 기반 데이터를 분리했다.
- 완료한 범위는 고정 60Hz 전투 코드·데이터·자동 검사다. 신규 안무 승인과 실제 Android 기기 확인을 완료로 기록하지 않는다.

## 전투 동작

- 자현 4단·나비 3단 지상 약공격, 방향 통합과 차지 없는 단타 강공격을 새 두 MoveSet에 정의했다. 공용 코드에 캐릭터 이름 비교를 추가하지 않았다.
- 자현 강공격은 사거리 180의 단타이며 실제 충돌 이동으로 상대를 64 간격까지 끌어온다. 나비 강공격은 위로 띄우는 단타다.
- 공중 약·강은 각 한 번씩만 시작한다. 길어진 공중 약은 피격 상대의 추가 점프·공격을 제한하며 경직 뒤 좌우 이동은 허용한다. 기존 남은 기회는 보존하고 새 기회를 지급하지 않는다.
- 나비 공중 강은 피격 상대의 전체 행동을 막고 위로 띄운다. 자현 공중 강은 시전자를 움직이지 않고 피격 상대를 아래로 빠르게 친다. 실제 착지에서 다운 18tick과 기상 보호 12tick을 적용한다. 공격을 시작하면 기상 보호를 종료한다.
- 추가 제한의 120tick은 첫 피격에서만 시작한다. 재피격으로 시간을 늘리지 않고 만료 뒤 같은 체공에서 다시 잠그지 않는다. 일반 피격 경직은 별도로 유지한다.
- 자현 지상 특수는 좌/우/위 세 영역에서 활성 6,12,...60 tick에 각 한 번 판정한다. 영역 중복은 타격 수를 늘리지 않는다. 앞의 아홉 번은 끌고 마지막은 시점에 따라 바깥으로 민다. 합계 피해는 14다.
- 나비 특수는 승인된 속도 1,200px/s로 최대 320 경로의 첫 적 뒤 64에서 멈추고 그 상대만 한 번 공격한다. 도착 시 바로 마지막4개 활성tick으로 옮겨 단타 후 회복20tick을 적용한다. 빈 대시/실패는 즉시 회복20tick이며 가까운 적에게 먼저 도착해도 남은 이동 시간을 추가로 기다리지 않는다. 이동 중 캐릭터 밀기만 제외하며 지형 충돌·피격은 유지한다. 빈 경로는 320 이동만 한다. 벽이나 종점 점유가 있으면 이동 전에 실패하여 겹친 몸이 벽 안으로 밀리지 않게 한다.
- 두 특수는 지상에서만 시작하고 시작 시 300tick 쿨다운을 적용한다. 가드 가능하며 피격 시 남은 동작을 중단한다. 빗나가거나 중단해도 쿨다운을 돌려주지 않는다.
- 단순 조작 규칙은 필살기·기본 대시·회피·차지를 실행하지 않으며 키보드 연결에서도 해당 명령을 만들지 않는다. 기존 규칙 false 경로는 보존했다.

## 검사

새 `tests/two_fighter_combat_v2.gd`가 실제 고정 tick·이동·공격 영역·적중 처리를 사용한다.

- 새/기존 형식 검증과 잘못된 펄스 시간·빈 영역 거부.
- 모든 지상 방향, 실제 4/3단 연계 전부 적중, 삭제 행동 거부, 즉시 강공격과 원거리 끌기.
- 긴 공중 약, 공중 사용 기회 분리, 경직 뒤 좌우, 추가 점프/공격 금지, 최초 120tick 유지·재피격 강화/만료 후 재설정 금지·남은 기회만 사용.
- 두 공중 강의 단발·피격자와 시전자 역할 구분·초기 아래 속도 900·실제 착지 다운 18/기상 보호 12·공격 시 보호 종료.
- 세 방향 상대 각각 10회·6tick 간격·피해14·마지막 바깥 밀기, 전 펄스 가드, 시전자 피격 중단, 빈 경로와 쿨다운.
- 나비 첫 적 단일 타격/뒤64 종점/빈320 이동/가드/종점 점유 실패/지형 경로 사전 차단/이동 피격 중단.
- 동시 타격은 양쪽 모두 맞고 이후 펄스는 중단, 같은 거리 대상은 배열 순서와 무관하게 ID로 선택.
- 상태 기록 왕복·구버전 기본값·동일 초기 상태 재현·타격별 복사본이 원본 Resource를 바꾸지 않는지 확인.

모든 신규 검사는 PASS이며 SCRIPT ERROR가 없다. 이전 공용 전투·조합·상속·8인 경기 검사 14개와 제품 연결 검사도 PASS다. 일부 기존 검사의 종료 시 Resource 미해제 경고는 신규 동작 오류와 구분했다. 새 전투 검사는 해당 경고도 없다.

Godot 논리 리소스 검증은 PASS(519개, 품질 차이25개). 소유 파일의 `git diff --check`는 통과했다. 전체 검사 명령·문서 검사와 실제 기기 확인은 통합 담당자가 기록한다.

## 승인 전 시각 상태

자현 약3은 기존 첫 동작을 재사용한다. 약4의 `attack_light_combo_04`, 특수의 `special_scarf_sweep`는 시안 전용 이름만 연결했고 PNG·manifest는 추가하지 않았다. 나비 약2는 `attack_light_up`, 약3은 기존 `attack_light_combo_02`를 사용한다. 공중 강 등 기존 이름의 임시 그림 재사용도 새 안무 승인을 뜻하지 않는다.


## 승인 수치 재점검 보완

부모의 최종 점검으로 나비 특수의 초기 구현값1,600px/s·회복24tick이 승인 기본값1,200px/s·회복20tick과 달랐음을 확인하고 맞췄다. 데이터 숫자만 바꾸지 않고 실제 이동과 종료 시점 검사도 추가했다.

- 매 tick 실제 좌표 변화가 20px 이내이며 마지막 도착 tick을 제외한 이동은 정확히20px인지 확인한다.
- 탐색 최대320의 적을 만났을 때 최대384px를20이동tick에 도달하고 한 번 맞히는지, 빈 대시는320px를16이동tick에 끝내는지 확인한다.
- 적 도착 뒤4활성tick에서 중복 적중 없이 바로 회복을 시작하고, 회복19tick에는 아직 공격 중이며20tick에 끝나는지 확인한다.
- 가까운 적의184px 도착도 동일한4+20 흐름을 가지며 남은 활성 예약 시간을 더 기다리지 않는지 확인한다.
- 이동 공격 데이터가 최대 이동·단타 구간을 담을 수 없는 잘못된 활성 길이는 거부한다.

수정 후 `two_fighter_combat_v2`는 PASS이며 SCRIPT ERROR가 없다.
