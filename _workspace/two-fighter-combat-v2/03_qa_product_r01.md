# UI·AI·저장·LAN 독립 교차 검토

- 결과: **pass**. 표시 오류 한 건을 담당자에게 전달했고 수정 뒤 다시 확인했다.
- 검토자: 전투 담당(제품 연결 코드 작성자와 다름).
- 기준: `00_request.md`, `01_contract.md`, Forest Arena QA 스킬. 실제 Android 기기는 확인하지 않았다.

## 확인 범위

- 제품 카탈로그는 원래 캐릭터·장신구 ID를 보존하고 활성 제공만 자현·나비로 제한한다. 새 MoveSet 연결 전에 CharacterData도 복제하여 원본을 바꾸지 않는다.
- LocalPlayerStore는 보유·닉네임·설정 기록을 유지하고 실행 선택만 보정한다. 기존 버전3 저장도 선택 보정이 필요하면 백업 후 저장에 성공해야 메모리를 바꾼다. 읽기 전용 DB 가져오기는 기존 기기 파일을 쓰지 않는다.
- API는 트랜잭션 안에서 보정과 저장을 처리하고 장신구·비활성 캐릭터의 새 선택을 거부한다. DB 클라이언트의 동작은 서버 저장 성공 뒤 최신 상태를 읽는 기존 순서를 유지한다.
- 저장된 옛 프리셋은 보정한 복사본으로 실행하고 저장 원본은 유지한다. 새 프리셋은 활성 캐릭터와 미장착만 허용한다.
- LAN protocol3, 초대 코드, 서버·클라이언트 행동 목록과 선택 검사가 일치한다. protocol2, 비활성 캐릭터, 장신구, 직업 선택의 우회를 막는다.
- 로컬과 LAN의 `configure_minimap`이 실제 로컬 파이터 ID를 터치 상태 표시에도 연결한다. 상대방의 공중 사용 여부·쿨다운을 내 상태로 읽지 않는다.
- AI 단순 조작 경로는 기본 대시·회피·필살기와 강공격 해제를 만들지 않는다. 공중 특수는 요청하지 않고 공중 약·강의 개별 사용 여부와 공중 행동 제한을 읽는다. 보통 이동·간격 유지·후퇴·대기·가드 선택은 유지한다.

## 지적과 수정 확인

- P2: 착지 다운 동안 공중 잠금 값은 이미 0이므로 기존 표시 조건만으로는 공격 버튼이 준비 상태로 보였다. 실제 전투는 `landing_down_ticks>0` 동안 행동을 막으므로 표시와 동작이 달랐다.
- 담당자가 터치 표시의 비활성 조건에 착지 다운을 추가했다. 약·강·특수는 `행동 불가`, 점프를 포함한 네 버튼은 비활성 색으로 표시한다. 다음 정상 상태 기록에서 복원되고 입력 자체를 차단하는 새 기능은 추가하지 않았다.
- 담당자가 추가한 착지 다운 표시·복원·관찰값 불변 검사를 읽고 최신 `two_fighter_product.gd`를 독립 실행해 PASS를 확인했다.
