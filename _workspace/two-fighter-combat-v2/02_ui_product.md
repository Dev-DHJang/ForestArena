# 자현·나비 제품 화면·저장·입력 연결

## 구현한 동작

- 전체4캐릭터·6장신구의 원본 카탈로그와 보유 ID는 유지한다. `playable_characters()`와 `is_playable_character()`는 자현·나비만 제공하며 신규 선택·첫 지급·상점 구매·AI 편성·LAN 참가가 같은 목록을 사용한다. 이번 전투에는 직업·장신구를 장착하지 않는다. 보관함의 과거 기록은 읽기 전용이다.
- `LocalPlayCatalog.new()`는 원본 카탈로그와 각각의 외부 CharacterData를 별도로 복제한 뒤 새 두 MoveSet을 연결한다. 기본 개발 검사에는 `new(false)`로 이전 MoveSet을 읽을 수 있다. 원본 CharacterData/MoveSet/CombatRules는 바꾸지 않는다.
- 기기 저장 v3은 기존 보유를 지우지 않고 현재 선택만 정리한다. 비활성 선택은 보유한 활성 캐릭터로 바꾸고, 둘 다 없으면 자현을 무료 추가한다. 상대는 활성 캐릭터, 장신구는 미장착으로 바꾼다. 변경된 v3도 원본 백업→임시 파일 확인→교체 성공 뒤 메모리 적용 순서를 지키며, 실패하면 기존 메모리를 유지한다. 이미 정리한 선택은 다시 저장하지 않는다.
- API 프로필도 같은 정리를 사용한다. 보유 ID 검사와 현재 전투 선택 검사를 분리해 과거 보유와 전적을 유지하고 새 비활성 캐릭터·장신구 구매/선택을 거부한다. GET/가져오기에서 바뀐 선택은 DB UPDATE 성공 뒤 응답한다. 프로필 형식은3을 유지한다.
- 옛 프리셋은 그대로 읽고, 적용할 때 복제본의 캐릭터·장신구만 현재 정책으로 정리한다. 과거 프리셋 원본을 자동으로 덮어쓰지 않는다. 새 프리셋 저장은 두 캐릭터·미장착만 허용한다.
- 실제 오프라인 앱과 LAN 서버/표시는 새 `two_fighter_combat_rules.tres`의 별도 복제본을 사용한다. 기존 기본 전투 규칙은 `simplified_combat=false` 그대로다.
- 실제 터치는 점프·약·강·특수의4버튼이다. 약96px/나머지80px 곡선 배치와 조이스틱·고정/플로팅·크기/투명도·접근성을 유지한다. 버튼 크기1.2배에서도 점프와 약의 판정 사각형이 겹치지 않게 간격을 확보했다. 조작 설정 미리보기에도 특수를 포함한4버튼을 표시한다.
- 궁극기 표시는 없다. 가드 막대는 유지하고 특수 대기시간을 초로 표시한다. 공중 특수는 `지상 전용`, 이미 쓴 공중 약·강은 각각 `사용함`, 공중 행동 제한에는 `행동 불가`를 표시한다. 전투 snapshot을 읽을 뿐 피해·사용 횟수·금지 시간을 계산하지 않는다.
- AI는 기본18tick·기존5전술을 유지한다. 새 규칙에서는 대시·회피·궁극기·강공격 해제 명령을 만들지 않고, 방어는 아래 입력, 특수는 지상에서만 요청한다. 강공격 사거리는 실제 기술 데이터에서 구하며 공중 약·강 사용 여부/행동 제한을 따른다. QA 자동 플레이도 snapshot의 새 규칙 표시를 읽는다.
- LAN protocol3과 FAH3/FA3 코드를 사용한다. 구버전1·2를 명시적으로 거부하고 클라이언트·서버 모두 이동/점프/약/강/특수만 전송·허용한다. 서버 선택 검사도 활성 캐릭터·직업 없음·장신구 없음만 받는다. 기존 닉네임·미니맵·재접속·결과·재대전을 보존한다.

## 남아 있는 확인

DB 실제 서버를 사용하는 긴 프로필 검사의 기대값은 활성2명·미장착으로 갱신했으며, 이번 담당자는 DB 실연결 검사 통과를 주장하지 않는다. 전체 통합 검사와 DB 실행 상태는 조율 역할이 확인한다. 기존 일부 검사 종료 때 ObjectDB/Resource 정리 경고가 있으며 기능 검사 PASS와 구분한다.

새 모션은 승인 전 시안이다. runtime PNG·manifest는 변경하지 않았고 기존 승인 모션 재생만으로 새 기술이 완성됐다고 기록하지 않는다. 모션별 승인·새 APK의 물리 Android 조작/표현·중단 복귀·LAN 두 기기 동시 확인은 별도 미실행/승인 대기다. 출시·배포는 하지 않았다.
