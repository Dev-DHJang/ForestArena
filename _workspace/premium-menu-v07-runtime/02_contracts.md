# 메뉴 저장 구현 확인

2026-10-15. `LocalMenuStateStore`는 [공용 연결 약속](01_contract.md)의 함수와 필드를 구현했다. 기존 `LocalPlayerStore` v3 파일·API·DB 저장 형식은 변경하지 않았다.

- `menu_presets_v01.json`: 사용자별 슬롯 4개와 선택 번호를 저장한다. 기기 사용자, DB 서버 A의 사용자, 서버 B의 같은 사용자 데이터가 서로 섞이지 않는다. 첫 지급 전 빈 장비는 빈 슬롯으로 시작한다.
- `menu_controls_v01.json`: 고정/플로팅, 크기 1.0~1.2의 0.05 간격, 투명도 0~50의 5 간격을 검사한다. JSON에서 읽은 숫자는 크기 float와 투명도 int로 정리한다.
- 저장은 임시 JSON 작성·내용 확인·정상 이전 파일 백업·최종 교체 순서다. 쓰기·백업·교체 실패에는 메모리 값을 유지한다. 손상된 기본 파일은 정상 백업을 덮어쓰지 않는다.
- 읽을 수 없는 JSON·잘못된 catalog ID·모르는 필드는 정상 백업을 확인하고 둘 다 잘못되면 오류를 반환한다. 기본 파일의 다른 schema_version은 백업이 있어도 거부하며 파일을 덮어쓰지 않는다.
- 생성 파일은 전달받은 base_dir 아래만 쓴다. 앱의 QA 프로필 디렉터리를 전달하면 메뉴 저장도 같은 QA 디렉터리로 분리된다.
