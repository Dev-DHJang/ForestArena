## 화면 결과와 81개 상태 해석

기본 13개 메뉴의 1280/1920 원본을 각각 열고, 20:9 네 원본과 실패 화면의 주요 원본도 열었다. 1.15/1.3 전체는 비교 이미지와 대표 원본으로 확인했다. 한국어 제목·본문·선택 표시·조작 여백·원화 비율을 확인했고, 의도한 목록과 본문 스크롤의 잘림을 화면 밖 조작이나 겹침과 구분했다. 확대 후에도 바깥 주요 행동은 화면과 안전 여백 안에 있다. 60장은 `RenderingServer.frame_post_draw` 이후 실제 창의 화면을 저장한 PNG이며, 설계 PNG를 UI로 붙이거나 빈 PNG를 만들어 대체하지 않았다. 비교 이미지는 그 원본을 축소해 모은 검토 자료다.

81행은 **81개의 서로 다른 완성 기능 또는 81개 독립 클릭 시나리오라는 뜻이 아니다**. 각 행을 실제 라우터와 네이티브 화면으로 대조하고, 구매 팝업·복원 팝업·프리셋·설정 등은 실제 버튼과 저장 검사를 추가했다. 미래 미션·친구·랭크의 예시 상세/친구/실패 상태는 사용자 요청에 따라 준비 중·빈 화면으로 합친다. 가짜 친구·보상·순위·연결 실패를 만들지 않는다. `Review`는 제작 전달용 보드이므로 제품 메뉴를 추가하지 않고 전체 메뉴 이동 검사로 대응했다. `SelectionRequired`는 네 슬롯을 채우기 전 실제 빈 슬롯 적용 안내를 확인했다.

합성 노치는 화면 좌표를 논리 좌표로 바꾸는 계산과, 스트레치 기준을 끈 실제 1184×720 Godot 창으로 검사했다. 이는 실제 Android 노치·시스템 바·터치 밀도 검사가 아니다. 200ms 전환 뒤 안정된 상태에서 검사하며, 버튼 자동 검사는 실제 Button의 신호를 호출한다. Android 화면 터치와 뒤로는 에뮬레이터 검사와 구분한다.

## 마지막 로그 수정과 실행 기록의 한계

[전체 검사](verify-final.log)는 종료 코드 0과 전체 PASS지만 `SCRIPT ERROR` 0줄, `ERROR` 37줄, `WARNING` 15줄이다. ERROR에는 리소스 종료 정리 11줄과, 빨리 사라진 버튼의 디버그 좌표 기록을 뒤늦게 호출한 `_log_button` 오류 26줄이 포함된다. WARNING에는 객체 종료 정리와 원본 이미지 읽기 검사 안내가 포함된다. 오류나 경고가 없었다고 보고하지 않는다.

전체 검사 뒤 버튼을 강하게 잡아 두는 인자 대신 `WeakRef`로 전달하고, 유효한 버튼만 읽도록 수정했다. QA가 해당 코드와 [수정 뒤 기존 흐름 검사](legacy-flow-deferred-fix.log)를 대조했다. `LOCAL_AI_APP_FLOW: PASS`, 지연 호출 오류 0줄이다. 이 기록에는 종료 시 리소스 정리 ERROR 1줄/객체 정리 WARNING 1줄이 남는다. 마지막 로그 수정 뒤 전체 검사를 다시 했다는 뜻은 아니며, 전체 검사와 영향 범위 재검사를 분리한다. [독립 로그 집계](qa-build-independent-audit.json)를 참조한다.

최종 r08 네이티브 실행 자체는 `SCRIPT ERROR`·`ERROR`·`WARNING` 모두 0줄이다. r08의 60장 화면은 플레이어 문구 수정까지 반영한 출력이다. 뒤이은 디버그 기록 수정은 메뉴 배치·표시 코드·저장·전투를 바꾸지 않았으며, 최신 APK에는 수정된 기록 코드가 들어 있다.
