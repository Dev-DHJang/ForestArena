# 모바일 메뉴 드래그 수정 근거

실기기 r03은 새 타이틀 진입에는 성공했지만 상점의 purchase/yu-ran 버튼을 찾지 못했다. 실제 화면에서 4번째 유란 카드가 아래에 잘려 있었고 첫3개 보유 상태는 정상이다.

root가 실제 ADB로 상점 카드 본문을 x0.65/y0.60→0.30, x0.39/y0.72→0.30에서 드래그했지만 구매 버튼의 y비율1.022222/visible=false가 변하지 않았다. 오른쪽 스크롤바를 x0.889/y0.40→0.70으로 끌면 y0.766667/visible=true로 이동했다. 데이터 누락이 아니라 장식 컨트롤에서 손가락 입력이 막힌 것이다.

Godot4.7.1의 실제 PanelContainer 기본 mouse_filter는 STOP(0), VBox·Grid·ScrollContainer는 PASS(1)임을 로컬 객체로 확인했다. 카드·추천 배너의 장식 패널 PASS와 추천 이미지 IGNORE만 추가했다. 독립 QA가 구매 버튼과 모달의 동작은 유지됨을 검토했다.

PREMIUM_MENU_TOUCH_SCROLL 자동 검사는 실제 native PanGesture를 입력 경로로 보내 스크롤0→184, 보유 불변과 구매 모달 미표시를 확인했다. Godot의 headless 환경에서는 터치스크린 마우스 드래그가 비활성화되므로 이를 실제 Android 손가락 결과로 표현하지 않는다. 참고 엔진 원본: https://github.com/godotengine/godot/blob/4.4/scene/gui/scroll_container.cpp (gui_input; 최종 판단은 현재 Godot4.7.1과 실기기 재검사).

새 APK는 기존 APK를 덮어쓰지 않고 build/android/ForestArena-integrated-device.apk로 만든다. 실제 상점 구매 흐름과 추천·장신구·도감 드래그는 이 APK에서 재검사한다. 실기기 결과는 후속 기록한다.

추가 패키지 확인: 첫 수정 APK를 이전 APK와 비교해 호스트 npm 검사로 생긴 server/api/node_modules·dist의 JSON33개가 추가 포함됨을 발견했다. 두 export preset에서 해당 경로를 제외하고 패키지 검사에서 발견 시 실패하도록 했다. 수정 전 APK를 강화된 검사로 거부하는 부정 검사(예상 exit1)가 통과했고, 최종 새 APK의 패키지·120텍스처·아이콘·부트 검사와 서명 호환성이 통과했다. 최종 APK SHA-256은 ae579f8ed372c32f79c479edebb1a671047e7b4d1467ce9f0f06997fd55df6df다.
