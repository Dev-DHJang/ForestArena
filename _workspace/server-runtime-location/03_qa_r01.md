## 운영 주의사항

- server-dev up은 기존 이미지가 없을 때만 tar를 불러오며 `--no-build`로 실행한다. 향후 새 코드 배포는 이미지/JAR를 명시적으로 갱신해야 한다. README에 이 한계가 기록돼 있다.
- admin-dev start는 준비 상태를 기다리지 않는다. 이번 이전은 별도의 status·HTTP 확인까지 통과했다.
- 기존 db-dev의 reset/restore는 파괴적인 관리 명령이며 확인 인자가 필요하다. 이번 QA에서는 실행하지 않았다. 평소 이전·재시작에서는 server-dev up을 사용한다.
- DB 데이터 자체는 새 폴더가 아니라 기존 Docker 볼륨에 있다. README는 이 차이와 복구용 dump를 설명한다.
- 로그인·권한 변경·실제 게임 매치·Android 검사는 이번 위치 이전 QA의 통과 항목으로 기록하지 않는다.
