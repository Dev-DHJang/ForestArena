# 피격 모션 재진입 실제 화면 독립 확인 r02

2026-10-25. 담당 `/root/hit_pixel_final`. 판정: **pass — 현재 승인 이미지로 표시하는 로컬 연속 피격의 실제 픽셀·재생 범위**. 앞선 `03_qa_r01.md`의 코드/자동 검사와 별개로 실제 화면 자료를 직접 확인했다. 제품 코드·원화·후보·manifest는 수정하지 않았다.

## 검토한 실행과 파일

`qa/live-normal-r01/`과 `qa/live-mirror-small-r01/`의 자현·나비 각1개, 총4개 클립이다. 각60틱·60fps이며 정상 줌1.50과 좌우 반전/소형 줌0.75다. `runtime-only-catalog.json`의 `assets=[]`와 촬영 코드를 읽어 미승인 후보를 넣지 않고 현재 등록된 idle/hitstun을 쓰는 실행임을 확인했다. 영상의 공용 캡션에 남은 “승인 전 실제 입력 검토” 문구는 새 자산의 승인 상태를 뜻하지 않는다.

실제 장면과 고정 전투 tick에서 공개 `apply_hit`를 물리 step 뒤 t12·t18에 각각16tick 경직으로 호출한다. 6tick 간격으로 같은 HITSTUN 상태에 다시 맞게 하며, 그림을 강제로 지정하거나 상태를 오래 붙잡은 재생이 아니다. 공격 판정 상자를 맞히는 장면이나 실제 LAN 피격 영상이라고 기록하지 않는다. 같은 화면의 피격하지 않는 상대는 대기 자세를 유지한다.

`qa/independent-r02/inspect-captures.py`를 이번 역할에서 다시 실행해 네 무손실 MKV의 모든240장 RGBA를 풀었다. 원 raw의 전체 SHA-256·각 프레임 MD5·보관 영상 SHA·촬영 보고서 SHA와 일치했고 촬영 source hash도 현재 파일과 모두 일치했다(`reverification-final.log`, `capture-verification.json`). `validate-live.py`로 두 촬영의 실제 클립 수·상태 검사·매틱 촬영·현재 코드 해시·오류 없는 렌더링 로그를 확인하여 각각2클립120프레임 pass를 받았다(`validation-final-normal.json`, `validation-final-mirror.json`). 메타데이터 일치만으로 행위 판정을 대신하지 않았다.

## 직접 본 픽셀과 재생

각 클립60틱을 두 장씩 나눈 비교판8개를 모두 직접 확인했다. 원본 영상을 QuickTime Player의 정식 로컬 파일 열기로 열어 보통1×와0.5배속을 선택하고 재생 상태와 중간·복귀 화면을 대조했다. 브라우저 file URL 재시도, 서버 또는 다른 브라우저 우회는 하지 않았다. 도구가 제공한 동영상 화면은 재생 도중의 표본이며, 모든 순간을 끊김 없이 실시간 육안 관찰했다고 주장하지 않는다. 전체 시간 순서 판단은240틱 직접 비교판과 함께 한다. 자현 정상 영상은 반복 재생으로 시작·피격 중간을 확인했고 종료 자세는 비교판에서 확인했다. 다른3개는 재생 종료1초·0.98초 idle 화면도 직접 확인했다. 클립별 표본 시점과 정확한 자료 해시는 `qa/independent-r02/pixel-review-final.json`에 남겼다.

- **두 캐릭터·두 방향 모두** t12에 피격 첫 그림(f0)으로 들어간다. t17의 진행 자세(f5)에서 새 타격 t18을 받으면 다시 f0으로 돌아간다. 앞선 피격을 끝까지 기다려서 f15를 먼저 표시하거나 대기 자세를 거쳐 다시 진입하는 중간 장면은 없다.
- 두 번째 피격은 t18부터 진행해 t32 f14·t33 f15까지 도달한다. t34에는 실제 상태가 idle로 바뀌며 대기 그림을 표시한다. 뒤의 t59까지 남은 피격 자세나 다시 시작하는 피격 흔적이 없다.
- 자현은 첫 피격의 움츠린 팔/몸 자세를 다시 취한 뒤 몸을 젖히고 회복한다. 나비는 팔이 풀리며 상체를 뒤로 젖히는 자세가 두 번째 타격에서 다시 처음으로 돌아가고, 마지막에는 가드를 갖춘 대기로 복귀한다. 정상과 소형/반전 모두 이 반응이 구별된다.
- 이 네 장면에서 재진입 때문에 캐릭터가 사라지거나 잘리는 프레임, 반전이 두 번 적용되는 장면, 피격 종료 뒤 마지막 그림이 남는 문제는 찾지 못했다. 발과 몸의 원화 자세 변화는 기존 승인16장 자체의 움직임이며 새 원화를 추가하거나 이 변경에서 외형을 다시 승인한 것은 아니다.

## 판정의 범위

이번 pass는 사용자 요청의 로컬 피격 재진입·마지막 자세·대기 복귀와, 그 실제 정상/반전소형 표시를 확인한다. 새 모션 이미지의 승인 요청이나 남은26종의 미술 품질 전체 통과가 아니다. 경직 길이 변화·가드/무효/갑옷·launch/down·이벤트 중복/epoch는 r01의 독립 자동 검사 범위를 따른다. 이 화면은 고정16tick 표본이므로 모든 경직 길이의 시각 품질까지 일반화하지 않는다.

LAN3에는 남은 경직 필드가 없어 LAN은 기존 FPS와 다음 서버 상태를 따르는 한계가 있다. 로컬처럼 짧은 LAN 경직마다 마지막 그림까지 보인다고 증명하지 않는다. 실제 WebSocket 영상·Android 기기·중단/복귀는 이번 픽셀 QA에서 실행하지 않았으며 기기 통과로 기록하지 않는다. 최종 전체 verify와 연결 검사는 조율 담당의 별도 증거를 사용한다.
