# 피격 표시 연결

전투 계산이 정한 결과를 표시 코드가 읽는 연결만 추가한다. 공격 데이터·스냅샷·저장·LAN 메시지의 필드와 버전은 바꾸지 않는다.

- `FighterController.hit_reaction_started()`는 실제 피격 반응이 정해진 뒤 보낸다. 값이 없는 로컬 표시 신호이며 피해나 경직을 계산하지 않는다. 가드 파괴로 실제 피격 상태가 시작되는 경우도 포함한다.
- `LocalFighterPresentation`은 신호를 받으면 피격 재생을 다시 시작한다. 로컬 HITSTUN의 길이는 이미 정해진 `hitstun_ticks`를 읽고 전투가 끝나는 시점을 그대로 따른다.
- `LocalFighterPresentation.play_combat_event(event_id, payload)`는 기존 `hit_resolved`의 대상 ID·HIT 결과·경기 번호와 순서를 확인한다. 실제 피격 상태에서만 재생을 다시 시작하며, 이 함수는 전투 상태를 피격으로 바꾸지 않는다. 로컬 신호로 처리한 타격은 같은 이벤트로 다시 초기화하지 않는다.
- `main.gd`는 기존 표현 이벤트를 현재 경기의 표시 노드에 전달한다. 늦게 만들어진 LAN 파이터도 현재 목록에서 찾는다.
- LAN3에는 남은 경직이 없으므로 이를 표시 코드에서 추측 계산하지 않는다. 이벤트로 첫 그림부터 다시 재생하고 다음 서버 상태가 오면 즉시 해당 동작으로 바꾼다.

자동 검사는 실제 피격 함수·HitResolver·main 연결과 중복/지난 경기/다른 대상/비HIT 이벤트를 포함한다. 실제 공격 판정·WebSocket 연결·영상 픽셀·Android 기기는 각 검증 범위를 별도로 기록한다.
