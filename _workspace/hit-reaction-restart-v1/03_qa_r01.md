# 피격 모션 재진입 독립 확인 r01

판정: **pass — 피격 표시 재생 시간과 기존 이벤트 연결의 코드·실행 검사 범위**.

담당: 별도 QA 역할 `/root/hit_reaction_qa`. 생산자의 로그를 그대로 통과 근거로 쓰지 않고 현재 제품 코드와 검사를 읽고 독립 실행했다. 제품 파일은 수정하지 않았다. 그림·타격 판정·피해·경직 길이·LAN 데이터 형식 변경은 이 작업에 없다.

## 확인한 사용자 동작

`tests/hit_reaction_presentation.gd`를 Godot 4.7.1 headless에서 직접 실행했다. 자현·나비의 실제 `FighterController.apply_hit`를 호출하여 다음을 확인했다.

- 16tick 피격 재생 도중 6tick 경과 후 새 30·10·6tick 피격을 받으면 같은 전투 상태·같은 activation_serial에서도 표시 프레임이 즉시 0으로 돌아간다. 남은 10tick과 새 10tick이 같은 경우도 포함한다.
- 새 경직의 마지막 tick에는 실제 등록된 hitstun의 마지막 그림을 선택하고, 다음 전투 tick에서 실제 idle 전환과 함께 idle을 선택한다. 경직을 늘려 그림 끝을 기다리지 않는다.
- 같은 launch·knock_down 재피격도 처음부터 다시 표시한다. 기존 착지·일어남·등장 표시 검사는 별도 실행하여 유지됨을 확인했다.
- 로컬 피격 신호와 그 타격을 설명하는 기존 `hit_resolved` 이벤트가 함께 와도 두 번 초기화하지 않는다.
- 실제 HitResolver의 BLOCK·IMMUNE·ARMOR는 일반 피격 재생을 시작하지 않는다. 가드 파괴로 상태가 HITSTUN으로 바뀌면 첫 피격 자세로 진입한다.
- 경기 재시작과 같은 캐릭터 프로필 재설정은 남은 표시 시간을 지운다. 표시 호출 전후 전체 fighter snapshot은 변하지 않는다.

## LAN 이벤트의 경계

추가한 `qa/independent-r01/event-boundaries.gd`는 실제 main 장면과 Presentation을 만들고 `MatchController.presentation_event`를 보내 main의 새 연결을 통과한다. private 초기화 함수를 직접 호출하여 결과를 만드는 방식이 아니다.

- 기존 HITSTUN에서 새 HIT는 첫 프레임으로 재진입한다. 중복 event_seq는 재생을 다시 시작하지 않는다.
- 같은 tick의 서로 다른 event_seq 두 타격은 각각 새 타격으로 처리한다.
- 새 epoch에서는 작은 event_seq·tick으로 다시 시작할 수 있다. 이전 epoch·중복·직전 이벤트보다 과거 tick은 무시한다.
- 서버는 `step_fixed_tick` 안에서 이벤트를 전송한 뒤 3tick마다 snapshot을 전송한다. 클라이언트는 같은 WebSocket에서 순서대로 받는다. 이 코드 경로를 읽고 event-before-snapshot 순서도 별도로 재현했다. idle에 도착한 선행 이벤트는 전투 상태를 만들지 않고, 뒤따르는 실제 HITSTUN snapshot이 첫 자세로 들어간다. 다음 새 HIT는 재생 중인 자세를 다시 시작한다.
- 다른 대상·HIT 이외 결과·idle·death·match end에서 늦게 받은 이벤트와 지연된 고유 HIT는 생산자 검사에서 실제 main 전달 및 snapshot 적용과 함께 확인했다.

LAN3에는 남은 hitstun tick이 없으므로 LAN은 기존 모션 FPS로 표시하고 서버가 보낸 다음 상태를 따른다. 로컬처럼 모든 짧은 경직에서 마지막 그림까지 표시한다고 증명하거나, 표시 코드에서 없는 전투 값을 계산한다고 기록하지 않는다.

## 범위와 남은 검사

이번 확인은 실제 제품 표시 함수가 선택한 animation/frame과 전투 상태·snapshot의 자동 실행 검사다. 화면의 픽셀을 촬영하거나 정상·느린 동영상을 눈으로 확인한 모션 미술 검토는 아니다. 기존 승인 이미지와 manifest는 이 변경에서 수정하지 않았다. 실제 WebSocket 두 참가자 연결과 Android 기기·중단/복귀 확인도 이 QA 역할에서 실행하지 않았으므로 통과로 기록하지 않는다. 최종 통합 verify와 관련 연결 검사는 조율 역할에서 별도로 기록한다.

현재 범위에서 제품 수정이 필요한 결함은 발견하지 못했다. 문서의 snapshot tick 설명이 초기 초안과 달랐던 점을 생산자에게 전달했고, 현재 `02_2d_animation.md`가 실제 이벤트 tick 기준으로 정정된 것을 확인했다.
