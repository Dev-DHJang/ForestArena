# 추가 콘셉트 등록과 사용 규격

- 2026-10-24 사용자의 선택형 답변 `네 장 모두 등록 승인`을 `approval.json`으로 기록했다. 로컬 정리 허용과 최종 이미지 채택을 별도로 기록한다.
- 승인 당시 `normalized-candidates.json`과 네 PNG 해시는 고정한다. 해당 보고서의 `user_approved: false`는 최종 답변 이전의 검토 스냅샷이므로 다시 쓰지 않는다. 현재 채택 여부는 별도 승인 기록과 설치 검사가 확인한다.
- 생성: 내장 이미지 생성 도구. `02_prompts/`에 실제 사용 프롬프트, `03_drafts/`에 원본 시안, `05_normalized/`에 최종 승인 후보를 둔다. 등록 PNG는 승인 후보와 바이트 단위로 같다.
- 편집: alpha 8 미만 잔여물 제거, 필요할 때만 비율 유지 축소, 투명 캔버스 중앙 배치. 다시 그리기·확대·신체/의상 변경은 하지 않았다. 세부 수치는 후보 보고서에 있다.
- 용도: 1024×1536 실제 투명 RGBA, 전신과 최소 48px 여백. `assets/character/<id>/concept/personality-v01.md`에서 사용하는 추가 정지 이미지다. 별도 게임 화면·카탈로그 연결이나 기존 대표 콘셉트 대체는 하지 않는다.
- 권리: 승인된 프로젝트 캐릭터를 참조한 생성 파생 이미지이며 사용자가 최종 채택했다. 외부 이용 권리 검증은 주장하지 않는다.

## 데이터 보존과 호환

- 최신 `origin/develop` 기반 별도 작업 공간에서 manifest의 기존 항목을 그대로 두고 4개를 끝에 추가했다. 다른 작업의 더 최신 모션을 이전 작업트리의 파일로 덮지 않았다.
- 기존 type=`concept` 네 장, CharacterData의 ID·이미지 참조·스키마, 전투·모션·UI는 유지한다. 새 항목은 `concept-variant` / `personality`이며 대표 ID와 참조 해시를 별도 기록한다.
- 외형 JSON의 추가 규칙은 허용 ID 네 장의 정지 비전투 자세만 예외로 삼는다. 기존 캐릭터별 외형 항목은 바꾸지 않는다.
- 설치 기록은 기존 manifest와 2115개 기존 파일 해시를 보존한다. 기존 이력 검사 도구는 정확한 승인·메타데이터·파일 해시가 확인된 네 추가 항목만 비교에서 분리하며 알 수 없는 추가·중복·일부 누락은 거부한다.
- `verify.sh`에 구조·정리·등록 검사와 Godot PNG 가져오기 검사를 연결한다. 잘못된 승인·변경된 해시·중복·네 장 전체 누락도 실패해야 한다.
