# 추가 콘셉트 데이터 약속

- 캐릭터 4명과 기존 대표 type=concept 항목은 유지한다. 새 항목은 type=concept-variant, variant=personality, reference_concept_asset_id=<기존 대표 ID>다.
- 새 자산 ID와 파일 이름은 <character-id>-concept-personality-v01이며 승인 후 기존 캐릭터 concept 폴더에 PNG를 추가한다.
- CharacterData 필드·스키마·concept_image·concept_asset_id와 UI 연결은 변경하지 않는다. 추가 자산은 디자인 기록에서 참조한다.
- 외형 계약의 추가 비전투 포즈 규칙은 비전투 추가 콘셉트의 전투 자세 요구만 제외한다. 인간형 신체·종 특징·색상·의상·장식·금지 구조는 그대로 적용한다. 전투 모션이나 기존 대표 콘셉트의 자세 조건을 완화하지 않는다.
- 제작자는 승인 콘셉트와 외형 계약을 읽는다. 등록 검사와 외형 검사는 대표 4항목과 추가 4항목을 구분한다. 기존 manifest 보존 도구는 정확히 승인·해시가 확인된 추가 항목만 허용하도록 보완한다.
- 원본과 시안·승인본의 해시, 프롬프트·생성 방식·승인 이력을 기록한다. 외부 권리 검증을 새로 주장하지 않는다.
- 실패한 생성본·승인되지 않은 시안은 assets 및 manifest에 등록하지 않는다.
- 2026-10-24 사용자 `네 장 모두 등록 승인`으로 확정한 PNG 네 장을 추가한다. 최종 채택 승인 기록은 `approval.json`이며 승인 당시 보고서·PNG 해시에 묶인다. 과거 검토 보고서는 불변 스냅샷으로 유지한다.

## 로컬 규격 정리 준비 코드

- 실행에는 별도 `normalization-permission.json`이 필요하다. 사용자의 로컬 정리 명시 답변 전에는 이 승인 파일을 만들거나 실제 시안에 실행하지 않는다.
- 승인 기록은 고정된 원시 후보 보고서 SHA-256과 정책을 연결한다. 정책은 alpha 8 미만만 제거, 48px 투명 여백, 비율 유지·축소만 허용, 다시 그리기 금지다. 보고서나 정책이 바뀌면 거부한다.
- 후보는 별도 `05_normalized/`와 `normalized-candidates.json`에만 만든다. 기존 파일을 덮어쓰지 않고 대표 콘셉트·모션·manifest에는 쓰지 않는다.
- 로컬 정리 허용과 최종 이미지 채택 승인은 다르다. 정리 결과도 다시 시각 검토하고 사용자 승인을 받아야 등록할 수 있다.
- 준비 코드의 자동 검사는 임시 폴더의 단색 도형만 사용한다. 합성 테스트의 가짜 승인 데이터는 실제 캐릭터 편집 허가나 사용자 최종 승인으로 재사용하지 않는다.
