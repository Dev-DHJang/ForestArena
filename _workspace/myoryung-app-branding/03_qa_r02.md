# 묘령 앱 브랜딩 독립 확인 2차

2026-10-16. 1차의 APK 픽셀 비교 방법을 바로잡고 같은 원본·APK의 전체 이미지 비교를 다시 실행했다. 구현 파일은 바꾸지 않았다.

판정: **구현·시각·Android 빌드와 패키지는 pass, 전체 완료는 물리 기기 미연결로 blocked**. 기본 전체 검사도 최종 PASS로 확인했다. 1차의 나머지 시각·설정·원본 보존 검토를 유지하며, 이 문서가 APK 이미지 비교 결과를 대체한다.

## 1차 판정 정정

처음 사용한 Pillow `ImageChops.difference(RGBA).getbbox()`는 알파 차이가 0이면 RGB 차이를 놓칠 수 있다. 따라서 1차의 전경까지 “픽셀이 완전히 일치한다”는 문장은 잘못된 검사 결과였다. 이를 원시 RGBA 바이트와 NumPy 채널별 배열 비교로 고쳤고 `03_qa_r01.md`와 `qa-independent-evidence.json`도 함께 정정했다.

## 실제 APK 재검사

| 대상 | RGBA 바이트 | 알파 | 불투명 RGB | 차이가 있는 픽셀 |
| --- | --- | --- | --- | --- |
| xxxhdpi 일반 | 원본과 동일 | 동일 | 동일 | 0 |
| xxxhdpi 배경 | 원본과 동일 | 동일 | 동일 | 0 |
| xxxhdpi 전경 | 낮은 알파 RGB 일부 다름 | 동일 | 동일 | 6,457 |
| 시스템 시작 아이콘 | 낮은 알파 RGB 일부 다름 | 동일 | 동일 | 6,457 |

전경과 시스템 시작 아이콘의 차이 6,457개 중 4,577개는 완전 투명한 픽셀이고, 1,880개는 알파가 1–31인 픽셀이다. 알파가 32 이상인 영역은 RGB도 모두 같다. RGB 차이에 알파 비율을 곱해 실제 합성 영향에 맞춰 비교한 결과, 0–255 척도의 채널 평균 차이는 약 0.007816, 최대 차이는 약 10.306이다. 따라서 원본과 바이트가 완전히 같다고 주장하지 않으며, WebP 변환에서 거의 투명한 가장자리 색이 달라진 것으로 판단한다.

Godot Image API로 APK에서 꺼낸 WebP 전경을 직접 불러 48·72·128·192px 및 숲 배경 합성 결과를 만들고 원본과 나란히 시각 검토했다. 특히 요청받은 128·192px에서 얼굴·두 귀·리본·머리 가장자리에 눈에 띄는 변색이나 잔상 차이를 발견하지 않았다. 숲 배경 합성도 같은 범위에서 차이를 구별하기 어렵다. 이 변환 차이를 구현 결함으로 판정하지 않는다.

기존 완성 아이콘의 원형·둥근 사각형 마스크 검토 12개는 1차 결과를 유지한다. 실제 launcher나 시스템 시작 화면에서 보이는 최종 결과는 물리 기기 실행·영상으로 확인해야 하며 아직 미실행이다.

## 증거와 재현

- `qa-independent-evidence.json`: 정정 이유, `rgba_bytes_identical_to_source`, 알파·불투명·알파 32 이상 비교, 차이 픽셀 수와 알파 가중 RGB 차이를 각각 기록했다.
- `qa_apk_previews.gd`: 실제 APK에서 꺼낸 WebP와 원본을 Godot로 읽어 비교 PNG를 만든다. 명령은 `godot --headless --path . --script _workspace/myoryung-app-branding/qa_apk_previews.gd`다.
- `previews/qa-apk-comparison.png`: 위에서부터 원본 전경 / APK 전경 / 원본 전경+숲 / APK 전경+숲. 각 행은 왼쪽부터 48·72·128·192px다.
- `previews/qa-apk-foreground.webp`, `previews/qa-apk-background.webp`, `previews/qa-apk-splash.webp`: 실제 APK에서 수정 없이 꺼낸 이미지 바이트.

물리 기기 검사는 여전히 blocked다. 2차 기록은 검사 방법을 정정한 기록이며, 미실행 검사를 통과로 바꾸지 않는다.

## 최종 자동 검사 확인

`verify.log` 마지막의 `Forest Arena verification passed.`와 `checks.json`의 종료코드 0을 함께 확인했다. SCRIPT ERROR는 0개, ERROR는 12줄이며 모두 종료 시 남은 리소스(`resources still in use at exit`) 메시지다. WARNING은 16줄이다. 자동 검사 통과와 이 종료 메시지를 함께 기록하며, 오류 메시지가 전혀 없었다고 보고하지 않는다.

`verify-docs-final.log`의 문서 PASS, `verify-resources.log`의 논리 자산 518개·품질별 차이 24개 PASS, `branding-checks.json`의 실제 APK 아이콘·시작 설정 PASS도 확인했다. APK에서 읽은 설정은 `show_image=false`, `minimum_display_time=0`, 기존 `scenes/local_ai_app.tscn`, 새 묘령 앱 아이콘 경로다. 시스템 시작 branding image는 완전 투명이며, 실제 APK SHA-256은 독립 QA 증거에 적힌 값과 같다.

물리 Android 0대 상태는 바뀌지 않았다. 검토 가능한 draft PR 준비는 가능하지만, 전체 QA 완료 또는 develop 병합 통과 판정은 하지 않는다.
