# 메뉴 v08 독립 품질 확인 r05 — 제작 도구 정적 검토

2026-10-20. 파일 읽기만 수행했다. Penpot·CUA·API를 실행하지 않았다. 대상은 penpot-fast.js, penpot-prototype-fast.js, penpot-export-batch.js, penpot-finish.js, penpot-comparisons.js, penpot-audit.js, resize_exports.py와 baseline이다.

## 판정

**FIX — 최종 audit의 실제 프로토타입 검사 보강 2건.** 생성 도구의 주요 페이지·보존·출처 흐름에서는 차단 결함을 찾지 못했다. 이 판정은 도구 정적 검토에만 한정하며 실제 UI·PNG·클릭·저장 완료를 뜻하지 않는다. 과거 탭 중단 전 메모리 작업량이나 폐기된 배경 실행을 저장 완료 증거로 사용하지 않는다.

## audit 수정 요청

1. 예상 밖·중복·숨김 HIT와 click/navigate-to 검증. 현재 예상 활성 조작별로 name·위치가 맞는 실제 HIT의 목적지 ID를 대조한다. 하지만 실제 HIT 전체 반복은 주로 최소 영역·범위·전환만 보며, 예상 목록 밖 또는 중복 HIT가 남았는지는 확인하지 않는다. 실제 HIT가 hidden인지, 첫 동작 trigger가 click인지, action type이 navigate-to인지도 명시 대조하지 않는다. 이 상태에서는 낡은 모달 뒤 조작 영역이나 다른 상태의 초과 HIT가 남아도 통과할 가능성이 있다. 마지막 MODAL/scrim 뒤의 기대 조작 목록과 실제 HIT를 name+xywh로 1:1 대조하고 총개수·중복·visible·trigger·action·모든 목적지를 검사해야 한다.
2. 실제 SNAPSHOT 검사. 현재 audit는 prototype에서 보이는 SNAPSHOT/v08가 한 개인지, 현재 장면의 N.snapshots media ID인지, 위치/크기 1920×1080이 맞는지를 대조하지 않는다. 따라서 오래된 또는 다른 상태의 이미지 위에 조작 영역만 맞아도 통과할 가능성이 있다. 한 개의 보이는 snapshot과 현재 export/media 연결을 독립 확인해야 한다.

두 요청은 주 작업 담당자에게 즉시 전달했다. 코드가 실제 잘못된 화면을 생성했다고 단정하는 결함이 아니라, 최종 자동 검사의 거짓 통과를 막기 위한 보강이다.

## 양호한 흐름

- 현재 foreground makeBatch는 await 순서로 끝까지 실행하며 background 시작 함수를 오류로 막는다. 상태 페이지는24개씩 분할되고 새 상태는 실제 열린 페이지에서 생성·복제한다. 복제 후보는 같은 페이지로 제한한다.
- 원본14개는 baseline의 ID로 열린 원본 페이지에서 갱신하고 기존 자식은 삭제하지 않고 숨긴다. 새 v08 소유 자식만 다시 제작한다. 기존14개 prototype ID도 baseline과 비교하고 원본 자식을 숨겨 보존한다. baseline에는 Native14·Proto14가 각각 실제로 존재한다.
- prototype fast의 준비·연결은10_Prototype 페이지 활성 검사를 포함한다. 비교 화면은 전용 페이지를 연 뒤 같은 native spec으로 다시 그려서 다른 페이지의 노드를 직접 복제하지 않는다.
- 모달 HIT 생성은 마지막 MODAL/scrim 뒤의 유효 button/hotspot만 사용한다. unused HIT를 삭제하고 사용 불가 조작은 제외한다. wiring은 기존 초과 interaction을 제거하고 click/navigate-to/dissolve200ms/ease-out으로 맞춘다.
- 선택 상태마다 각 control의 실제 destination ID를 검사하는 기본 audit 경로는 존재한다. state 이름만 비교하는 방식은 아니다. 위 1번은 이를 실제 전체 HIT의 1:1 일치까지 넓히는 요청이다.
- 1920 export는 실제 Penpot board.export 결과와 SHA-256을 기록한다. resize_exports.py는 실제1920 파일의 SHA와 크기를 확인해 Pillow LANCZOS로1280을 만든다. importSnapshotBatch는 원본 ID·이름·specHash·원본SHA, 실제1280파일의 PNG크기·SHA를 대조한다. source.sha256이 이미 있으면 JS는 그것을 재사용하지만 Python이 실제 원본 파일 SHA를 재확인하므로 이 두 단계를 함께 수행할 때 출처 흐름이 유지된다.
- snapshot/image/control signature 변경 시 prototype 준비를 다시 하며 prepared가 바뀌면 wired를 지워 연결을 다시 하게 한다.
- 실제 저장/다시 열기는 도구의 메모리 ready와 별개이며 반환 값도 savedVerified:false로 구분한다. 저장·재열기 증거를 최종 결과에서 별도로 확인해야 한다.
