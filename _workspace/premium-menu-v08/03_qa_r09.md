## 독립 확인

`qa_r09_static.py`는 생산 검사기를 호출하지 않고 JSON과 기존 baseline 해시를 직접 읽었다. 결과 `qa-r09-static-check.json`에3631개 확인과 오류0개를 남겼다.

- 최종263개 이름이 고유하다. 보존한214개 baseline의 이름·순서가 정확히 유지된다. UTF-8/정렬된 키/공백 없는 JSON을 직접 SHA-256으로 계산해 기존23개 변경·49개 추가·191개 불변임을 확인했다. 생산자의 변경 목록과도 일치한다.
- 모든 활성 컨트롤의 목적지가 내부 또는 명시된 기존 외부 화면에 있고 터치 크기가72px 이상이다. 모든 장면의 전환은200ms다. 모달에서는 마지막 `MODAL / scrim` 뒤에 있는 조작만 경로로 사용해 가려진 배경 버튼을 제외했다.
- 소리·화면효과·접근성·미니맵·최대 글자 크기의5개 대표 변경에 대해 적용→닫기에서 새 값과 저장 상태를 유지한다. 복원 취소는 저장한 값으로 돌아간다. 복원 확인은 실제 기본값을 미적용 상태로 보여 주며 이전 저장값을 따로 유지한다. 변경 취소 확인의 취소는 복원 중인 값, 버리기는 이전 저장값으로 돌아간다. 복원 값 적용→닫기는 기본값을 유지한다.
- 실제 기본값은 `scripts/audio_director.gd`의 음악0.6/효과음0.8, `scripts/local_player_store.gd`의 접근성1.0/진동켬/효과축소끔과 미니맵투명도30/얼굴/이름켬을 읽어 대조했다. 초기 예시70%/70%는 기본값이라고 잘못 해석하지 않았다.
- `settingsState`만 신뢰하지 않고 해당 장면들의 화면용 음량/투명도 글자·켬/끔 버튼·텍스트 크기 선택도 각각 비교했다.
- 로비 출발과 일시정지 출발의 플로팅 양쪽에서 크기/투명도 안내를 열고 취소·확인하면 같은 플로팅 출발 상태로 돌아간다. 복원 취소도 플로팅을 유지하며 복원 확인만 고정 상태로 돌아간다.
- 닉네임 수정에는 `INPUT / nickname` 사각 입력 표현과 편집 가능한 `INPUT / value` 텍스트가 존재한다. 예시 이름은 숲빛 여행자이며 실제 입력은 앱에서 한다는 안내가 있다. 변경 확인→결과→프로필의 이름이 모두 숲빛 여행자다. 시안 예시라는 문구도 있다. Penpot 안의 실제 키보드 입력이나 저장 엔진을 구현했다고 주장하지 않는다.

설정은 한 분류 안의 대표 값 변경·적용·복원을 모델링한다. 여러 분류의 저장 조합과 다른 메뉴에서 재진입한 뒤의 모든 조합은 유한 시안의 한계이며 이 정적 통과가 런타임 저장 검사를 대신하지 않는다.

## 수동 검사 계획 갱신

`manual-click-plan.json`과 `.md`를 최종263개 spec 기준으로 갱신했다. 기존17개와 닉네임 확인/변경 프로필·일시정지 출발 플로팅의2개를 합쳐 **19개 경로·148단계**다. 각 단계의 활성 컨트롤·목적지·보드 내부1920/1280중심·확인 문구를 현재 spec에서 다시 계산했다. 기존 플로팅 결함을 우회하던 불필요한 재클릭은 제거했다.

모든 case와 step은 **NOT_RUN**을 유지한다. 계획 파일에는 실제 실행 결과가 없다. 전체 메뉴 상태의 시각 검토와 클릭 통과는 실제 새 출력 및 프로토타입 생산 후 별도로 기록해야 한다.
