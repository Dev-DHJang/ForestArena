## 실제 연결 복구

기존 원격 MCP 연결은 플러그인이 켜져 있어도 응답하지 않았다. 공식 npm 패키지 `@penpot/mcp` 2.15.4의 로컬 서버·문서화된 REPL을 사용하여 편집 연결을 복구했다. 호스트 Penpot는 2.18.4여서 플러그인에 버전 차이 안내가 표시된다. 실제 저장·네이티브 요소·출력·클릭 검사를 별도로 수행해야 하며 연결 성공만으로 완료 처리하지 않는다.

- `penpot_call.py`: 공식 로컬 REPL `http://localhost:4403/execute` 호출. 인증 정보 수집이나 브라우저 내부 상태 조작을 사용하지 않는다.
- `plugin_server.py`: 공식 캐시의 plugin.js를 루프백으로 제공한다. 원격 자동 연결 대신 공식 수동 연결 UI가 열리도록 `mcp` 자동 감지 값과 UI URL만 조정했다. 런타임 게임 의존성이나 Penpot 서버 설정은 변경하지 않았다.
- `asset_server.py`: 루프백에서 이 작업 및 v07 자산만 제공하고 현재 요청한 출력·JSON 기록을 저장한다. 브라우저의 이전 명세 캐시를 방지하기 위해 `no-store`를 사용한다.
- 복제는 Penpot의 활성 페이지 제한을 따른다. 기존 기본 화면은 기존 ID·페이지에서 수정하고 새 상태는 `04_Lobby_Meta` 별도 영역에 둔다. 원본 텍스트와 컴포넌트 인스턴스는 유지된다.
- 공식 execute-code 처리기가 호출 종료 후 자식 순서 플래그를 복구하므로 비동기 제작기는 API 작업마다 자연 순서와 오류 검증을 명시한다. `check-fast-helper.cjs`는 비활성 페이지 복제 금지·역순 자식·중복 이름·중간 정지·삭제된 객체 재시도를 포함해 검사한다.

## 자동 검사 해석

`./scripts/verify.sh`는 LAN 검사 전까지 통과한 뒤 검사용 포트 18081 중복으로 중단되었다. 해당 포트가 비워진 뒤 중단된 LAN 검사와 이후 Android LAN·온라인 서버·하네스 검사를 순서대로 다시 실행했다. 각 명령은 통과했으며 최초 전체 스크립트의 종료 코드가 0이었다고 기록하지 않는다. `verify.log`, `verify-resume.json`과 각 후속 로그를 함께 본다. 하네스의 최초 실행에서 마무리 기록 링크가 없던 문제도 문서 작성 뒤 재검사하여 해결했다.

문서 검사·Godot 리소스 검사·아이콘 패키지 검사와 독립 이미지 확인 결과는 각각 기록한다. 실제 Android 기기가 연결되지 않아 설치·런처·첫 실행·재실행 결과는 미검증이다.
