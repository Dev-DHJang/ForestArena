# 메뉴 v08 독립 품질 확인 r08 — 중단 시 실제 출력 114쌍

2026-10-20. `forest-arena-qa` 지침에 따라 로컬 PNG와 기록만 독립 확인했다. Penpot·CUA·API는 실행하지 않았고 생산 파일은 수정하지 않았다.

## 판정과 범위

**FIX — 닉네임 변경 화면의 입력 표현 누락.** 출력 파일의 출처·해시·규격·축소 픽셀 대응은 검사 범위 안에서 PASS다. 전체 화면 완료, 실제 클릭 통과, 최종 Penpot 저장, 범위 밖 원본 보존 또는 Android 실기기 통과를 뜻하지 않는다.

검사 시작 때 실제 기록은 native 1920×1080 PNG 114개, 축소 1280×720 PNG 114개다. 이 가운데 Penpot 스냅샷 반영 기록은 113개이고 유란 이야기 전체 필터 1개는 로컬 축소만 존재한다. 시작 당시 새 설정 수정이 반영 중이라 `scene-spec.json`은 261장면이었다. 이 수와 이전 214개 기준을 혼동하지 않는다.

## 독립 파일 검사

별도 코드 `qa_r08_pixels.py`를 실행해 시작 때 읽은 `export-records.json`과 `derived-snapshots.json`을 `qa-r08-records-snapshot.json`에 고정했다. 결과는 `qa-r08-pixel-check.json`에 파일별 실제 SHA-256·바이트 수·규격과 오류 목록으로 남겼다.

- native 114개, Penpot 스냅샷용 축소 기록 113개, 실제 축소 목록 114개를 각각 검사했다. 두 축소 목록의 겹치는 파일은 양쪽 기록을 독립 비교했다.
- 모든 실제 SHA-256·기록 바이트 수·PNG 규격·중복 이름 검사에서 오류가 없었다.
- 축소 파일 114개 모두 sourceFilename/sourceSha256/nativeSpecHash가 해당 native 기록과 일치했다.
- native 전체 RGBA를 Pillow LANCZOS로 메모리에서 1280×720으로 다시 축소한 전체 픽셀과 실제 파일이 114쌍 모두 동일했다.
- 현재 spec과 각 출력의 의미 내용이 같은지 판정하는 검사는 아니다. 수정된 설정 화면은 새 native 출력 후 별도 재검사가 필요하다.

## FIX-08-01 — 닉네임 변경 입력 표현 누락

`MENU08 / NicknameEdit`의 실제 PNG에는 현재 닉네임을 설명하는 본문과 취소/변경 확인만 있다. 사용자가 새 닉네임을 넣는 칸이 없다. 현재 spec에서도 `INPUT` 요소가 없고 `변경 확인`은 변경 결과 상태 없이 기본 `SCR_24_Profile`로 돌아간다. 친구 검색의 입력 예시 칸과도 표현이 다르다.

이는 기존 닉네임 변경 기능을 확인 창과 혼동하게 한다. 편집 가능한 입력 예시 칸과 명시적 시안 예시, 확인 뒤 바뀐 이름을 보여 주는 결과/프로필 상태를 제공하거나 단순 설명 창으로 행동 문구를 바꿔야 한다. 독립 QA가 root에 즉시 보고했다. 실제 런타임 저장 기능을 새로 구현하라는 요구는 아니다.

이 PNG의 SHA-256은 `qa-r08-pixel-check.json`의 `MENU08 / NicknameEdit` 행으로 고정했다. 수정 뒤 이 통과 기록을 재사용하지 않고 새 PNG를 확인해야 한다.
