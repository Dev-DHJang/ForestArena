# 현재 개발 APK 실기기 결과

## 검사 대상과 현재 판정

현재 작업 폴더의 코드와 승인 자산을 보존한 복제본으로 검사했다. 원본 코드 버전은 `423b1a898f25fa10609833dd9c5449df33a521fa`, APK SHA256은 `6b855d25aa5376f4b24958ce985e1c88cad21b6f0df5bdb1e82c8b613a3d092f`이다. 실제 기기는 S23 Ultra SM-S918N(Android 16)와 Tab S5e SM-T725N(Android 11) 두 대다.

**두 기기의 자동 검사를 마쳤고 사용자 수동 관측을 기다린다.** Solo·Team은 실제 제품 결함으로 실패했다. Tab의 새 10분 반복과 두 실제 APK의 LAN 검사를 완료했다. 실제 기기 네 대·30분/28개 조합 전수 검사는 수행하지 않았다.

## 실행별 증거

- 현재 r02 `70873fded0584336b82ad757cb1e4c03`: 설치/터치/1대1 통과, 실제 Solo·Team 실패. 복싱 글러브 ID의 정상 `yu-ran.base-*`를 허용하지 않은 도구 판정 오류와 LAN 준비 화면 복귀 오류도 보존했다. 제품 결함과 도구 결함을 구분한다.
- 현재 r03 `a1f6f9438c314c3092c3b1853630d151`: ADB 서버 종료 요청을 관측했고 요청자는 미확인이다. 실행은 blocked다.
- 현재 r04 `86291f16cf914b508b420f27cb040eb4`: 별도 ADB 서버 포트 5038을 사용했다. S23 SOAK는 604.951초/5판 pass가 저장됐고 Tab SOAK 종료·LAN·전체 마무리 기록은 없다. 기존 파일을 변경하지 않고 `build/android-current-device-test/r04-interruption.json`과 `.md`에 부분 판정을 따로 남겼다. Mac 재시작 뒤 호스트 프로세스가 없음을 확인했지만 재시작이 이전 종료의 원인이라고 단정하지 않는다.
- S23 LIFE 재검사 `877bc77e60ff4f668a70361aec6d1ac2`: DEV/UI/LIFE 3개 pass, 선택하지 않은 9개 미실행. 원본 전후와 설치 APK 해시가 같고 검사 전후 원래 저장 경로 해시도 같다.
- Tab SOAK 재검사 `967a78215f6d4ae7964590294153121b`: ADB 사전 조회 시간 초과로 DEV/SOAK blocked. 10분 반복은 시작하지 않았다. Mac 주소는 `192.168.45.135`; S23 TCP는 응답하고 Tab의 기존 무선 디버깅 주소 `192.168.45.145:45279`는 응답하지 않아 사용자에게 연결 확인을 요청했다.
- Tab SOAK 재연결 검사 `53b036796d3b4f61b019777e1ddd46db`: 동일 하드웨어의 새 주소에서 605.277초/5판, 종료 0과 입력 해제·로비 복귀를 확인했다. 이 실행의 device-1은 Tab 단독 별칭이다.
- LAN 재검사 `c4d05e973e334e3d98a500f018d77d92`: 원본 요약은 pass 8개·blocked 2개·미실행 14개, 종료 2다. 안내 Label을 진단 목록에서 읽을 수 없어 LAN-02를 blocked로 보존하고 네 실제 캡처를 별도 `lan02-visual-review.json`에서 판독했다. 독립 QA도 네 문구·화면·해시를 확인했다. 실제 세 번째 APK 대신 정원만 채우는 도구 참가자를 사용했으며 나가기 응답은 미확인이다. 소켓·서버 종료 증거와 오류 화면 통과를 구분한다.

동일 APK의 완료 관측을 참조하는 중간 JSON 색인은 `build/android-current-device-test/current-evidence-index-incomplete.json`이다. 기기별 24개 사례 중 pass 13개·fail 2개·blocked 7개·미실행 2개이며 단일 전체 실행의 통과를 뜻하지 않는다. 주요 증거는 `build/android-current-device-test/`의 실행별 JSON·화면·게임 로그에 있다. 기존 r04의 원문 로그를 보존하며 공개 검토용으로 비밀값을 가린 `game-partial-redacted.log`를 따로 작성했다. 미완료 로그와 메모리에서 잃은 성능 표본을 완전한 종료 증거로 사용하지 않는다.

새 관측 색인 `current-evidence-index-automatic-complete.json`은 pass 20개·fail 2개·미실행 2개를 참조한다. LAN-02 두 항목은 동일한 두 기기 합산 검토를 참조한다. 원본 실행 판정을 덮어쓰지 않고 통과의 범위를 함께 기록했다. 단일 전체 실행 통과 또는 제품 전체 통과를 뜻하지 않는다.

LAN 정상 경기의 승자 슬롯 1·종료 tick 5935·해시 `8a7ecf67453ec311eefbcda2223ab93e33fa5caf44f0b818beac2a9af8f98d83`는 서버와 양쪽 APK에서 일치했다. 65초 이탈 패배의 승자 슬롯 2·종료 tick 5999·해시 `413026f8b7bcce1f14c41e69a1c7c7dff6a16e3009cf9306c72aac8c8f5f8699`는 서버와 Tab에서 일치했다. 이때 S23의 마지막 결과는 비어 있어 양쪽 이탈 패배 해시 일치로 확대하지 않는다. 단절 전 실제 이동 표본과 단절 뒤 서버 입력 초기화 tick 1263/2398을 확인했으며 단절 직전 서버 입력값 자체는 미확인이다.

## 제품 결함

마지막 기회를 소진한 캐릭터의 `DEAD/0`이 다음 전투 tick에서 `FALL/RUN`으로 바뀌고, 경기장 밖 판정에서 기회가 `-1`, `-2`로 줄었다. Solo·Team에서 실제 남은 참가자 또는 팀이 있어도 결과가 끝나지 않았다. 원인과 독립 재현은 [품질 확인](03_qa_r02.md)에 기록했다. 제품 코드·동결 APK를 수정해 검사를 통과시키지 않았다.

## 성능과 수동 확인

r02에 저장된 성능 표본을 정리했다. 기능 검사·실패한 Solo/Team·일부 반복 구간이 섞인 값이며 완료된 10분 반복만의 측정은 아니다. 승인된 합격 수치가 없으므로 성능 합격으로 판정하지 않는다.

| 관측 | S23 Ultra | Tab S5e |
| --- | --- | --- |
| FPS 표본 범위 / 중앙값 | 57.03–60.10 / 60.00 (177개) | 7.50–60.00 / 59.62 (51개) |
| 300프레임 표본별 p95 범위 | 16.67ms (177개) | 16.67–145.00ms (51개) |
| 메모리 PSS 범위 | 251.2–552.8MiB (33개) | 290.1–459.7MiB (30개) |

| Android thermal status | 관측 표본 모두 0 | 관측 표본 모두 0 |

Tab의 약 7.5FPS 표본은 Solo/Team 세대 12·13에서 관측됐다. 성능 저하 원인은 별도 분석이 필요하며 남은 기회 음수 결함과 같은 원인이라고 단정하지 않는다. p95는 각 300프레임 표본의 값으로 실행 전체의 p95가 아니다. PSS는 앱 메모리 사용량의 한 측정 방식이다. 온도는 서로 다른 센서 배열 전체 범위이며 표면 온도와 같다고 해석하지 않는다. 0°C 읽음은 미확인으로 제외했다. 원 자료와 집계는 `build/android-current-device-test/performance-observed-summary.json`에 있다. r04에서 잃은 성능 표본을 이 수치로 대체하지 않는다.

수동 확인은 [현재 APK 수동 재검사](05_manual_checklist.md)를 따른다. 실제 동시 터치의 체감, 캐릭터 모션·가독성, 소리·진동은 자동 입력의 통과 결과로 대체하지 않는다.

새 Tab SOAK 독립 실행에서 수집한 측정은 FPS 36.915–60.002/중앙값 59.754(115개), 각 300프레임 p95 최대 33.333ms, PSS 286.166–359.160MiB(23개), 양수 온도 센서 27.5–42.4°C, thermal status 0이다. FPS 표본의 처음부터 끝까지는 약 595.907초, 시스템 표본은 약 658.534초이며 DEV/UI 준비와 정리 구간도 포함한다. 이 수치는 r02 혼합 표본과 분리하며 승인된 성능 합격 기준은 없다.

수동 검사 세션 `77e501cdb8af46cfbccc93d4af314fc6`에서 양쪽 실제 LAN 경기를 준비하고 자동 입력을 해제했다. 초기 peer 상태 신호가 없는 v1 진단의 false만으로 연결 실패를 판정하지 않고 실제 두 참가자 경기 시작을 확인했다. 앞선 준비 실패 `82c51dcee4f941d480b4bd5bb7adebba`도 보존했다. 사용자의 실제 Wi-Fi 관측을 기다리며 아직 수동 통과로 기록하지 않는다.
