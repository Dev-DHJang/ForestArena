### 확인된 실제 제품 문제 — Solo 탈락 상태가 다음 tick에 풀림

- S23의 MODE-01 Solo 8명은 최대 300초를 넘겨 fail했다. 실제 마지막 경기 데이터는 mode 1, tick 18,005, 승자 없음이며 참가자 모두 HP 0이다. 남은 기회는 -195, -109, -14,321, -174, -124, -127, -65, -152까지 줄고 탈락한 참가자가 CHARGE·RUN·ATTACK_RECOVERY 상태로 계속 동작했다.

## LAN 정원 검사 도구 독립 확인

- 최초 보완의 호스트 107개 단위 검사는 pass다(`qa-fleet-capacity-r01.log`). 실제 Godot 서버의 LAN v1·v2 검사도 각각 pass다(`qa-capacity-r01.log`, `qa-capacity/e7706c2bb8614130a5ba6ec8876e369f/`). 이 검사는 loopback의 별도 임시 포트이며 실제 기기 0대·APK 오류 화면 미실행을 결과에 명시한다.
- `ProtocolPeer`는 임시 통신 참가자다. v1은 인증 없이, v2는 메모리의 테스트 API에서 인증한 뒤 슬롯 2를 채운다. 실제 Android 참가자나 자동 전투 결과로 세지 않는다. 송신은 join/leave와 WebSocket pong뿐이며 전투 입력은 보내지 않는다. 인증값과 재접속값은 관측 결과에 남기지 않는다.
- 통신 대기는 연결/응답 제한, 취소 확인, HTTP 응답 16KB·프레임 8KB·최대 128개 메시지 제한이 있다. 오류/정상 종료 모두 소켓을 닫고 실제 서버 재현에서는 leave 확인 뒤 방장 슬롯 1이 disconnect 승리를 받았다. 테스트 서버는 지정한 프로젝트·loopback/CIDR에서 실행하고 검사 뒤 게임 서버와 임시 API를 닫는다.
