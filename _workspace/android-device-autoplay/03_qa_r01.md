# Android 실기기 자동 플레이 독립 확인 r01

- 날짜: 2026-10-11
- 기준: 승인 요청, `00_request.md`, `01_contract.md`, README와 Android·LAN 현재 구현.
- 확인 역할: `forest-arena-qa`, `forest-arena-mobile`.
- 중간 판정: 실행 도구와 Godot 자동 검사는 pass, 실제 기기 smoke 실행 증거 확인 대기. 기기 실행 전에는 물리 기기 통과를 기록하지 않는다.

## 사전 발견과 수정 요청

1. 현재 ADB에는 네 transport가 보이지만 실제 기기는 두 대다. 각각 IP 연결과 mDNS 연결이 같은 물리 기기를 가리킨다. CLI serial 문자열뿐 아니라 `ro.serialno`/`ro.boot.serialno` 중복도 검사하도록 생산자에게 전달했다.
2. 최신 LAN v2는 게스트·닉네임과 서버의 `/internal/v1/lan/auth` 인증을 요구한다. 이전 익명 LAN 경로로 검사를 우회하면 안 된다. 테스트 API 결과와 실제 데모 API/DB 인증 결과를 구분하도록 전달했다.
3. 설치된 Godot 4.7.1 Android 템플릿은 `command_line_params` string array를 읽지만, 기본 시작 Activity의 인자 정리 때문에 외부 전달 값이 실제 APK에 도달하지 않았다. 최초 정적 판단만으로 전달 성공을 결론 낸 부분은 실제 기기 r04 실패로 정정했다. debug에서 정확한 검사 인자 세 값만 읽는 전달 코드와 APK 사전 표시 확인을 추가했다.

## 실행한 독립 검사

| 검사 | 결과 | 증거와 의미 |
| --- | --- | --- |
| 문서 위치·상대 링크·한국어 규칙 | pass | `./scripts/verify-docs.sh` |
| 테스트 API 게스트 두 개 분리 | pass | 서로 다른 player ID, nickname 없는 내부 LAN 인증은 409 |
| 테스트 API 닉네임 중복 | pass | 대소문자만 다른 이름의 두 번째 등록은 409 |
| 테스트 API 내부 서비스 인증 | pass | 서비스 값 없으면 401, 올바르면 등록 게스트만 반환 |
| 테스트 API 갱신·동일 요청 반복 | pass | 동일 요청 재수행은 같은 결과, 다른 successor로 이전 토큰 재사용은 401, player ID·닉네임 유지 |

추가 도구 함수 검사: serial 중복·최대 수·부적절한 문자 거절, 1~4대별 28개 조합의 중복 없는 균등 배정, 전체 미실행의 blocked 집계, fail/blocked 우선순위, 인증 문자열 제거, 1초 화면 시간 제한, 예상하지 않은 ADB 단절의 blocked 처리를 독립 Python 검사로 확인했다. 현재 함수 단위 결과이며 완성된 CLI·실기기 전체 결과를 뜻하지 않는다.

테스트 API 검사는 격리된 메모리 fixture를 검증한 결과다. 실제 API·PostgreSQL·운영 인증 통과를 뜻하지 않는다. 인증 토큰 값은 기록하지 않았다.

## 통합 리뷰에서 생산자에게 전달한 항목

- Godot 진단 좌표는 0~1 중심 좌표인데 초기 도구는 절대 좌표·왼쪽 위 기준으로 해석했다. 실제 ADB 화면 크기로 변환하고 현재 스크롤에 가려진 항목을 제외해야 한다.
- UI ID·touch/config 상태 형식이 생산자와 도구 사이에서 달랐다. 공용 계약과 함께 맞춘 뒤 검사해야 한다.
- 궁극기 준비 검사에 필요한 자동 궁극기 사용 중지가 초기 런타임에서 처리되지 않았다.
- 앱 재실행 뒤 PID가 바뀌므로 게임 로그 수집도 다시 시작해야 한다. 정상 반복 시간 종료를 한 판 실패와 구분하고, 각 선택의 실제 경기 반영을 확인해야 한다.

## 최종 사례 판정 정밀도 검토

- 약/강/특수 공격 검사가 새로운 공격 ID 아무 값이나 받는 문제를 발견했다. 실제 입력 종류와 같은 공격 계열을 요구하도록 생산자에게 전달했다.
- 궁극기 준비 전 실제 터치·게이지 조건, 입력별 해제 상태, 실제 Solo/Team 모드·팀 구분, 결과의 승자·tick·해시 형식 확인을 강화하도록 전달했다. 생산자는 같은 공격 계열 확인, 실제 궁극기 터치·게이지 확인, 입력 해제, 실제 모드·Solo 무팀·Team 4대4, 참가자 승자·양수 tick·64자 해시 확인을 반영했다. 잘못된 공격·없는 터치·잘못된 모드/팀·결과를 거절하는 사례를 포함해 48개 도구 검사를 독립 재실행했고 pass다. 짧은 반복 시간 종료로 완료한 대전이 없으면 미실행으로 남기고 해당 실행 전체를 pass로 올리지 않는다.

## 실제 기기 실행 증거

- r04 실행 `8aff408038bc42f89b82009ae3667730`: 전체 fail. 물리 기기 두 대의 `DEV-01` 새 검사 프로세스 상태 확인이 30초 안에 끝나지 않았다. device-1은 검사 전후 기존 저장 해시 변화도 `UI-01 fail`로 기록됐다. 전체 0 pass·3 fail·20 blocked·2 미실행, 28개 조합은 모두 미실행이다.
- r04 증거는 `build/android-fleet/8aff408038bc42f89b82009ae3667730/`에 보존됐다. 인자 전달 코드가 없는 APK의 실행을 사전에 거절하는 검사를 추가했으며, r04 기존 저장 변경 결과를 후속 검사 통과로 덮지 않는다. r04 뒤의 기본 저장 백업 파일 해시가 실행 전 기본 파일 해시와 같아 기존 주 저장 내용이 내부 백업에 남아 있을 가능성이 있다. 해시 변화 실패 기록은 보존하며 기기의 기존 저장 내용을 자동으로 되돌리지 않았다.
- r08 실행 `817b1ae4ab6a4c1e8c13a8ceee16546e`: 두 기기의 `DEV-01`은 pass로 APK 설치·검사 모드 진입을 확인했다. device-1 상점 마지막 두 상품은 화면 아래에 가려졌고 스크롤이 이동하지 않아 `UI-01 fail`, device-2는 ADB 단절로 `UI-01 blocked`다. 뒤 검사와 28개 조합은 완료하지 못했다. 기존 저장의 종료 해시 조회가 빈 결과여서 추가 fail이 기록됐으나, ADB 단절 상태의 조회 불가와 실제 파일 삭제를 구분하지 못한 도구 문제를 발견했다. r08의 빈 종료 해시만으로 저장 손실을 결론 내리지 않는다. 종료 해시 조회 전후의 연결·명령 완료 확인을 추가해 조회 불가를 blocked로 처리했다. 실제 터치 스크롤은 구매 버튼을 피하는 x=0.19 위치·600ms 드래그로 바꿨다. 해당 실패 경로의 자동 검사까지 48개가 pass다.

## 실제 기기 확인 대기

- 실제 기기 두 대에서 최신 APK의 오프라인 및 LAN 방 생성·참가·결과·재대전 증거.
- 실제 Wi-Fi 끄기/켜기, 동시 터치, 소리 청취·진동 체감은 자동 검사로 대신하지 않는다.
- 네 대·두 경기 동시 실행은 현재 두 대의 증거로 통과 처리하지 않는다.
