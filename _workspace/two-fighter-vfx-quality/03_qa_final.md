# 공격 효과 독립 최종 검토

2026-10-21, 담당 `/root/vfx_qa`. 판정 **pass** — 이번 VFX 변경 범위의 독립 검토를 통과했다. 모션별 사용자 승인과 Android 실기기 확인은 별도이며 미완료다.

## 검토 범위와 방법

- 원 요청, `00_request.md`, `02_image.md`, 모션 행위 검토 문서, 실제 공격 데이터와 표현 코드를 대조했다.
- 실제 효과가 바뀐 8종은 자현 지상 강·공중 약·공중 강·특수와 나비 지상 강·공중 약·공중 강·특수다. 새 후보 발차기·올려할퀴기 2종을 포함해 정상 1.50배와 좌우 반전 소형 1.0배의 각 10종을 확인했다.
- 최종 자료는 `_workspace/two-fighter-combat-v2/review/vfx-r05/`와 그 아래 `mirror-small/`이다. 각 6시점 비교판, 정상·0.25배 재생 화면 표본과 실제 공격 단계별 frame sequence를 대조했다. 36종의 전체 16프레임 비교판도 직접 재확인했다. 연속 모든 영상을 실시간 지켜본 검사로 확대 해석하지 않는다.
- 효과 비대상 28종은 개별 원화·SpriteFrames 해시, 모든 `runtime_variants`, 기대 행위가 종전과 동일함을 확인했다. 본체 표현 코드의 변경은 `effects.sprite = sprite` 연결 한 줄이고, 나머지 상태/지상 약공격은 새 효과의 조기 반환 또는 비적용 분기로 들어감을 독립 확인했다. 28종의 시간·반전·소형 판정은 동일 자료와 같은 실행 경로의 동등성 확인에 근거하며 해당 영상 28개를 새로 연속 재생했다는 뜻이 아니다. 이전 상태값이나 관찰 문장은 복사하지 않았다.
- 새 `review/motion-review.json`에 모션별 구체적 관찰과 판정 근거를 적었다. 결과는 36 pass이며 승인 상태는 `pending`이다.

## 두 회차 수정 뒤 접근 변경

1차는 천 내부가 그려지지 않는 mesh 수명 오류와 원화 바깥 UV, 2차는 귀/머리 부착과 실제 손의 휘두르기 방향 불일치를 발견해 **fix**했다. 단순히 효과의 폭과 색을 바꾸는 방식에서 실제 착용 천을 프레임별로 연장하는 방식으로 접근을 바꿨다. 그 뒤 r03/r04의 연결을 확인했고 촬영상 공중 강 하단 잘림은 공중 시전자만 80px 위로 옮긴 r05로 보완했다. 앞선 두 fix 기록과 자료는 보존한다.

| 자현 좌·우·위 특수 | 목 뒤 착용부와 원화에 그려진 두 꼬리의 방향을 따른다. 좌우로 펼친 뒤 위로 휘두르고 옆으로 돌아온다. 넓은 청색 표면·흰 무늬·접힌 명암이 보이며 새 세 번째 무기를 만들지 않는다. 준비에는 원래 천만 있고 회복 초반 감쇠한다. |

| 공유 효과 | 자현 지상 강·공중 약은 수평 천, 나비 지상 강은 위 곡선, 공중 약은 짧은 할퀴기로 구분된다. 나비 특수는 이동 중 효과가 없고 실제 마지막 4tick만 진행률 0~1로 재계산해 한 번 할퀸다. |
| 비대상 모션 | 발차기·올려할퀴기·지상 약공격·이동·피격·쓰러짐·일어남 등에 새 효과가 잘못 붙지 않는다. 기존 점프·짧은 착지 쓰러짐·보호 구간의 frame sequence도 동일하다. |

- `scripts/fighter_attack_effects.gd`: `e7ee384aa86dc21d0b2c5e3b858ae47aee9d94474960262038c9a7d596f132b6`

## 자동 검사와 제한

QA 담당이 `godot --headless --path . --script res://tests/two_fighter_vfx.gd`를 별도로 실행해 **PASS**를 확인했다. 이 검사는 좌우 방향·준비/판정/회복의 표시 값, 전투 snapshot 불변, 7tick 안의 감쇠와 피격/공격 종료의 즉시 해제를 확인한다. 실제 그리기 자료와 코드도 함께 대조했다. 합성 상태 렌더는 전투 피해·표적 선택·실제 경기 이동 검사의 대체가 아니다.

생산 담당의 `verify.log` 최종 `Forest Arena verification passed.`, 문서·리소스 검사와 LAN 로그를 확인했다. 최종 렌더 로그에는 최초 mesh 오류가 없고 독립 후보 이미지 로더의 export 관련 경고만 있다. 이 로더는 검토용으로 직접 이미지를 읽으며 제품 runtime 등록을 뜻하지 않는다.

정식 양식을 `review_motion_actions.py validate --require-pass`로 검사한 결과 **36 pass / MOTION_ACTION_REVIEW PASS (record integrity only)**다. 자동 검사는 기록과 해시의 완전성을 확인하며 외형에 대한 사용자 승인을 대신하지 않는다.

Android 기기는 연결되지 않았으므로 실제 기기의 가독성·성능·중단/복귀는 **미실행**이다. 새 5개 모션의 runtime·manifest 등록과 PR 병합도 사용자 승인 전 상태로 남긴다.
