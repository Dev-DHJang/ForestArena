# 관리자 웹 독립 품질 확인 1회

결과: fix (수정 필요), 2026-10-08.

원 사용자 계획, 요청·공용 데이터 약속, 관리자 문서, Java·Vue·SQL·실행/검사 스크립트를 생산자와 별도로 읽었다. Android 실기기 검사는 이번 웹 범위의 통과 근거로 사용하지 않는다.

## 확인된 수정 사항

1. 기존 인증 통합 검사의 마지막 활성 최고관리자 보호는 현재 최고관리자가 정확히 1명일 때만 실행된다. 별도 E2E 계정이 있으면 필수 검사를 실행하지 않는다. 기존 계정에 영향을 남기지 않는 취소할 트랜잭션 안에서 명시 검사가 필요하다.
2. IP별 로그인 제한 기록이 테스트 뒤 남아 재실행 때 정상 로그인이 401로 거부됐다. 첫 독립 실행 7개 중 4개 실패. 검사 DB의 해당 제한 행을 검사 전후 정리하여 반복 실행을 분리해야 한다.
3. PostgreSQL 키 교체 검사는 키 추가만 확인했다. 실제 계정 암호문 재암호화와 이전 작업 사유 복호화를 같은 DB에서 확인해야 한다.
4. 로컬 복구 명령은 계정을 활성 최고관리자로 바꾸지만 비밀번호 초기화 기록만 남긴다. 권한·활성 상태의 변경 전후도 이력으로 남겨야 한다.

## 완료 근거와 남은 검사

- `./scripts/verify-admin-db.sh`: 독립 실행 통과. 관리자 전용 계정의 허용 조회·프로필 갱신·이력 추가와 불필요한 수정·삭제·DDL 거부, 게임 계정의 admin 접근 거부 확인.
- 정적 검토: 행 잠금 뒤 변경 번호 확인, 프로필·이력·중복 요청을 동일 트랜잭션 저장, SQL 값 매개변수 사용, 기존 게임 요청 표 무변경 확인.
- same-origin, 쿠키, 세션 ID 교체, 역할·활성·비밀번호별 세션 종료, 조건 없는 마지막 최고관리자 보호, DB 키교체의 독립 자동 검사를 추가하는 중이다.
- 실제 브라우저, 전체 기존 검사와 최종 변경분 재검토는 다음 회차 근거로 기록한다. 미실행을 통과로 보지 않는다.

5. Vite 개발 프록시는 원 요청 Origin을 검증하지 않고 Spring 주소로 바꾼다. 개발 서버의 기본 localhost CORS와 함께 다른 로컬 출처가 같은 출처 확인을 우회할 가능성이 있다. 개발 서버 CORS를 끄고 프록시 이전에 원 요청의 Origin·Sec-Fetch-Site를 검사해야 한다.
6. 인증 검사 계정은 임시 키를 사용하지만 계정 삭제 뒤 해당 작업 이력이 남는다. 실제 브라우저의 이력 조회가 이미 삭제된 검사 키를 요구할 수 있다. 전용 검사 DB의 검사 계정·이력과 로그인 제한 기록을 함께 정리해야 한다.
