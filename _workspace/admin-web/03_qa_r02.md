# 관리자 웹 독립 품질 확인 2회

결과: pass (구현과 검사 통과), 2026-10-08. 원격 PR 검토·병합 기록은 조율 역할이 별도로 마무리한다.

## 검토 범위

원 사용자 계획과 `00_request.md`, `01_contract.md`, 관련 ADR·관리자 운영 문서, SQL 변경 0005, Spring 인증·계정·암호화·프로필·조회 API, Vue 화면·API 연결, 개발 프록시, 실행·백업·검사 스크립트와 최종 수정 차이를 읽었다. 생산코드는 작성하지 않았으며 인증의 독립 경계 검사를 보강하고 실제 실행했다. 기존 미완료 작업 공간을 건드리지 않는 별도 작업 공간을 사용했다.

## 1회 지적 재확인

- 마지막 활성 최고관리자 검사는 다른 테스트 계정 수와 무관하게 실행한다. 취소할 DB 트랜잭션 안에서 다른 최고관리자를 일시 비활성화하여 실제 거부를 확인하고 원래 상태를 보존한다.
- 반복 검사마다 테스트 DB의 IP 제한 기록을 정리한다. 임시 키로 만든 인증 계정의 이력도 검사 종료 때 삭제하여 브라우저 이력 복호화를 방해하지 않는다. 개발 DB의 실제 이력을 삭제하지 않는다.
- 실제 PostgreSQL에서 계정 암호문을 새 키 식별자로 바꾼 뒤 복호화하고 이전 키의 이력 사유도 읽는 검사가 통과했다. 다른 fixture 계정의 원본은 바깥 트랜잭션 취소로 보존했다.
- 복구 명령의 권한·활성 상태 변경 전후를 `ADMIN_RECOVER`로 남긴다. 이력 추가를 실패시켰을 때 비밀번호·권한·활성·세션·잠금 변경이 모두 취소되는 PostgreSQL 검사도 통과했다.
- Vite는 원 요청 출처를 먼저 검사하고 CORS를 끈다. `changeOrigin:true`로 Spring에 전달할 Host와 Origin을 맞춘다. 이름 붙인 수동 재검사 **개발 프록시 출처 검사**: 별도 5174 서버에서 정상 Origin은 200, 다른 로컬 포트 Origin과 `Sec-Fetch-Site: cross-site`는 각각 403. 검사 서버는 종료했다.
- 세션 확인은 관리자 API에 적용하여 로그아웃·만료 뒤 Vue 첫 페이지를 제공한다. 이미 다른 요청이 종료한 세션의 중복 종료는 안전하게 처리한다. 공개 파일의 DB 세션 검사 제외와 중복 종료의 401 응답을 자동 확인했다. 실제 브라우저의 로그아웃 후 재로그인 흐름도 통과했고 최종 서버 로그에서 ERROR가 없음을 확인했다.

## 실행 근거

- 독립 실행 `./scripts/verify-admin-db.sh`: 통과. 전용 DB 계정의 필요한 조회·프로필 열 수정·이력 추가 허용과 불필요한 수정·삭제·표 생성 거부, 게임 계정의 admin 접근 거부.
- 독립 실행 `AuthIntegrationTest`: 7개 통과, 실패·건너뜀 0. CSRF, 권한, 암호화, 세션 시간 제한·강제 종료, 계정 잠금, 비밀번호 변경 의무, 같은 출처·보안 헤더·쿠키·세션 ID 교체, IP 제한, 권한·활성·비밀번호 변경별 종료, 마지막 최고관리자 보호, DB 키 교체를 확인했다.
- 독립 실행 `AdminDataPostgresTest` 3개, `ProfileValidatorTest` 2개, `CryptoServiceTest` 2개: 모두 통과. 프로필 오류·첫 지급 유지·변경 번호·중복 요청·암호화 이력·게임과 관리자 동시 수정·이력 실패 전체 취소·목록 경계를 확인했다. 기존 게임 요청 표를 변경하지 않는 코드와 검사도 확인했다.
- 최종 통합 `./scripts/verify-admin-web.sh`: 통과. `/tmp/forest-admin-web-resume.log`와 Surefire 결과를 직접 확인했다. 최종 Java 핵심 검사 17개와 별도 브라우저 fixture 준비, TypeScript 공용 프로필 예제, Vue 빌드, 실제 Spring 18080 브라우저 흐름을 포함한다. Playwright 4개 통과, 건너뜀 0: 화면·재시도, 실제 관리자 생성→운영자 저장→이력 조회→조회자 서버 거부, 변경 번호 충돌 재편집, 비밀번호 변경 의무.
- 기존 `./scripts/verify.sh`, 게임 프로필 DB 실제 연결 검사, 서버 실제 연결 검사: 조율 역할의 `/tmp/forest-admin-verify.log`, `/tmp/forest-admin-profile-runtime.log`, `/tmp/forest-admin-server-runtime-final.log`에서 PASS를 직접 확인했다. 문서 검사는 최종 QA 기록까지 포함해 원격 통합 전 재실행한다.

Android 실기기 검사는 수행하지 않았다. 이번 개발용 관리자 웹 검사를 Android 기기 통과로 기록하지 않는다. 인터넷 배포·정식 플레이어 계정·차단·성장·재화·결제·경기 결과 수정은 추가하지 않았다.

## 새 DB 초기 설치 추가 확인

최종 `scripts/db-dev.sh`의 추가 변경을 독립 재검토했다. 첫 마이그레이션으로 변경 기록 표가 생긴 직후에도 다음 변경 전 백업이 가능하도록 개발 DB 표식을 먼저 확인·설정한다. 다른 환경 표식이면 기존처럼 중단한다. 한 번의 migrate 실행에서 변경 전 백업을 한 번 만들고, 이미 적용된 파일의 체크섬 확인과 마지막 환경 확인은 유지한다.

조율 역할이 별도의 `forest_arena_admin_fresh_verify_dev`에서 실제 0001~0005 적용·백업·동일 명령 재실행을 수행하여 `5:development`를 확인했다. 해당 임시 DB는 삭제하고 기존 환경 파일을 복원했다는 실행 결과를 받았다. `verify-database.sh`와 문서 검사도 통과했다. 초기 설치에서 0002 전 백업이 환경 표식 부재로 실패할 수 있던 경로가 수정됐으며 기존 통과 판정을 유지한다.

## 운영 시작·중지 추가 확인

최종 `admin-dev.sh start` 변경을 독립 재검토했다. 외부 디렉터리의 실행용 JAR를 Python `subprocess.Popen(start_new_session=True)`으로 시작하여 호출 도구가 끝나도 서버가 유지되도록 했다. 표준 입력은 닫고 출력은 외부 로그로 보내며 환경 변수는 상속한다. 명령 인수에는 Java 실행 파일과 JAR 경로만 넣고 기존 077 파일 생성 제한과 PID 기록을 유지한다.

조율 역할이 서로 다른 도구 호출에서 시작→상태·HTTP 200 유지, 중지→중지 상태, 재시작을 확인했다. QA도 별도 도구 호출의 `./scripts/admin-dev.sh status` 준비됨과 `/admin/api/v1/auth/csrf` HTTP 200, 셸 문법 검사를 직접 확인했다. 통과 판정을 유지한다.
