# 로컬 AI 캐릭터 표현과 모션 제작 목록

## 승인 자산 연결

`local_fighter_presentation.gd`는 `RuntimeCombatProfile.character_id`로 자산 목록의
승인 런타임 SpriteFrames를 찾는다. 경기 참가자 슬롯 ID로 캐릭터 외형을 선택하지 않는다.
기존 인간형 외형 계약을 유지하고, 같은 캐릭터를 양쪽에서 선택해도 각각 표시한다.
우향 원본을 좌우 반전하고 128×128 셀의 발 위치를 전투 몸체 아래쪽에 맞춘다.
공격은 `visual_state_id`의 정확한 연계 단계에 연결한다. 준비·활성·회복 tick을 읽어
재생 위치를 정하며 그림 갱신이 전투 상태·적중·승패를 바꾸지 않는다.

확인 원본은 캐릭터 manifest와 네 기본 MoveSet이다. 철갑옷 등 장신구 규칙은
외형을 자동 변경하지 않는다. 복싱 글러브 교체 MoveSet의 기술도 별도 모션 검토가
필요하다. 승인된 기본 모션 연결만으로 새 전투 모션 제작 완료를 주장하지 않는다.

미제작 공격은 승인 idle을 임시 표시하고 `missing_motion`에 요청 ID를 남긴다.
해당 대체 표시는 전투 모션 승인이 아니며 최종 완료 전 교체해야 한다.
방어·회피 등 상태별 포즈도 현재 승인 idle을 유지한다. run은 이동·대시,
jump는 상승·하강에 한해 재사용한다.

## 다음 모션 검토와 확인 항목

캐릭터별 기존 승인 콘셉트와 외형 계약을 기준으로 누락된 모션을 검토용 경로에
제작한다. 모션별 시트와 재생 미리보기를 사용자에게 제시하고, 명시 승인 후에만
runtime 경로와 manifest에 등록한다. 나비의 흰 꼬리·귀, 묘령의 긴 토끼 귀,
자현의 얇은 꼬리·파란 리본, 유란의 굵은 고리무늬 꼬리를 유지한다.

자동 검사는 네 캐릭터의 승인 자산 16프레임 로드, 슬롯 ID와 외형 ID 분리,
정확한 공격 표현 ID, 좌우 반전과 전투 snapshot 비변경을 확인한다.
잘림·발 위치·작은 화면 가독성·실기기 메모리 및 draw call은 실제 화면 검토와
측정이 필요하며 이 문서 작성만으로 통과 처리하지 않는다.

2026-10-01 사용자가 나비 약공격 02 r01과 로컬 이미지 처리를 승인했다. 01·02의
회색 배경을 가장자리 연결 영역으로 제거하고 작은 분리 잡픽셀을 버린 뒤, 공통 크기와
발 기준선으로 16개 128×128 RGBA 셀을 2048×128 시트에 배치했다. 승인 원본과 이전
미등록 파일은 덮어쓰지 않았다. 처리 스크립트·접촉 시트·GIF·좌표 보고서는
`motion-review/nabi/normalized/`에 보존한다. 두 SpriteFrames는 12 FPS 비루프이며,
manifest의 프레임 구간을 AttackData의 준비·활성·회복 tick에 맞춰 표시한다.

2026-10-02 사용자가 유란 약공격 01 r02·02 r02·03 r03, 방어 r02, 회피 r02를
모두 채택했다. 승인 원본은 덮어쓰지 않고 `normalize_yu_ran_approved.py`로 회색 배경과
셀 경계의 이웃 잔여물만 제거했다. 다섯 모션에 같은 크기와 발 기준선을 적용해 16개
128×128 RGBA 셀로 만들고 `runtime/local_ai_v01`과 manifest에 등록했다. 2단은 승인된
순서 `1,2,4,5,6,7,3,8,9,10,11,12,13,14,15,16`을 적용했다.

약공격 프레임은 AttackData의 준비·활성·회복 구간 안에서만 표시된다. 방어는 진입 뒤
승인된 7번 방어 자세를 유지하고, 상태 종료 시 idle로 돌아간다. 회피 16프레임은 기존
12 tick에 맞춰 표시한다. 이 표현 규칙은 피해·적중·무적·이동 시간을 바꾸지 않는다.
정규화 접촉 시트·GIF·프레임 좌표·해시는 `motion-review/yu-ran/normalized/`에 보존한다.

## 자동 커버리지

`tools/forest_arena/report_motion_coverage.gd`는 실제 기본 LoadoutCatalog의 네 MoveSet과
승인 manifest를 비교해 `_workspace/local-ai-playable/motion-coverage.json`을 만든다.
현재 승인 공격 표현은 자현 3/17, 묘령 4/18, 나비 2/16, 유란 3/17이다. 상태 표현은
자현·묘령·나비 3/13, 유란 5/13이다. 유란에는 idle/run/jump/guard/evade가 등록됐고
charge, hitstun, launch, knock_down, wake_up, death, ring_out, spawn이 남아 있다. 이
수치는 미등록 시안을 완료로 세지 않으며 manifest나 MoveSet이 바뀔 때 다시 계산한다.

유란의 다음 검토 묶음으로 `hitstun`, `launch`, `knock_down`, `wake_up` r01 시트와
GIF를 만들었다. 승인 전 검토 경로에만 있으며 현재 커버리지와 runtime에는 포함하지
않는다. 동작 구간·해시·생성 프롬프트는 `motion-review/yu-ran/reaction-r01-review.md`에
기록했다.

유란의 남은 상태 검토 묶음으로 `attack_heavy_charge`, `death`, `ring_out`, `spawn`
r01 시트와 GIF를 만들었다. 승인 전 검토 경로에만 두었고 현재 커버리지와 runtime에는
포함하지 않았다. 상세 내용은 `motion-review/yu-ran/state-r01-review.md`에 기록했다.

유란의 방향·상황별 약공격 검토 묶음으로 `attack_light_up` r02와
`attack_light_down`, `attack_dash_light`, `attack_air_light` r01 시트·GIF를 만들었다.
위 약공격 r01은 5·4·4·3 배열이라 거부 기록으로만 보존하고, 같은 16포즈를 정확한
4×4로 다시 배치한 r02를 최종 검토 대상으로 삼았다. 네 시안 모두 승인 전 경로에만
있으며 runtime, manifest와 현재 커버리지에는 포함하지 않았다. 상세 내용은
`motion-review/yu-ran/light-variants-r01-r02-review.md`에 기록했다.

유란의 강공격 검토 묶음으로 `attack_heavy_side`, `attack_heavy_up`,
`attack_dash_heavy`, `attack_air_heavy` r02와 `attack_heavy_down` r01 시트·GIF를
만들었다. 네 초기 r01은 투명 가장자리의 적·황색 오염 때문에 거부 기록으로 보존하고,
같은 구성의 불투명 배경 r02를 최종 검토 대상으로 삼았다. 다섯 시안 모두 승인 전
경로에만 있으며 runtime, manifest와 현재 커버리지에는 포함하지 않았다. 상세 내용은
`motion-review/yu-ran/heavy-variants-r01-r02-review.md`에 기록했다.
