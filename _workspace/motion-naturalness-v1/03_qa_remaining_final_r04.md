## 확인한 범위

- 현재 원화 **21종×16장=336장**을 직접 확인했다. 자현12종, 나비 상태9종이다. 외형 계약의 두 귀·한 꼬리·사람 얼굴/손발·각 의상과 실루엣을 대조했다. 작은 장식이 모든 각도에서 모두 식별된다는 주장은 하지 않는다.
- 실제 Godot 자료 `qa/remaining-live-r11/`에서 상태 정상/반전소형 각8장면과 자현 공격 각3장면, 총 **22장면·3580 RGBA 프레임**을 무손실 MKV에서 독립 복원했다. 프레임별 MD5, 원 raw SHA-256, 영상 SHA-256, 촬영 보고서 해시와 현재 소스 해시가 일치했다. 자료를 복원해 검사한 것과 같은 idle 유지 틱을 모두 눈으로 개별 판독한 것은 구분한다.
- 현재 자료에서 모션별 고유 자세와 동작 전환 앞뒤 비교판을 만들고, 원화 전체·정상/반전 전환·자현 공격 실제16자세와 날림 실제16자세를 직접 대조했다. `qa/remaining-21-independent-r04/independent-integrity.json`에42개 방향/모션 묶음의 실제 표시 그림 번호를 남겼다. 짧은 상태가 모든 원화를 표시한다고 가정하지 않았다. 예를 들어 실제 가드24틱에서는 F1~10, 착지 쓰러짐은 F13~16을 쓴다.

## 두 날림 연결의 새 판정

**자현 launch: pass.** 이전에는 실제21틱에서 F1~5만 보이고 크게 다른 낙하 자세로 잘렸다. 현재는 실제 경직 안에 F1~16을 표시한다. 새 F13~15의 회복 자세와 승인 jump F11을 공유하는 F16을 거쳐 낙하가 이어진다. 로컬 장면 t32의 F16→t33의 jump F11 경계가 큰 머리/몸통 이동 없이 이어지는 것을 정상·반전 영상과 원점 판에서 확인했다. 마지막 그림 뒤 선택 표시 연결이 로컬 경직 시간을 더 늘리지 않는다.

F12→13에는 작은 몸통 원근/압축 변화가 남지만 현재 속도에서는 뒤로 밀린 자세에서 앞으로 균형을 회복하는 동작으로 읽힌다. 정지 원화의 알파 사각형 크기를 그대로 머리 배율로 해석하지 않았고, 기존의 한 틱 큰 자세 이동과 같은 수정 필수 문제는 찾지 못했다. 목도리 양끝의 방향도 회수 동작에 따라 바뀌며 따로 떠 있는 큰 잔광 덩어리는 보이지 않았다. 공통 끝자세는 원본 RGBA뿐 아니라 실제 import 보정을 반영한 현재 영상으로 판단했다. 예비 r01의 raw/import 경계색 차이 진단을 현재 렌더 불일치로 재사용하지 않는다.

**나비 launch: pass.** 현재도 F1~16 전체 뒤 실제 FALL/jump로 넘어간다. 끝의 접힌 두 다리에서 한 다리를 아래로 펴는 자세 변화는 남는다. 그러나 정상·느린/반전소형 재생과 경계 표본에서 머리·몸통의 큰 위치 튐 없이 수동 피격 종료→하강으로 읽혔다. 현재 게임 타이밍에서는 허용할 수 있으며 새 연결 원화를 필수로 요구할 추가 문제는 찾지 못했다. 자세 차이가 전혀 없거나 두 끝 그림이 같은 픽셀이라는 주장은 아니다.

선택 LAN 표시 연결4틱과 실제 입력 결과에 따른 중단은 별도 코드·실제 소켓 QA 범위다. 이 로컬 영상의 시각 pass로 LAN 실제 픽셀 촬영이나 Android 결과까지 확대하지 않는다.

## 기록 고정과 한계

catalog r10 SHA-256은 `005960d9a5ec54d29a7ca637905eaee64b33ecb6308a527debc53d46bfbed324`다. 현재 제품으로 새 timeline을 생성하고 원화·공용 표현 코드·전투 자료를 고정했다. 추가로 `scripts/launch_release_clock.gd`의 현재 해시가 실제 r11 촬영의 `b95123f945341896926b6af8a651fcc4267de0597f0a7e9377ec01ca614ef947`와 같음을 확인해 formal review의 `sources`에 추가했다. 원 timeline은 바꾸지 않았으며 이미 촬영에서 사용한 보조 코드의 후속 변경을 놓치지 않도록 기록만 보강했다.

상태 영상은 공개 전투 API로 발생시킨 짧은 피격/날림·실제 물리 착지, 공개 ring_out 호출과 기회 소진을 포함한 검토 fixture다. ring_out 장면을 실제 낭떠러지 이동 검사로 확대하지 않는다. 자현 공격3장면은 실제 입력으로 시작한 전투 재생이다. 후보는 프로세스 안에서만 쓰며 runtime/manifest에 등록하지 않았다.

최종 사용자 명시 승인·후보 등록, 실제 Android 엄지 접근성과 가독성·중단/복귀, 모든 경기 조합과 실제 Wi-Fi 두 기기 검사는 별도다. 이번 pass는 선언한21종의 행위·시각 품질과 현재 검토 자료 범위다. 원본 PNG·후보·제품·manifest를 이 역할이 수정하지 않았다.

공용 `validate`는 기록 무결성 PASS이며 `pass21/blocked4`를 그대로 보고했다. 전체 `--require-pass`는 별도 담당4종이 blocked이므로 예상대로 종료 코드1과 `motion decisions are not all pass`를 반환했다. 이를 전체25종 통과로 기록하지 않는다. 제21종 집계는 모든 항목과 여섯 확인 값이 pass임을 별도 검사했다. `verify-docs.sh`도 PASS다. 해당 로그는 각각 `qa/remaining-candidate-review-r10-current-validate-final.log`, `qa/remaining-candidate-review-r10-current-require-pass-scope-note.log`, `qa/remaining-21-independent-r04/verify-docs-final-r04.log`에 보존했다.
