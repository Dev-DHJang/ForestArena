# 자현 launch → 낙하 자세 연결 제안

## 현재 문제와 직접 확인

독립 QA가 지적한 실제 `state-normal` 장면을 대조했다. `nabi-air-heavy`의 경직 입력은22틱이고, 시험 함수가 step 전에 호출되어 LAUNCH는 화면에21틱 나타난다. 현재 launch는12 FPS로 F1–5만 보여 준 뒤 곧바로 승인 jump의 낙하 첫 그림 F11로 바뀐다. 이때 표시 배율은 양쪽 모두0.85이며, launch의 `foot_pivot_y=104`, jump의 값은117이다. 그림 위치의 기본 Y 차이는11.05world px다. 실제 시각 차이는 이 기준점 차이와 두 그림의 자세 내부 위치 차이가 합쳐진다.

원화16장과 동일 파이터 원점의 비교판 `qa/launch-transition-pose-comparison-proposal.jpg`를 직접 봤다. launch F16도 뒤로 젖혀 앉은 자세이고 승인 jump F11–16은 모두 앞으로 숙인 낙하 자세다. 따라서 배율 변경이나 단순히 마지막 그림을 보여 주는 것만으로 연결 자세 차이가 전부 해결되지는 않는다. 머리 단위가 비슷하므로 신체 일부 확대/축소로 덮지 않는다. 최종 독립 QA의 r02 귀 바깥 끝→턱 측정은 launch F5=31.28world px, 승인 jump F11=32.31world px다(수동±3셀 px). 초기40/41 추정은 옷/손이 섞인 판독이므로 폐기한다. `qa/remaining-21-independent-r03/ja-head-measurements-r02.json`을 기준으로 한다.

## 1. 실제 경직 길이에 launch 재생을 맞춘다

제품의 기존 HITSTUN 매핑과 같은 방법으로 로컬 LAUNCH의 이미 정해진 `hitstun_ticks`를 읽는다. 새 타격 신호에서 duration을 다시 읽고 첫 그림부터 시작한다. 상태 진입 신호가 없는 로컬 초기 표시에서는 현재 남은 값을 한 번 읽는다. 경직 계산·증가·감소는 전투 코드가 계속 결정한다. 표현은 duration을 계산하지 않는다.

제품 파일은 바꾸지 않고 `qa/launch-transition-proposal-r01/presentation-proposed.gd`의 두 조건만 HITSTUN 또는 LAUNCH로 넓혔다. 현재 원본 fixture와 같은 물리를145틱 실행한 결과, 모든 경기 snapshot이 같았다. 실제 LAUNCH 표시21틱도 같았으며, 원본은0–4번 그림, 제안은0–15번 전체 그림을 보여 줬다. 마지막 t31/32는F16, t33/34는 승인 jump F11이었다. `comparison.json`에 기록했다. 이는 headless 상태/프레임 선택 시험이며 새 픽셀 영상 품질을 통과시킨 검사는 아니다.

KNOCK_DOWN은 이 분기에 추가하지 않는다. 실제 착지 뒤 `landing_down_ticks`의18틱과 WAKE_UP12틱 매핑을 우선 보존한다. 공중 KNOCK_DOWN이나 바운스의 뜻은 별도 사례로 확인한다. 새 피격은 기존 신호로 LAUNCH 재생을 다시 시작하고, 사망·리셋·캐릭터 변경은 기존 초기화 경로를 따른다. 짧은6틱 반응은 전체16장을 억지로 끝내기 위해 전투를 연장하지 않고 시작/중간/끝을 선택한다.

## 2. 후반 F13–16을 낙하로 연결되는 새 자세로 만든다

승인 jump PNG는 그대로 둔다. 미승인 launch의 첫12장은 보존하고 후반은 새 F13–15와 승인 jump F11의 전체 그림을 공유하는 F16으로 구성한다. 새4자세 원화 r02는 보존하되 생성된 F16을 억지 변형하지 않고 공통 낙하 경계 자세를 선택했다. F12의 뒤로 젖힌 수동 피격에서 몸통을 세우고 팔을 가드 쪽으로 회수하며, F16은 승인 jump F11의 앞으로 숙인 낙하 자세에 이어지게 한다. 도약 준비·발판 딛기·새 점프로 보이면 안 된다. 그림 수는16장을 유지한다. 현재 실제21틱보다 그림을24장으로 늘리면 실제 장면에서 모든 그림을 한 번씩 보여 줄 수 없기 때문이다.

모든 새 자세는 몸 전체의 한 가지 균일 배율만 쓴다. 머리/몸/팔다리 부분 왜곡을 하지 않는다. 한 셀 안에서의 배치는 바꿀 수 있으며 원화·배치·원본 및 새 셀의 확인값을 따로 기록한다. 현재 같은0.85배율에서 끝 그림을 승인 jump F11과 같은 world 위치에 놓으려면 셀 그림을 Y13px 옮기는 방식이나 마지막 그림의 기준점을117로 바꾸는 방식이 필요하다. r09에서는 승인 jump F11 RGBA를 그대로 공유하고 F16에만 `body_root=[64,117]`을 썼다. F1–15는[64,104]다. 이는 물리 위치나 실제 골반 좌표를 바꾸는 정보가 아니라 그림의 가상 원점이다.

새 비교판 `remaining/ja-hyun/launch-neutral-r09/same-origin-r09.png`는 같은 파이터 원점과 배율에서 F12 → 새F13 → 새F14 → 새F15 → 공통F16 → 승인jumpF11을 보여 준다. 첫12셀 RGBA와 F16→jump F11 정상/반전 경계 픽셀이 제작자 검사에서 일치했다. 새3자세 머리 단위는30.97/31.21/32.82world px이며 수동±3셀 px다. 밝은/짙은/회색 배경에서 별도 잔광 오라를 발견하지 못했지만 인물 가까운 반투명 색과 F12→13 원근 차이는 독립 QA가 다시 판단해야 한다. 새 원화는 독립 QA와 해당 모션의 사용자 명시 승인 전 runtime/manifest에 쓰지 않는다.

## LAN3와 호환 범위

LAN3에는 남은 경직이 없다. 클라이언트가 공격ID/로드아웃으로 경직을 다시 계산하거나 고정22틱이라고 가정하지 않는다. 현재 LAN은 기존 이벤트로 첫 그림 재진입, 기존 FPS 재생, 다음 서버 상태 즉시 반영을 유지한다. 로컬의 전체16장 재생 결과를 LAN 전체 통과로 넓혀 쓰지 않는다. 서버가 이미 계산한 duration을 새 표시 값으로 보내는 방안은 계약 변경이므로 지금 슬쩍 같은 버전에 추가하지 않는다.

새 후반 중립 자세가 완성된 뒤에도 LAN의 짧은 LAUNCH에서 앞부분만 보이는 문제가 남으면, 별도의3–4틱 표시 전용 회복 구간을 검토할 수 있다. LAUNCH→FALL에서 마지막에 본 그림이 회복 시작보다 앞에 있을 때만 새 F13–16을 짧게 보여 주고 낙하로 넘긴다. 로컬이 이미F16을 봤으면 재생하지 않는다. 새 피격/공격/점프/착지KNOCK_DOWN/사망/리셋은 즉시 끊으며 전투 상태·입력을 늦추지 않는다. 이 선택은 아직 구현/검증하지 않았으며 새 키포즈와 실제 LAN 영상으로 효과를 판단해야 한다.

기존 승인 자산의 PNG·SpriteFrames와 동작 구간은 바꾸지 않는다. 일반 LAUNCH에도 새 시간 매핑을 적용하면 표시 시간만 달라지므로, 기존16장/새16장·가중 프레임·반복 피격·짧은/긴 경직·LAN duration없음·실제 착지 전환을 함께 재검사한다. 필요하면 새 후보에만 시간 맞춤 선택값을 두는 대안도 있지만, 이는 표시 메타데이터의 선택 필드와 소비자/검증자 변경을 함께 기록해야 한다.

## 통합 후 확인할 항목

- 로컬 LAUNCH6/16/22/30틱, 같은 상태 재피격의 duration 연장·축소·동일 남은 값에서 첫 그림 재진입.
- 실제22틱 입력의21개 화면에서16장 전체가 보이고, 물리 snapshot/경직/승패와 landing-down/wakeup 순서가 바뀌지 않는지.
- 첫12개 기존 셀 보존과 새4장의 외형·몸 전체 균일 배율·F12/새F13/새F16/jumpF11의 머리/골반 연결.
- 정상/느린 재생·반전·소형·짧은 LAN 상태에서 낙하로 넘어갈 때 몸이 순간 이동하거나 새 점프로 보이지 않는지.
- 기존 승인 run/jump/피격 및 새 타격/공격/점프/사망/리셋이 회복 그림을 즉시 끊는지.

현재 제품 코드·PNG·manifest·기존 테스트는 이 제안 작업에서 수정하지 않았다.

## 나비의 같은 경계 관찰

`remaining/ja-hyun/launch-neutral-r09/nabi-launch-jump-same-origin-r09.png`는 기존 r07-head launch F5/F16과 승인 jump F11/F12/F16을 정상/반전으로 같은 파이터 원점에 놓았다. 현재 선언 배율과 기준점은 launch1.122254/root104, jump1.0/root109다. 전체16장을 재생하면 머리 위치 차이는 자현의 이전 F5→jump F11처럼 크지 않지만, F16의 접힌 두 다리와 jump F11의 한 다리를 푼 낙하 자세는 다르다. 시간 매핑만으로 이 차이가 전부 사라졌다고 판단하지 않는다. 이번에 나비 새 원화를 만들지는 않았으며 실제 새 시간 매핑 영상에서 단절이 남으면 후반 연결 자세 또는 공통 끝자세 방식을 별도로 검토한다.
