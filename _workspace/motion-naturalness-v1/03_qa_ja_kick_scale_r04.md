# 자현 킥 표시 크기 원인 재분류 r04

담당: scale_qa. 2026-10-22. 독립 QA와 애니메이션 skill, 행위 표현 검토 규칙을 읽고 원화와 후보를 직접 확인했다. 작업은 이 worktree 안의 QA 기록·진단 비교판에만 한정했다. 원화, 후보 PNG, 코드, catalog, runtime, manifest는 수정하지 않았다.

## 결론

**현재는 fix를 유지하되, 킥 원화 재생성이 반드시 필요하다는 판정은 유보한다.** 기존 `pack-candidate.py`가 모션 전체의 인물 높이 중앙값을 승인 idle의 높이로 맞추고 있다. idle은 양 무릎을 구부린 자세이고 킥은 지지 다리를 펴므로, 같은 모델이어도 발부터 귀까지의 전체 높이는 달라진다. 따라서 같은 전체 높이의 비교판에서 머리가 작다는 관찰만으로 원화 비율 결함을 확정할 수 없다.

기존 킥 r02 후보에 **전체 모션 고정 표시 배율 1.15**를 적용한 진단 비교판에서는 승인 idle·새 펀치와 머리/얼굴 크기의 차이가 크게 줄어든다. F0~15 전체를 같은 배율로 확인했으며, 준비→무릎 들기→한 번의 킥→회수→양발 회복이 유지된다. 지지 다리가 펴져 키가 높아지는 설명과 양립한다. 이 단계에서 원화를 다시 그리도록 되돌리기보다 같은 배율의 실제 연계 재생을 먼저 확인할 근거가 있다.

1.15는 시각 비교용 시험값이며 승인된 확정 배율은 아니다. 이 비교판은 기존 `foot_pivot_y=124`를 같은 바닥선에 놓았으며, 실제 표현 코드의 body_root 적용·카메라·효과·시간 순서를 실행한 결과가 아니다. 회복 F10~15는 idle보다 덜 웅크리고 있어 실제 idle 복귀에서 높이 변화가 남을 수 있다. tick100→101과136→137에서 머리·얼굴의 크기 변화와 자세 높이 변화를 구분해 다시 확인해야 한다. 개별 프레임별 배율 변경이나 몸 일부 변형은 사용하지 않았다.

root가 같은 PNG와 고정 표시 배율을 사용한 실제 연계 캡처를 제공하면 두 전환 경계와 전체 순서를 다시 본다. 전체 정상·느린 재생, 좌우 반전, 작은 크기와 고정 코드/메타데이터의 전체 자료는 이 기록에서 확인하지 않았다. 따라서 모션 전체 pass, 사용자 모션별 승인, Android 기기 통과를 기록하지 않는다.

## 고정1.15배 실제 연계 확인

`review/live-ja-combo-scale-r04`의 완료 report는823검사·오류0, 자현162tick/PNG162장이다. 전체162장을 `qa/ja-scale115-full-actual-r04-part1.jpg`~`part5.jpg`로 시간순 대조했고, 전환을 `qa/ja-scale115-transition-actual-r04.jpg`에서 확대 확인했다. 101·112·113·136·137은 원본 전체 화면도 직접 봤다. 모든 킥 프레임에 표시 배율1.15가 적용되고 PNG는 이전과 동일함을 report와 함께 대조했다.

- 고정 배율은 작은 머리/얼굴로 바뀌는 인상을 줄였다. 원화 전면 비율 결함이나16장 전체 재생성 필수 판정은 철회한다.
- 다만 tick100 약1 F15→101 킥 F0에서 이미 무릎과 상체를 더 편 자세로 즉시 바뀐다. tick136 킥 F15→137 idle F0에서는 즉시 웅크린 자세로 낮아진다. 이번 자료에서 크기보다 **시작·끝 자세 높이의 연결 튐**이 남는다.
- 킥 내부의 지지발 바닥선은 유지되고, 무릎 들기→한 번의 발 뻗기→회수→양발 회복은 읽힌다. 타격 프레임을 원본 전체 화면에서도 확인하여 진단 크롭이 신발을 숨긴 결과로 판정하지 않았다.
- 따라서 자현 전체 연계는 여전히 **fix**다. 다음 접근은 킥 전체를 계속 다른 모델로 다시 그리기보다, 같은 머리/얼굴 크기를 보존하면서 시작 준비와 마지막 회복이 직전 펀치·승인 idle의 웅크린 높이를 잇는지 확인하는 것이다. 개별 프레임 축소나 몸 일부 늘이기로 해결할 항목이 아니다. 실제 자세 수정이 필요하면 새 연결 원화를 사용해야 한다.

이 확인은 고정tick 실제 캡처의 전체 시간 순서를 직접 본 결과다. 정상 속도·느린 재생 동영상 끝까지 보기, 좌우 반전·소형 표시까지 완료했다는 기록은 아니다. 전체 모션 pass와 사용자 승인을 대신하지 않는다.
