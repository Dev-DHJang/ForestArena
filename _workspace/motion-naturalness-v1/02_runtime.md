# 가변 모션 표시 구현

2026-10-21. 담당: runtime 표시. 원본 미커밋 폴더와 전투 계산은 수정하지 않았다. 새 PNG·manifest·런타임 자산 등록은 하지 않았다.

## 변경

- `LocalFighterPresentation`이 16·24·32장의 그림과 프레임별 표시 시간 가중치를 읽는다. 준비·판정·회복 안에서만 그림을 고르고, 전투 틱 수와 상태는 바꾸지 않는다. 기존 가중치 없는 16프레임 공격은 기존 반올림 방식과 FPS를 유지한다.
- 새 `jump_frame_ranges`가 있으면 상승·정점·하강을 따로 시작하고 각 마지막 그림을 유지한다. 착지 구간은 실제 지상 상태에서만 기존 0.25초 안에 표시한다. 기존 16프레임 점프 경로는 그대로 둔다.
- `run_stride_px`가 있으면 실제 월드 X 좌표 이동 거리로 발걸음을 진행한다. 신규 대표값은 96px/한 주기다. 새 달리기 진입, 새 activation, 위치 차이가 주기의 두 배(96일 때 192px)를 초과하는 이동에서는 위상을 초기화한다. 제자리이거나 idle이면 시간만으로 발걸음이 진행되지 않는다. 필드 없는 기존 달리기는 이전 FPS 재생을 유지한다.
- 목도리 효과는 현재 표시 중 그림의 `frame_anchors`를 읽고 sprite의 위치·크기·반전을 적용한다. 24·32프레임에 앵커가 없거나 개수·좌표 형식이 잘못되면 연장 효과를 생략하며, 과거 16개 좌표의 마지막 항목으로 강제 고정하지 않는다. 기존 16모션에 한해 이전 좌표와 위쪽 펼침 분류를 유지한다.
- 새 timing/jump/stride/anchor/range 메타는 `sha256`가 있는 그림 항목에서 읽는다. 명시된 항목 값이 동일 PNG의 표시 보정 데이터보다 우선한다. 항목에 없으면 해시가 일치한 보정 데이터만 적용한다. 기존 몸 크기·발바닥 기준점은 기존 해시 보정 우선순위를 유지한다.

## 실제 경기 대표 세트 촬영 도구

`render-pilot.gd`는 제품의 `main.tscn`, `MatchController`, 2캐릭터 기술 목록과 규칙, 실제 지형 충돌을 사용한다. 초기 위치와 바라보는 방향을 정한 뒤에는 `CombatIntent` 입력만 보내며, 모션 검토를 위해 상태·위치·공격 단계·피해를 강제로 지정하지 않는다. 비공개 후보는 `motion_review_candidate_frames.gd`로 이 프로세스의 표시 캐시에만 설치한다. 첫 프로필 검색이 캐시를 초기화하므로 검색을 마친 뒤 후보를 넣는다.

- 두 캐릭터 × 달리기→정지120틱·점프→착지120틱·전체 약공격 연계162틱의 6개 영상. `--flip --small`은 왼쪽 진행·좌우 반전과 줌0.75를 함께 사용한 별도6개를 만든다. 기본은1280×720, 줌1.50, 60 FPS다.
- 각 틱의 실제 전투 snapshot(순간 상태), 좌표·속도·지면 접촉·공격ID, 표시 모션·그림 번호·크기·반전, 제출 입력을 JSON에 기록한다. 모든 표시 처리 전후의 경기 값이 같고 누락된 그림이 없는지 확인한다. 촬영 시작·끝의 코드·후보·지형·카메라 해시를 비교해 도중 변경도 거부한다.
- 실제 달리기 거리와 입력 해제 뒤 정지, 점프 이륙·착지, 자현4타·나비3타 실행과 상대 HP 감소·연계 종료를 검사한다. 이미 보고서가 있는 출력 폴더에는 덮어쓰지 않는다.
- `pack-pilot.py`는 촬영 뒤 소스 해시와 그림 수를 다시 확인하고1280×720 H.264 CRF16 MP4, 실제 상태에 맞춘 핵심6장 비교판, 정상·0.25배 속도 HTML을 만든다. `--lossless`로 FFV1 파일도 보존할 수 있다. 기본은 성공한 포장 뒤 임시 PNG만 삭제한다.

실행 예시(프로젝트 루트):

```sh
godot --path . --script _workspace/motion-naturalness-v1/render-pilot.gd -- --output _workspace/motion-naturalness-v1/review/live-pilot-r01
python3 _workspace/motion-naturalness-v1/pack-pilot.py --output _workspace/motion-naturalness-v1/review/live-pilot-r01
```

반전·작은 표시는 별도 출력 폴더와 `--flip --small`을 사용한다. 특정 항목만 재검사하려면 `--character ja-hyun` 또는 `--scenario full-combo`를 추가한다. 화면 촬영 없는 코드 검사는 `godot --headless ... -- --state-only`로 실행하며, 영상 검사로 기록하지 않는다.

도구 자체 확인에는 이전 36모션 catalog를 `--catalog _workspace/two-fighter-combat-v2/candidate-catalog.json`으로 명시했다. 새 대표 그림의 품질 통과는 아니다. 실제 화면 smoke `qa/live-fixture-capture-r02/`에서 자현 4타와 HP100→96→92→88→81, 미등록 발차기 후보의 표시와 최종 대기 복귀를 직접 확인했고 MP4·6장 비교판 포장을 확인했다. 이 smoke는 후속 소스 해시 검사 보강 전 도구 버전을 기록한 보조 자료다. 최종 도구의 정상 6개 및 반전·소형 6개 무영상 검사는 각각 `qa/live-fixture-dry-r06/`, `qa/live-fixture-dry-r07/`에서 **3279개 검사 PASS**, 누락 모션 없음, 촬영 도중 소스 변경 없음으로 확인했다.

## 2026-10-22 코드 검토 후 보강

기존 좌표 fallback(새 부착점이 없을 때의 이전 값)은 프레임 수16만 확인하던 것을 실제 검토한4개 PNG 해시와 모션 ID에 한정했다. 새16그림도 자체 부착점이 있어야 하며 다른 그림의 손·목 좌표를 빌려 쓰지 않는다. 이전 private 후보처럼 SHA 필드가 없을 때는 PNG를 한 번만 읽어 캐시한다. 표시 검사48개와 VFX·기존120모션 시간표를 다시 통과했다. 독립 코드 검토는 `03_runtime_review.md`에 남겼다.

실제 촬영 r01은 macOS 포커스 알림으로 제품의 일시정지가 실행돼 실패했다. 촬영 프로세스만 제품 main.gd 소스를 그대로 읽되 `_notification` 함수 이름 한 곳을 촬영 전용 이름으로 바꿔 플랫폼 알림을 받지 않게 한다. 나머지 준비·HUD·전투·입력·표시 처리는 제품 코드다. 함수 이름의 단일 일치와 컴파일 성공을 확인하며 제품 파일은 바꾸지 않는다. 이 촬영은 플랫폼 생명주기 검사가 아니다. 초기 상속 시도 r08은 Autoload 준비 전 컴파일 문제로 실패했으며 새 r09 무영상6개가3265검사를 통과했다.
