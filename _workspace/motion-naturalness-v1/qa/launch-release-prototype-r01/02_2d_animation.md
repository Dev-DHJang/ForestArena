# 복제 코드 동작과 한계

`presentation-prototype.gd`는 현재 제품 전체 파일의 workspace 복사본이다. 제품과의 차이는 `integration-review.patch`에 있다. `release-clock.gd`는 FighterController나 입력 객체를 소유하지 않으며, 넘겨받은 읽기 값으로 표시할 launch 그림 번호 또는-1만 반환한다.

실제 상태가 이미 FALL/JUMP여도 선택 연결 구간 중에는 `requested_motion=launch`를 표시한다. 이는 의도적인 표시 예외이며 fighter.state는 바꾸지 않는다. 공격 효과는 기존 실제 상태/active_attack 조건을 그대로 읽으므로 공격·판정 효과를 만들지 않는다. 마지막 셀의 body_root와 반전은 원래 표현 경로를 그대로 따른다. 새 입력 결과가 있으면 다음 표시 호출에서 즉시 그 행동으로 넘어간다.

LAN의 launch F5에서 끝나면 F13부터 시작한다. 이미F13을 봤으면F14부터, F15를 봤으면F16부터 표시한다. F16을 봤으면 추가 연결 없이 낙하로 간다. 로컬 전체16장 매핑은 원래 마지막 그림에 도달하므로 이 연결이 중복되지 않는다.

고정 r09 F16은 승인 jump F11과 전체 그림/원점이 같아, 30FPS에서F16 시점이 샘플되지 않아도 곧바로 같은 낙하 첫 자세로 넘어간다. 이는 정적 원점 비교로 알려진 조건이며 이번 headless 시험이 게임 픽셀을 직접 촬영한 결과는 아니다.

해제 판단은 이미 전투에서 적용된 점프 결과를 관찰한다. 새로운 jump 신호를 보내거나 velocity를 계산/수정하지 않는다. LAN3가 어떤 실제 행동 결과도 전달하지 않고 오직 구분 불가능한 동일 상태·속도만 보낸 경우, UI가 그 차이를 알아낼 수 있다는 보장은 하지 않는다. 기존 점프 표시와 같은 허용 횟수/속도 변화 관찰에 더해 FALL→JUMP를 확인한다.

실제 네트워크 패킷 왕복, 상태 사이에 새 피격이 완전히 지나가서 단 한 번도 관찰되지 않는 경우, 화면 픽셀의 자연스러움·Android 실기기 검사는 이번 범위에서 통과시키지 않았다. LAN 메시지 버전도 변경하지 않았다.
