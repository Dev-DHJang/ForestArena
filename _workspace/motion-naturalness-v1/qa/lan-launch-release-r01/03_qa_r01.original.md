## 실제 연결과 입력

서버와 두 클라이언트는 같은 작업 공간, HEAD `7be326f05f7d10646a3acbdc795186e43245616a`에서 실행했다. `run.py`는 변경 없는 `tests/lan_auth_fixture.py`를 127.0.0.1:18081에 실행하고, 변경 없는 `server/game/lan_game_server.tscn`을 127.0.0.1:17819에 실행했다. 기존 QA 인증의 service token과 host/guest 테스트 신원을 사용했으며 인증·방 생성·참가를 우회하지 않았다. DB 대신 기존 HTTP QA fixture이므로 실제 DB 저장을 주장하지 않는다.

한 QA 프로세스 안에 정식 `LanMatchClient` 두 노드를 만들었지만 각 노드는 별개의 실제 WebSocket을 갖는다. `begin_host`, `room_created` 초대, `begin_join`, 실제 `match_start/snapshot/presentation_event`를 받았다. `qa_active`와 `qa_autoplay`를 명시한 기존 `submit_qa_intent` API로 이동·정지·공격·점프를 전송했다. 서버는 슬롯과 실제 지상/공중 상황을 자체 선택해 기존 입력 경로로 실행했다.

서버 파이터는 위치·상태·피해를 강제 설정하지 않았다. 시작 지점에서 두 파이터를 실제로 이동시키고, 거리가 70 미만이며 둘 다 실제 바닥에 있는 snapshot을 받은 뒤 이동을 해제하고 나비 강공격을 보냈다. 클라이언트 표시 파이터도 받은 자료를 정식 `apply_network_snapshot`으로 반영했다. 두 클라이언트는 전투 틱을 계산하지 않는다. 원격 표시의 초기 프로필 구성은 정식 `configure_profile` API를 썼다.

## 자료와 재실행

```sh
python3 _workspace/motion-naturalness-v1/qa/lan-launch-release-r01/run.py
```

제품 통합 뒤에는 같은 명령을 `LAN_RELEASE_PRESENTATION=res://scripts/local_fighter_presentation.gd` 환경값과 함께 실행한다. 기본값은 고정 r04 clone이다. `client-fixture.gd`는 process-local r09 후보와 launch_release만 넣고 원본 파일을 쓰지 않는다. 후보 loader는 같은 r10의 메모리 안 `fix_alpha_edges` import 보정 helper를 쓴다.

- `*-client.log`, `*-server.log`, `auth.log`, `run.log`, `run-report.json`: 실제 실행 결과.
- `source-hashes-before.json`, `source-hashes-after.json`: 공통 서버/클라이언트 소비 소스·전투 리소스·후보·표시 clone·fixture 155파일. 세 실행 전후 전부 같은 해시였다. 같은 작업 공간 서버와 클라이언트임도 기록했다.
- `receipts.jsonl`: 변경 없는 기존 인증/결과 fixture의 요청 기록. 첫 실패 시도의 방도 들어 있으므로 정확히 세 경기만의 목록으로 읽지 않는다.
