# 숲빛 UI 검토 기록

## 검사 범위

Penpot `Forest_Arena_UI`의 편집 원본 50개(SCR 24, CBT 8, EXT 6, STATE 12)와 20:9 비교 3개를 PNG로 내보냈다. 원본은 1920×1080, 비교는 2400×1080이며 검토 PNG는 0.5배다. `exports/review-*.jpg` 모아보기와 개별 PNG를 사용해 전체 화면을 시각 검토했다. 프레임 개수 검사와 시각 검토를 별도로 수행했다.

## 시각 검토 결과

- VIS-01: 한국어 제목·본문·주요 버튼의 잘림과 겹침을 확인했다. 친구 화면의 긴 필터, 일반 설정 복원 문구, 선택 화면 5개의 목록·미리보기 구성을 수정했다.
- VIS-02: 대화상자를 실제 조합 컴포넌트로 바꾸고 가려진 상태 아이콘을 다시 앞으로 배치했다. 일시정지의 계속하기, 나가기 취소, 복원 취소의 목적지를 정리했다.
- VIS-03: 카운트다운은 시작 전 피해율 0%와 남은 기회 전체 표시, 큰 숫자 3으로 수정했다. 피격·링아웃·복귀·탈락·패배는 별도 상태 화면이다.
- HUD-08-STATIC: Solo 8인과 Team 4대4의 압축 HUD를 확인했다. 참가자 번호, 이름, 피해율, 씨앗 기회 표시와 팀 기호·색상을 함께 사용한다. 최대 줌아웃을 나타내는 정적 배치에서 상단 HUD와 중앙 참가자가 조작 버튼에 가려지지 않는다. 실제 카메라 이동 검증은 포함하지 않는다.
- SAFE-20-STATIC: 로비·선택·전투의 20:9 비교를 확인했다. 중앙 1920 영역과 좌우 여백, 전투 엄지 가림 표시를 구분했다. 카메라 경계의 실제 손가락 가림은 실기기 과제로 남긴다.
- 승인 자현 원화에 포함된 검은 배경은 유지했다. 신규 투명 컷아웃은 제작하지 않았다. 다른 승인 캐릭터와 Splash 무캐릭터, 장신구 무등급 원칙을 유지했다.

## 실제 프로토타입 검사

Penpot 보기 모드에서 화면 맞춤 64.54%로 다음을 직접 클릭하고 화면 이름과 표시 결과를 확인했다.

1. 검토 목록 → Splash → Login → 게스트 → Lobby.
2. 플레이 → Mode → AI → AI 조건 → 캐릭터 → 직업 → 장신구 → 경기장 → Loading → 자동 전투 진입.
3. 전투 메뉴 → 오프라인 일시정지 → 경기 나가기 → 나가기 확인에서 계속하기 → 전투 복귀.
4. 검토용 승리 예시 → 승리 → 결과 요약 → MVP → 다시 플레이 → Mode.

`penpot-final-audit.json`은 실제 저장된 프로토타입 연결 248개를 읽어 목적지 존재를 검사한 기록이다. 잘못된 목적지 0개, 시작 흐름 2개를 확인했다. 자동 전환 3개를 포함한다. 모든 상태를 손으로 각각 클릭한 것은 아니며, 위 실제 클릭 검사와 전체 목적지 구조 검사를 구분한다.

프로토타입은 10_Prototype의 화면 PNG와 실제 클릭 영역으로 구성된다. 한국어 텍스트와 재사용 인스턴스는 각 원본 페이지에서 편집한다. 프로토타입의 검토 목록·승리/패배 예시 버튼은 개발 검토용이며 게임에 포함하지 않는다. 슬라이더 값 변경, 자유로운 캐릭터 선택 데이터, 전투 입력 자체를 실행하는 게임 구현은 아니다.

## 수치·파일 검사

- `geometry-audit.json`: PNG 53개, 기본 및 85%·100%·110% 크기에서 전투 터치 영역 겹침 0, 지정 안전 영역 이탈 0. 방향패드는 왼쪽·아래, 행동은 오른쪽·아래 경계를 고정한다.
- 87 SVG와 87 투명 PNG의 파일·크기·알파·원본 해시를 대조했다.
- 기존 이미지 슬롯 61개는 실제 등록 파일과 대조해 누락 0개다. 확정 전 콘텐츠 원화는 의미 아이콘과 준비 중 표시를 사용한다.
- 신규 Penpot 컴포넌트 93개(벡터 87 + 조합 6), 기존 보관 컴포넌트 22개. 전투 HUD 32, 참가자 슬롯 8, 대화상자 9에 조합 인스턴스를 사용한다.
