# 자현 특수기 피격 표시 — 전투/표현 전달

## 재현과 원인

실제 MatchController의 특수기 입력·hit window·HitResolver를 사용해 서 있는 상대, 걷는 상대, 공격 준비 중인 상대를 자현/나비로 각각 검사했다. 로컬은 원래부터 각 유효 HIT 직후 HITSTUN·hitstun 첫 그림으로 들어가고 실제 경직 안에서 진행했다. 로컬 상태 미진입은 재현되지 않았다. 새 그림이나 전투를 바꿔 이 결과를 덮지 않았다.

LAN에 해당하는 공개 프록시 경로는 20Hz snapshot과 기존 hit_resolved 이벤트로 별도 재현했다. 현재 hitstun TRES는 **24FPS**다. 6tick=0.1초마다 재시작하면 그림0~2까지만 보이고, 큰 반응인4~5에 도달하지 못한다. 초기에 추정한8FPS/F0고정은 잘못된 설명이며 이 관측으로 정정한다. 이전 검사는0.2초를 진행한 뒤 재시작해 실제 특수기의 더짧은 간격을 놓쳤다.

## 수정과 공용 표시 데이터

`local_fighter_presentation.gd`에 선택쌍 `hit_reaction_lead_frame_range:[0,6]`, `hit_reaction_lead_ticks:6`을 읽는 표시 경로를 추가했다. hitstun이며 실제 로컬 경직값이 없는 경우에만 첫6장을6개의표시틱에 보여주고 다음 그림부터 기존 FPS/표시가중치로 잇는다. 최초 draw의 delta를 빼 첫표시는 항상 원래 첫그림이다. 새 HIT는 재시작하고 실제 다음 전투상태는 즉시 우선한다. 서버 경직을 추측하거나 전투상태를 만들지 않는다.

쌍누락/잘못된값은 기존 표시를 유지한다. begin=0, end<=그림수, ticks정수1~12 및 구간그림수이상, bool/NaN/Infinity/소수거절이다. 로컬의 실제 경직 비례 표시와 현재 가중치 경로는 그대로다. `display_layout` 전달필드만 추가했으며 전투·원화·TRES·runtime manifest는 변경하지 않았다. 선택필드의 도구 계약은 별도 계약 담당자가 연결한다.

`hit-reaction-lead-candidates-r01.json`은 자현/나비 hitstun의 기존 그림SHA와 검토용 설정을 담는다. 아직 승인·등록하지 않았다. 현재 코드만으로 기존 배포 자산의 표시가 달라졌다고 기록하면 안 된다. 해당 설정의 실제 재생 독립검토와 수정본 승인 뒤 부모가 후보/등록에 연결한다.

## 검사

- clean red r06: 같은 실제 12경우(대상2×상황3×lead유무)의3876검사에서 옛 공개코드를 작업용 복사본으로 사용했다. 18개 연속타격의 가독자세 검사만 실패(exit1), 시험오류는0이다.
- 최종 r08:3967검사 PASS/exit0/ERROR0. 각 경기10타·6tick간격·총14피해, 110tick 전체snapshot 동일, 로컬 그림순서 동일을 확인했다. 설정의 경계·잘못된값·JSON정수, 느린 첫draw, 반복/과거/방어/무적/armor 이벤트, IDLE/GUARD/DEAD/MATCH_ENDED에서 늦은HIT도 검사했다.
- 기존 피격688검사와 표시연결680검사도 PASS/exit0/ERROR0. 공개 특수기 검사는 기본적으로 user://에 결과를 기록해 작업폴더에 의존하지 않는다.
- r01~r05의 초기실험에서 시험용metadata키슬래시, 만료된 pull정보와 facing의 초기값 차이, 정확한 부동소수경계 기대값 때문에 실패한 기록은 삭제하지 않았다. 이를 제품결함이나 최종통과 근거로 쓰지 않는다. 새 fixture는 초기상태를 명시적으로 같게 만들고 clean red/green을 분리했다.

전체verify·GPU클립·실기기·실제소켓 연결은 이 역할에서 실행하지 않았다. 원본 로그/수치 검사는 원화가 실제로 자연스럽게 보인다는 독립 시각 판정을 대신하지 않는다. `tests/special_hit_presentation.gd`를 전체검사에 연결하는 일과 PR/commit은 부모가 맡는다.


## Android 오프라인 관측 환경 후속 확인

사용자가관측환경을Android오프라인대전이라고명시했다. 기존LAN형초반표시수정은별도부분개선이며이오프라인증상의해결로주장하지않는다. AI가나중노드에서앞노드의Player를때리는실제native120tick/10HIT촬영1회와같은tick의sourceFX숨김9표본을확인했으나상대피격자세는읽혔고문제를재현하지못했다. sourceFX레이어코드는고치지않았다. 자세한한계와0~14.7%의sprite변화비율은 `qa/ai-hit-layer-r01/02_investigation.md`를따른다. Android실제앱의피격미진입은계속미해결로남긴다.
