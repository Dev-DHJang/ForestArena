# 최종 등록 뒤 검사 기준 정리

2026-10-28. 새 점프의 승인본은24장·8 FPS이며, 기존 나비 점프는24장·12 FPS였다. 제작 전달 r01의 “8 FPS를 유지”라는 설명은 기존12 FPS와 비교하면 잘못된 설명이다. 정식 후보 데이터·실제 검토 영상과 사용자 승인 대상은 처음부터8 FPS였다. 이번에는 그 승인본을 그대로 유지한다. 공중 자세가 바뀌는 속도의 설정이며 전투 계산60Hz·실제 점프 물리·착지 연결0.25초를 바꾸지 않는다.

전체 검사에서 기존 `tests/character_motion_contract.gd`의 나비 jump 기대값12 FPS가 승인본과 달라 실패했다. 다른 캐릭터와 모션의 기준을 유지하고 해당 한 항목을 승인본8 FPS로 갱신한다. 그림·TRES·manifest·승인 계획의 바이트는 바꾸지 않는다.

첫 전체 검사는 새 PNG의 Godot 가져오기 전에 Python의 실제 Godot 재생 검사가 먼저 실행돼2개 실패했다. `verify.sh`에서 새 자산 가져오기를 그 검사보다 먼저 실행하도록 순서만 옮긴다. 두 번 가져오거나 검사를 생략하지 않는다. 실패 로그 r03/r04를 보존하고 수정한 검사 절차를 r05에서 다시 실행한다.


r05에서 공격 모션 검사가 두 번째 원화 등록 이력의 마지막 행만 옛 콤보 계약으로 읽어 실패했다. 마지막 행은 이전 승인 원화이고 원래 콤보 설명은 더 앞의 이력에 그대로 보존돼 있었다. `character_attack_motion_contract.gd`는 뒤에서 앞으로 실제 콤보 설명 필드가 있는 행을 찾아 기존 값과 대조하도록 수정했다. 등록1회·2회에서 원래 계약 찾기와 계약 누락 시 실패 유지를 검사한다. 현재 등록 카탈로그·그림·의도 검사는 유지하며 게임 파일은 바꾸지 않았다. 관련 검사 r06은 통과했고 전체 r06을 다시 실행한다.


r06에서공중재점프검사가12 FPS의0.21초후그림번호를모든24장클립에고정해새8 FPS나비에만실패했다. 새승인본의실제그림은F2이며12 FPS클립은F3이다. 이예상번호만정확히분리하고실제공중점프의시작그림재진입·점프횟수차감·전투값불변검사는유지했다. 이미통과한앞검사와AI17경기를불필요하게다시실행하지않고, r07에서실패한이검사부터verify.sh의남은명령을원문그대로실행해전체명령의통과범위를합쳐기록한다.
