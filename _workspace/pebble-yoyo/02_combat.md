# 전투 구현

- `AccessoryAbilityData`와 선택형 `AccessoryData.active_ability`를 추가했다. 장비 원본을 복제해 프로필끼리 공유·변경하지 않는다. 기존 장신구 schema2와 RuntimeCombatProfile schema2를 호환한다.
- `EQUIPMENT` 상태를 enum 뒤에 추가하여 이전 상태 번호를 유지한다. 준비6→발사18→회수18→회복6틱, 시작부터600틱 쿨타임, 사거리180·28×28 본체를 데이터로 처리한다.
- 좌우 이동·새 행동·방향 변경을 잠그고 중력과 지형 이동을 유지한다. 피격·장외·stock 손실·경기 종료는 장비 판정을 지우며, stock·부활은 남은 쿨타임을 보존한다. 경기 초기화만 쿨타임을 지운다.
- 요요 본체의 이전→현재 위치를 확장한 피격 사각형과 선분 교차로 검사한다. 발사만 유효하고 실·귀환은 무판정, 적마다 한 번, 팀원·본인은 제외한다. 일반 공격을 먼저 해소해 같은틱 피격은 장비를 중단하며, 장비끼리는 후보를 먼저 고정해 동시 교환이 가능하다.
- 지형은 사각형 shape cast로 막는다. 모든 지형이 layer1인 기존 StageController를 고려하여 통과형 발판의 실제 one_way_collision 속성을 읽고, 아래/옆 통과는 허용하고 위에서 하강하며 윗면을 지날 때만 막는다.
- 순수 경직은 일반 apply_hit와 분리했다. 정확히30틱, 무게·경직배율·HP·추가 속도·공중 공격/점프 기회에 영향이 없다. 더 긴 기존 경직을 줄이지 않고 가드·무적·기상/다운 보호·해당 면역 규칙을 따른다. 장비 적중으로 기존 피해·게이지 효과를 발생시키지 않는다.
- 입력 우선순위는 아래+점프→일반공격→장비→아래가드→점프다. PRESS만 시작하고 사용/쿨타임 중 입력을 예약하지 않는다.
- snapshot은 계약의 장비8필드(조기 귀환 표현용 equipment_phase_tick 포함)와 accessory_id·equipment_ability_id·equipment_reach를 제공한다. 클라이언트는 받은 단계·시간·위치를 그대로 적용한다. AI는 보이는 snapshot으로 안전한 위치·사거리·높이·대기 상태를 확인한 뒤 같은 use_equipment 명령을 사용한다.
