# 장비 터치·표현 독립 검토 1차

검토자: menu 구현 역할과 분리된 parent 작성 touch/presentation 코드 검토. 실제 화면·모션 재생 검토와 분리한다.

## 발견과 조치 확인

1. `fix`: 최초 장비 버튼 중심 오프셋(294,60)은 크기1.2에서 약 버튼과11.6×5.6만큼 겹쳤고 상태 라벨 하단이 safe area를18px 넘었다. parent가(320,80)으로 수정했다. 수정 뒤 최대 버튼 크기96에서 라벨 하단은 safe area 하단보다2px 안쪽이며, 약/특수/점프 버튼과 사각형이 겹치지 않는 배치를 코드에서 대조했다.
2. `fix`: 전체48틱 기준 모션 샘플링은 벽에 닿아 일찍 회수할 때 팔 동작과 실제 요요가 달라질 수 있었다. equipment_phase_tick을 상태에 추가하고 단계별 프레임 구간 샘플링으로 수정한 코드를 확인했다.
3. `fix`: 준비·마무리 동안 손이 움직여도 요요가 고정 논리 원점에 남을 수 있었다. 해당 두 구간의 그림 위치를 손 앵커에 붙이도록 수정했다. 실제 판정 위치는 변경하지 않는다.

## 코드 검토 범위

- 장비 readiness는 장착·600틱 쿨타임·사용 단계·공중 제한·다운·허용 상태를 읽는다. 사용 중 다른 버튼은 준비 불가가 되며 입력의 최종 허용은 전투 코드가 판단한다.
- UI는 전투 snapshot을 복사해 읽고 피해·경직·궤적을 만들지 않는다. LAN 로컬 참가자 ID로 같은 표시 경로를 사용한다.
- 장비 그림은 ForestArenaResources 논리 ID에서 이미지를 읽으며 본체·실을 표시한다. 실 시작점은 후보 메타데이터의 equipment_hand를 좌우 반전·공통 표시 배율로 변환한다.
- 실제 화면 safe area·멀티터치·중단/복귀 검사와 후보 손 앵커 일치는 parent의 중앙 실행검사 및 다음 모션 검토가 필요하다. 이 기록은 실제 Android 통과나 모션 승인 기록이 아니다.

## 모션 원본 r01

자현·나비 지상 원본을 승인 combat 참조와 직접 비교했다. 준비→팔 전방 투척→당겨 회수→대기가 읽히지만 원본의 정사각 셀·여백·귀/손끝/신발 경계가 부족하다. parent가 이미 같은 원인으로 미채택하고 r02를 제작 중임을 확인했다. r01은 `fix`이며 사용자 승인 요청 대상이 아니다.
