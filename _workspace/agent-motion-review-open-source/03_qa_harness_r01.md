# 역할 체계·모션 검토 도구 독립 QA 1회차

- 검토자: 독립 QA 하위 에이전트 `review_myo`
- 검토일: 2026-10-19
- 대상: `forest-arena-open-source` 스킬, 팀 명세, QA·애니메이션 스킬, 모션 준비·기록 검사 Python, Godot 시간표 수집기, 실제 표현·전투 코드.
- 결과: **fix**. 오픈소스 역할 시나리오는 통과했으나 모션 도구에 검토 누락과 오래된 기록 재사용 위험이 있다. 이 결과는 Android 실제 기기 통과나 새 라이브러리 도입 결과를 뜻하지 않는다.

## 발견사항

### P1 — 실행 중 생성되는 차지 해제 공격이 시간표에서 빠진다

- 근거: `scripts/fighter_controller.gd:466–476`은 AttackData를 복제하고 차지량에 따라 회복 시간을 늘리며, `visual_state_id`를 `attack_heavy_charge`로 바꾼다. 반면 `tools/forest_arena/motion_review_timeline.gd:57–69`는 `base_move_set.attacks()`에 저장된 원본만 열거한다.
- 관찰: 현재 120종 시간표의 모든 모션은 변형이 1개뿐이다. `attack_heavy_charge`는 `attack_id: ""`인 비공격 CHARGE 유지 기록만 있다. 실제 차지 해제의 준비·적중·늘어난 회복 프레임은 검토 자료에 없다.
- 영향: 같은 그림을 힘 모으기와 실제 차지 공격이 공유하는데 기대 행위는 준비 전용으로 적혀 있다. 준비 그림으로만 수정하면 차지 해제 공격의 타격 표현을 망가뜨릴 수 있다. 눈으로 보지 않은 동적 변형까지 확인했다고 기록할 위험도 있다.
- 수정 필요: 전투 코드에서 실제 만들어지는 차지 해제 변형을 최소·최대 유효 차지량과 방향별로 수집한다. 준비 상태와 해제 타격의 표현 의미 충돌은 `redo`로 기록하고 담당 역할이 분리 방법을 정한다. 저장된 기본 공격 목록만으로 전체 실행 변형 확인을 주장하지 않는다.
- 재검사: 차지 준비 기록과 차지 해제의 startup/active/recovery 기록이 각각 존재하고, 최대 차지의 실제 늘어난 회복 길이가 반영되는지 확인한다.

### P2 — 기대 행위 원문 변경 후에도 이전 검토가 유효하다

- 근거: 시간표의 source 목록(`motion_review_timeline.gd:92`)에 `docs/gameplay/combat.md`가 없다. `review_motion_actions.py:232–233`은 action_source가 파일로 존재하는지만 검사한다.
- 재현: 기존 단위 테스트 fixture에서 모든 확인값과 관찰을 넣어 유효한 pass를 만든 뒤 `docs/gameplay/combat.md`의 행위 정의 내용을 전혀 다르게 바꾸었다. `validate()`는 오류 없는 `[]`를 반환했다.
- 영향: 일반 상태·방향 공격의 정의가 바뀌어도 예전 의미 검토를 재사용할 수 있다.
- 수정 필요: 실제 action_source 원문을 모두 고정하고 내용 변경 시 이전 결과를 거부한다. 준비 시 생성한 기대 행위도 현재 기준과 대조한다.

### P2 — 시간표 생성 뒤 SpriteFrames가 바뀌어도 오래된 재생 기록으로 새 검토를 만들 수 있다

- 근거: SpriteFrames 해시는 prepare 시 현재 파일에서 수집하지만 시간표 source에는 해당 `.tres`가 없다. 시간표와 SpriteFrames의 수집 시점이 연결되지 않는다. 실제 표현에서 읽는 `character_display_layout_v01.json`도 source에서 빠져 있다.
- 재현: 기존 fixture의 시간표를 보존한 채 SpriteFrames 내용을 FPS·순서 변경을 뜻하는 다른 내용으로 바꾸고 새 출력 폴더에 prepare를 실행했다. 새 review에 정상 pass 기록을 넣어 검사했을 때 `validate()`가 `[]`를 반환했다. 이는 의미 판단 실험이 아니라 오래된 시간표 수용 여부를 확인한 최소 재현이다.
- 영향: 새 FPS·프레임 순서와 옛 시간표를 함께 검토할 수 있다. 새 review 생성 후 파일 변경은 기존 테스트가 잡지만, 시간표 생성과 prepare 사이 변경은 잡지 못한다.
- 수정 필요: 시간표 수집 때 읽은 SpriteFrames 및 표현 배치 데이터도 고정하고 prepare 단계에서 동일성을 확인한다. 검토 뒤 변경뿐 아니라 수집→자료 생성 사이 변경도 거부한다.

### P2 — 비어 있지 않은 샘플 하나만 있어도 단계·길이 누락을 통과시킨다

- 근거: `review_motion_actions.py:98–105`는 샘플 존재, frame 범위, shown 이름, 양수 duration만 확인한다. exporter가 넣는 `phase_ticks`, 실제 단계 순서·총 tick 수·변형 ID 목록은 검증하지 않는다.
- 재현: fixture의 재생 기록을 frame0·phase=`garbage-phase`·duration=1ms 한 샘플로 줄였지만 `timeline_errors()`가 `[]`를 반환했다. 직접 반환한 시간표가 잘렸거나 잘못 조립돼도 새 prepare는 그대로 받아들일 수 있다.
- 영향: 일부 공격 단계나 변형이 빠진 자료로 전체 재생 확인을 진행할 수 있다. review와 timeline의 단순 동일성만으로 실제 코드의 전체 길이를 증명하지 못한다.
- 수정 필요: 공격 변형은 기대 ID·단계별 tick 수·60Hz 샘플 수와 순서를 검증한다. 상태·점프는 수집 시나리오의 필수 단계와 표본 길이를 검사한다. 동적 차지 변형도 이 기대 목록에 포함한다.

## 실행한 검사와 한계

- `python3 -m unittest discover -s tools/forest_arena -p test_motion_action_review.py -v`: 기존 15개 테스트 모두 통과.
- 별도 임시 폴더의 기존 fixture를 이용해 원문 내용 변경, SpriteFrames 변경 후 오래된 시간표 재사용, 비정상 단계·1ms 표본 축소를 실험했다. 세 경우 모두 검사기가 누락을 거부하지 않는 것을 확인했다. 임시 fixture는 정리했다.
- 원본 PNG 변경, review 이후 SpriteFrames 변경, 중복·누락 행, 자료 해시 변경, 재생 배열만 변경, timeline 파일만 변경, 관찰·필수 checks 누락을 기존 테스트가 검사함을 코드로 대조했다.
- validate의 성공이 기록 형식·동일성 검사라는 문구는 적절하다. 사람이 보지 않은 그림의 의미를 자동 검사로 증명하지 않으며 reviewer 문자열만으로 독립성을 기술적으로 증명하지 않는 한계도 그대로 남는다.
- 비공격 120tick 수집은 상태를 강제로 유지하는 시험이다. 실제 수명이 짧은 hitstun·launch의 마지막 대기 그림만으로 결함을 확정하지 않았다. guard·차지 준비처럼 유지 입력 상태의 끝 자세는 별도 확인 대상이다.
- 파일 수정은 이 독립 QA 보고서만 수행했다. 앞선 묘령 단독 결과의 charge 항목은 새 코드 근거에 따라 `fix`에서 `redo`로 보완했다. 공유 review·구현·런타임 자산은 수정하지 않았다.
