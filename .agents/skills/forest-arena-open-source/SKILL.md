# Forest Arena 오픈소스 활용

## 사용 시점

- 기능 추가·성능 개선·기술 문제에서 기존 구현으로 부족하거나 외부 도구가 도움이 될 때 사용한다.
- 단순 문구·설정 수정마다 조사하지 않는다. 특정 라이브러리 도입 자체를 목표로 삼지 않는다.

## 필수 입력

- 원 요청, 현재 Phase와 관련 결정, 해결할 문제와 확인 가능한 완료 조건.
- 기존 구현·의존성, 적용할 플랫폼과 담당 개발 역할, 비교할 성능·유지 비용.
- 현재 Godot·Android·개발 도구 버전과 도입에 허용된 작업 범위.

## 작업 흐름

1. 기존 코드 재사용·직접 구현과 외부 후보를 비교한다. 실제 필요가 없으면 조사 또는 도입하지 않은 이유를 남긴다.
2. 웹에서 공식 문서·원본 Git 저장소·릴리스·LICENSE를 확인하고 URL과 확인 날짜를 남긴다. 검색 요약·별 수만으로 결정하지 않는다.
3. 필요한 후보의 Godot 4·Android 호환성, 최근 유지보수와 알려진 문제, 이용 조건·표시 의무, 추가 의존성·실행 권한, 파일 크기·성능·교체 비용을 비교한다. 확인하지 못한 내용은 미확인으로 적는다. 이용 조건이 없거나 적용 가능성이 불명확하면 도입하지 않는다.
4. 선택한 버전 또는 commit을 고정하고 격리된 작업 폴더에서 문제를 해결하는 최소 시험을 한다. 실제 코드를 실행하기 전에 설치·빌드 절차와 실행 스크립트를 읽는다. 시험 실패는 실패로 남기고 다음 후보 또는 기존 구현으로 돌아간다.
5. 요청된 개발 범위 안에서 담당 역할과 통합하고 이용 조건·출처 파일, 버전 잠금과 필요한 테스트를 함께 반영한다. 전투·리소스·공용 데이터의 소유권은 기존 담당에게 둔다. 외부 예제의 캐릭터·UI 자산으로 승인 자산을 대체하지 않는다.
6. QA에 원 문제, 비교·시험·적용 결과와 되돌리는 방법을 전달한다. 현재 Phase와 승인 범위를 넓히거나 유료 서비스·계정·비밀정보를 임의로 도입하지 않는다. 적합한 후보가 없으면 무도입 결론도 완료 결과다.

## 산출물과 검증

- `_workspace/<topic>/02_open-source.md`: 문제, 비교한 대안, 원본 URL·확인일·버전/commit·이용 조건, 시험 환경·결과, 반영 파일, 미확인과 되돌리는 방법.
- 조사만 한 경우와 실제 반영한 경우를 구분한다. 미실행 Android 검사를 통과로 기록하지 않는다.
- 성공·호환 실패·이용 조건 미확인·후보 없음의 실제 사례 또는 이름 있는 시나리오로 다음 행동이 분명한지 검토한다.
