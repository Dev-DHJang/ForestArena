# Forest Arena QA

## 사용 시점

- 사용자 경험, 전투, 계약, 데이터, 에셋, 플랫폼 또는 릴리스 변경의 독립 검토에 사용한다.
- 캐릭터 콘셉트는 입력 충족, 독창성·권리, 최대 줌아웃 실루엣과 배경 대비를 forest-arena-character-design과 독립적으로 검토한다.
- 대전 대표 세트는 `docs/content/combat-character-references.md`에 따라 승인 콘셉트와 네 각도의 얼굴·비율·의상·종 특징, 몸 기준 크기, 128px·좌우 반전을 직접 비교한다. 이후 모션은 승인 세트·첨부 이미지 해시와 전체 프레임의 일관성을 확인한다. 구조 검사나 설명만으로 시각 QA를 통과시키지 않는다.
- 캐릭터 모션은 선언된 프레임 수(기존16, 신규16·24·32), 128×128 셀·최대16열 시트, alpha, 프레임 순서·잘림, 기준 방향, FPS·루프, SpriteFrames 참조, manifest 기록과 모션별 명시 승인을 forest-arena-2d-animation과 독립적으로 검토한다.
- 모션의 기대 행위·핵심 자세·방향과 게임 재생 타이밍은 `docs/content/motion-action-review.md`를 읽고 전체 프레임·재생 자료를 직접 확인한다. 파일명·메타데이터 일치만으로 통과시키지 않는다.
- 외부 라이브러리 도입은 원 문제·이용 조건·시험 환경·적용 버전과 실제 사용하는 코드를 함께 검토한다.
- 단순 문구 수정은 오케스트레이터 검토만으로 충분할 수 있다.

## 필수 입력

- 원 요청, 00_request.md, 담당 제품 문서, 계약과 생산자 산출물.
- 소비자 측 파일, 테스트 환경과 수용 기준.

## 작업 흐름

1. 기준마다 필수 또는 사용자 승인 명시적 이연을 표시한다.
2. 생산자와 소비자를 함께 읽어 ID, 타입, 상태, 이벤트와 경계를 비교한다.
3. 정상·경계·실패·회귀를 자동 검사 또는 재현 가능한 절차로 확인한다.
4. 모션은 사용자 승인 요청 전에 독립 검토하고 `motion-review.json`에 기대 행위, 해시, 검토 자료, 관찰과 문제 프레임·시간을 남긴다. 변경된 파일에는 이전 통과를 재사용하지 않는다.
5. 03_qa_rNN.md에 pass, fix, redo 또는 blocked를 기록한다.
6. 수정 뒤 새 회차로 영향 범위 전체를 검증한다.

## 산출물과 검증

- _workspace/<topic>/03_qa_rNN.md와 구체적 증거.
- 필수 blocked, 미실행 기기 검사와 명시적 이연을 pass로 바꾸지 않는다.
